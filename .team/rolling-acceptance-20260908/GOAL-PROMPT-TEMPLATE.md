# 单 Issue 端到端目标模式提示词模板

本文件是模板，base/判据未填写不得派产品执行。

采用目标模式语义：持续推进本 Issue 的可见结果，直到全部冻结完成标准满足，或存在有证据的外部阻塞。不得把提交、编译、workflow 成功、脚本自核或准备完成作为终点；不依赖字面 /goal 命令是否被包装器解析。

- 原始 Issue：<URL、快照路径/hash、需求条目>
- 唯一目标：<用户可观察的行为>
- 当前滚动基线：<Rn、serve/App commits/trees/artifacts>
- 独立 owning PR：<URL、base branch/40位SHA、工作目录>
- 最小写边界与明确不做事项：<路径/功能>
- 前期证据与原因：<已证事实、可证伪假设、未知项、既有失败>
- 架构影响：<实际闭包产物、调用方与回归面；不能用手抄清单替代>
- 冻结完成标准：<每项判据及具体测试入口、通过/失败/不可判条件>
- 累计基线回归：<此前已接受功能的实际测试集合>
- 真实功能验收：<复现步骤、截图/请求响应、精确设备与产物绑定>
- 构建与取件：<远端入口、禁止缓存、确切取件责任、无轮询的有界执行办法>
- 权限与设备：<专用 worktree/AVD/adb/socket、资源闸、禁区、清理>

你是本 PR 唯一端到端 owner：读取已有实现 → 复现并归属原因 → 最小修复 → 有意义红绿与兼容测试 → 推独立分支并更新同一 PR → 取回精确产物 → 真实功能验收 → 完整清理 → 对照全部标准交付。普通可逆实现/量具修正由你在已定范围内处理，不逐步请求 leader 转交。

禁止削弱或扩写判据来凑完成；超出契约才报告一次具体阻塞。每次失败保留原件，以新证据支持修复，不无修改重跑到绿。PR 正文含问题、行为变化、测试及限制；返回精确 commit/PR、每项判据结果、原始证据索引及下一基线候选。你不 merge、不自行宣布基线升级。
