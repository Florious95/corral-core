## 留给用户的缺口（`t.rv.final` 原文，一字未改）

本链自动编排到此为止，下面两件必须人做，机器代不了。

### 1. 用户真机装包实测「秒进秒排好」（092 §11 金标准门）

模拟器基线与切分复测只证明 logcat 里 1→7 / 1→8 没低于地板。金标准是用户手机上打开会话立刻进、排好。

下一步：
1. 用刚装出的暂存 APK（或 land 后的正式包）装到用户真机，配对连自己的 9900 舰队。
2. 从列表和收藏各点开至少一个真实会话（含 alt-screen CLI），目测：秒进、秒排好、不白屏、不闪。
3. 设置页导出诊断日志，确认 PerfTrace 八事件同一 `open_id`、`t=` 单调；`emitted=0` 行不当完成事件。
4. 用户口头或截图确认「秒进秒排好」后，这条才算过。未过则回炉切分/仪表，不许开 18 优化点。

### 2. 远端 PR 推送（一事一 PR 一闭环）

席位被禁 `git push` / 动 `mirror-pr*.sh` / 碰远端仓。本地 seal 不等于远端存在。

下一步（leader）：
1. 按 CLAUDE.md：每格 seal 之后、land 之前，先 `bash tools/mirror-pr.sh <分支>`（app/文档面 = corral-core 远端）和需要时 `bash tools/mirror-pr-serve.sh <分支>`（服务端 = corral-serve）。脚本会 `gh pr create`。
2. land 本地并线后立刻推 main，让该 PR 显示 **merged**，不要 land 后才推导致 closed。
3. `corral-app` 独立仓（https://github.com/Florious95/corral-app）本链只造了 `.team/staging/corral-app/` 本地暂存，**没有**推那个仓。若要把引用式工程落到远端，另开一事一 PR：把暂存工程推上去，并把 `includeBuild` 从「t.core2 快照」改成指向已 land 的 corral-core 核模块。
4. 本仓 `app/app` 壳还在。真要「APP 的全部东西从 corral-core 剥离」，是 land 之后的下一步删除/搬家，不是本链已经做完。

### 其它本链做不了的

- 暂存核是拷贝，不是 git submodule。合入后要用 live 树重指 `includeBuild`，否则再改核不会进暂存 APK。
