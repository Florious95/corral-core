# P0 · 派单信封的硬约束「不跑 git commit」使 PR 链整条断裂

- 日期：2026-08-21
- 报告人：远程Agent安卓 leader
- **投递状态：⛔ 未投递。** 投前按纪律验活，`讨论team-agent` 下 `team` 与 `wiki`
  **两个 team 每一行都是「错误」＝死队**，投过去会返回 `ok: True` 但无人读取。
  待对方起来后再投。

## 1. 现象

**用户视角**：要求「过程当中要提 PR、审 PR、测 PR」。实际跑下来，
**分支上一个 commit 都没有**，没有 PR 可提、没有 diff 可审、也没有东西可以 land。

**机器视角**：评审席自己发现并写进它的过程：

```
关键发现：pr/recon-foreground 是 main 的祖先——分支上没有任何超出 main 的提交。
说明.md 交代了：硬约束不许 commit，改动以未提交状态留在 .worktrees/pr1.recon 工作区。
所以实际要审的是那个 worktree 的工作区 diff。
```

## 2. 日志（原始，带量具身份）

量具：`ledger-run` md5 `8c1c850bec4c86d230480b99fd6cd671`，mtime 2026-08-20 15:06。
`team-agent` runtime `0.5.66`。

派单信封里由**引擎模板**加的那一段（不是账本作者写的，账本 `title` 里没有这几句）：

```
硬约束
- 不跑 git commit / push；不发 team-agent send。
- 改文件只准在上面的工作目录（git worktree）里。禁止在仓根 git checkout -- <目录>。
- 干完调一次 report_result(...)
```

pane 实证（`tmux -S <team 私有 socket> capture-pane`，席位 `pr1-judge-conn`）：
上述「关键发现」两行即出自该 pane。

## 3. 复现

1. 账本给某格声明 `resources.worktree_id`，`--drive` 建 `.worktrees/<id>`。
2. 席位在该 worktree 里改代码，按信封硬约束**不 commit**。
3. `report_result` → 判据全绿 → 格 `succeeded`。
4. `git rev-list --count main..pr/<branch>` ⇒ **0**。

**期望**：一个声明了写范围的格完成后，其改动应当以**可引用的形式**（commit / sha）交付，
否则「已完成」与「已接受」无法分离，也无法回退单个格。
**实际**：改动只以未提交工作区的形式存在于 worktree 里。

## 4. 原因分析及其边界

- 这条硬约束本身有它的道理：防止席位污染共享历史、防止乱推远端。**我不主张删掉它。**
- 但它与 `worktree_id`（每格一棵独立树）**组合之后**产生了未预期的结果：
  树是隔离的，可是**树上的成果没有被固定**。隔离了写，却没有产出可引用的交付物。
- **边界**：我没有读引擎源码，以上是外部观察（盲测）。
  我不知道这条硬约束是否可由账本关闭，也不知道是否有我没找到的「封版」机制。

## 5. 正确行为应该是什么（**给成选项，不替你们定方案**）

1. **账本可声明**「本格完成后由引擎在其 worktree 上 `commit` 到指定分支」，产出 sha 进 `attempts[]`；
2. **或**把硬约束改成「不许 push、不许碰共享分支，但**允许在自己的 worktree 分支上 commit**」；
3. **或**保持现状，但在信封里明说「你的改动不会被固定，交付物是工作区」，
   让账本作者知道要自己补封版步骤——**现在它没说，作者会以为分支上有东西**。

## 6. 我这边的责任，一并说清

我的账本把「提 PR」写进了派单正文，却**没有校验分支上真的有 commit**。
判据只验了单测、archwiki、坏味道、说明.md，**没有一条断言「本格产出了可引用的 commit」**。
⇒ 这是我判据不完备。我的错误只应该导致「PR 没被提出来」，
**不应该导致「格判绿、而交付物根本不存在于任何可引用的位置」**。

## 7. 我方绕法及其代价

**绕法**：commit 与开 PR 都由 leader 做（land 本来就是 leader 的活）。
新增 `tools/gate/seal-pr.sh`，作为每个实现格的一条机械判据 `A-<格>-seal`：
在该格 worktree 上 `git add -A && git commit` 到 `pr/<id>` 分支，
并**断言 `git rev-list --count main..HEAD >= 1`**（封版且非空）。

**代价**：
- 判据里做了有副作用的事（提交），这不是纯判据，属于妥协；
- 封版发生在**席位报完之后**，所以「席位自认为交付的那一份」与「被封的那一份」
  中间若有他人改动就会漂——本工程每格独占 worktree，暂时不会，但这不是结构性保证；
- 对方修好后应拆掉此绕法。
