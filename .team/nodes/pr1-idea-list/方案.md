## 2. E8 · 侧滑关列表而不是关会话

### 改什么

`SessionSwitchSheet.kt`：当 `visible==true` 时挂 `BackHandler { onDismiss() }`。Compose 的 BackHandler 栈是后进先出，sheet 内层会先于 `AgentMirrorApp` 根处理器收到系统返回 / 预测性返回 / 侧滑。

`SessionScreen.kt`：不要再给根导航清 `activeSession` 的机会——sheet 自己吃掉。

不要改 `MainNavState.onSystemBack` 的优先级表（那是「不在 sheet 时」的栈）。

### 外骨骼

`SessionSwitchSheet` 补：

```
@contract
@pre visible=true 时本组件已组合
@post 一次系统返回只调用 onDismiss，不修改导航栈
@err none
@inv visible=false 时 BackHandler.enabled=false，返回事件落到根处理器
```

### 判据（A-088-back）

- 新测：`app/app/src/test/kotlin/dev/agentmirror/app/session/OverlayBackClosesSheetNotSessionTest.kt`
- 先验红：`overlayOpen=true` 时 `onBackPressedDispatcher.onBackPressed()` → 现行为 `activeSession==null`（会话被弹出）且 `overlayOpen` 可能仍 true。断言失败条件：会话仍在栈顶且 sheet 关。
- 验绿：同步骤后 `overlayOpen==false` 且测试夹具里的「会话仍在」标志为真（不要 finish Activity）。
- UI 测：`compose.onNodeWithTag("session-overlay").assertExists()` 在返回后 `assertDoesNotExist()`；`session-list` 或会话壳 `assertExists()`。
- ⛔ 不要只断言 BackHandler 注册了。

## 5. E12 · 关闭是原子动作 + 二次确认

### 5.1 二次确认（不可逆）

`AlertDialog`：标题「关闭会话」；正文必须出现「不可恢复」和会话 `displayName`；按钮「取消」/「关闭」。testTag `close-confirm` / `close-confirm-ok` / `close-confirm-cancel`。

未确认不得发帧。

### 5.2 协议（增量，不 bump v）

`docs/protocol.md` §4.1 表追加（人读规范为准，Go 跟着改）：

| type | 方向 | 必填 |
|---|---|---|
| `close_session` | C→S | `req_id`≥1, `ref` |
| `close_session_ack` | S→C | `req_id`, `ok`；`ok=false` 时 `reason` |

`reason` 闭集（写入 §7，仿 `input_ack`）：`session_not_found` / `close_failed` / `internal`。

幂等：pane 已不在 → `ok=true`（客户端才能收尾取消收藏）。不是错误。

Go：

- `protocol/frametype.go` 加 `TypeCloseSession` / `TypeCloseSessionAck`
- `protocol/frames.go` 加 struct + `Validate`
- `protocol/json.go` `decodePayload` 加两支
- 夹具 `protocol/testdata/` + `golden_test.go`
- App：`conn/Frame.kt` 常量、`Frames.kt` 载荷、`FramePayload.decode` when 分支
- Web：`web/js/protocol.js` + `web/test/protocol.test.js`（未知 type 会让旧客户端报错；Web 必须认得 ack，即使 UI 本轮不做关闭）

### 5.3 服务端（不要改 bridge.Pane 的「只镜像」不变量）

**新文件** `server/internal/api/lifecycle.go`，由 `ws_conn.go` switch 增加 `case protocol.CloseSession`。

算法（必须记判据操作数，见工程诊断纪律）：

1. `catalog.entry(ref)`；没有 → ack `ok=true`（幂等）并 return。
2. socket = `entry.pane.Socket`。**空 socket 直接 `close_failed`，禁止回退默认 tmux socket。**
3. `tmux -S <socket> display-message -p -t <paneID> '#{pane_pid}'` 记下 `pane_pid`。
4. `tmux -S <socket> kill-pane -t <paneID>`。
5. 轮询（≤2s）：`list-panes` 不再含该 paneID **且** `pane_pid` 对 `signal.Kill(pid, 0)` 失败（进程不在）。
6. 若 pane 没了但 pid 还在：对 **进程组** `Kill(-pgid, SIGTERM)`，200ms 后再 SIGKILL。pgid 用 `syscall.Getpgid(pid)`。**只读 `/proc/<pid>/comm`（或 macOS `ps -o comm=`）核对，⛔ 禁止读 argv。**
7. 两边都成立才 `ok=true`。超时 → `ok=false` reason=`close_failed`，日志：`pane_gone=<bool> pid_alive=<bool> pane_pid=<n> socket=<path> pane_id=<id>`。
8. 成功后现有 listing 扫描会推出 `removed_refs`；本帧不替代 listing。

测试用隔离 socket（`e2e/layer2.sh` 那种：短路径 `/tmp/e2e-…`，**先 mkdir**，`unset TMUX`，`tmux -S sock list-sessions` 自检）。⛔ 碰用户默认 socket。

### 5.4 客户端原子收尾

收藏在手机本地（`FavoriteBook`），服务端不知道。客户端事务：

```
二次确认
→ 发 close_session
→ 等 close_session_ack
→ ok 才：若已收藏则 FavoriteBook.toggle 去掉；若当前会话就是它则 onSystemBack 一级
→ toggle 失败（几乎不会）重试一次；仍失败则 DiagLog + 不关对话框
```

失败可见：ack.ok=false 或超时 → 对话框留着，文案带 `reason`。半截 = 红。

当前若在看被关会话：先 ack 成功，再退会话页（不要先退再关——关失败用户已不在会话里）。

### 判据（A-088-close）

隔离 tmux 里起一个 **假 CLI**（脚本 `exec -a grok sleep 3600` 或仓库已有 fake，comm 必须是白名单之一否则 listing 滤掉），收藏它，发 close：

1. `kill(pid,0)` 失败（进程不在）
2. `tmux -S sock list-panes` 无该 pane
3. App `FavoriteBook.isFavorited(ref)==false`

任一假即红。⛔ 只断言 UI 行消失。先验红：现协议解码 `close_session` → `ErrUnknownType` / App `UNSUPPORTED_TYPE`。

## 7. E13 · 工作区页右上角「+」

088 原文「工作区页」= `WorkspaceListScreen`（标题「工作区」），不是二级会话列表。

新建必须有 cwd。一级页本身不带单个 cwd → 点「+」弹层：

1. 选工作区（当前 listing 的 cwd 列表；仅一个则预选）
2. 选 Provider（六个）
3. 勾选 Bypass（Pi 勾了也无旗，UI 可禁用该勾）
4. 确认 → 组装 argv（§6）→ `create_session`

`ScreenHeader.trailing`：`Row { PlusButton; 现有 LanPill }`。`testTag="workspace-new-agent"`。

### 协议

| type | 方向 | 必填 |
|---|---|---|
| `create_session` | C→S | `req_id`≥1, `cwd`, `argv`（`[]string`，≥1） |
| `create_session_ack` | S→C | `req_id`, `ok`；成功带 `ref`；失败带 `reason` |

`reason`：`cwd_not_found` / `no_tmux_anchor` / `create_failed` / `internal`。

`provider` 字段可选（S 只执行 argv，不按 provider 查表）。客户端仍应传，便于日志。

S 行为：

1. `cwd` 必须是主机上存在的目录（`os.Stat`）。
2. 在当前 catalog 里找 **cwd 相同** 的一条 pane，取其 `Socket` + `Session`（tmux session 名）。找不到 → `no_tmux_anchor`（空工作区无法挂 pane；不发明默认 socket）。
3. `tmux -S <socket> new-window -t <session> -c <cwd> -- <argv...>`。
4. 立刻 scan，找到新 pane（pid/argv 对不上就按新 window 的 pane id），ack 其 ref。
5. 之后 listing/level2 照常推送。

同样：空 socket 失败，不回退默认 socket。

App：ack.ok 后 `enterLevel2(cwd)` 或直接 `openSession(ref)`——建议 **打开新会话**（用户刚点了创建）。失败可见。

### 判据（A-088-new）

纯函数 `buildArgv(launch, bypass: Boolean)` 对六个 Provider：

- bypass=true：argv == command 分词 + 表中 bypass 旗（Pi 无旗；Grok 含 `--always-approve`）
- bypass=false：argv == command 分词，**不含**该旗

服务端：隔离 tmux 已有该 cwd 的锚点 pane，发 `create_session` argv=`["sleep","30"]`（或假 CLI 白名单 comm），ack.ok 且 `tmux list-panes` 多一条。先验红：解码 `create_session` → unknown type。
