# 现场基 · study-web-terminal-model

## 由来：用户的判断

> 「我还是认为这个东西应该有开源的办法。就比如说 herdr 它本来是一个 CLI，
>  然后它可以在 SSH 的客户端里面被使用，那也意味着它对移动窗口做了优化，
>  这些问题都应该能找到解决办法。」

判断成立，而且**对照实现就在本仓库里，一直没用**：

| | 终端实现 | 用户报告的四条缺陷 |
|---|---|---|
| `web/` | **xterm.js（MIT）** 成熟库 | 未知（待你验证） |
| `app/` | 自研内核（当初为避 GPL；Termux 那套是 GPLv3 不可用） | **四条全在这里** |

同协议、同 daemon、两个客户端。工程约定第一条测试流水线本就写着
「Web 端 + Chrome DevTool MCP → 拦 80% 问题」，**这四条从未走过那道关**。

## 用户报告的四条（真机，反复出现，历史上从未真正解决）

1. **右侧文字被截断**：最右侧的字跑到屏幕外，只能看到一半（第 4 次报告）
2. **发消息从上往下刷新**：有概率整屏自上而下重刷，导致底部最新消息看不到（第 4 次报告）
3. **向上滑完全失效**：只加载了一屏；捏小字体完全滑不动，捏大字体才「像能滑」，
   但滑的仍是同一屏，不是历史
4. **捏合后整体重绘闪烁一段时间才好**，且字号不持久化

## 四个必须逐条对照的模型点

| 模型点 | 成熟终端库的通行做法 | 对应用户现象 |
|---|---|---|
| **buffer 与 viewport 分离** | 终端维护完整 scrollback buffer；viewport 只是带偏移的窗口，滚动只移偏移、零网络 | 现象 3 |
| **reflow 锚定** | cols 变化时重排 buffer，**保持锚点行位置不变**，而不是整屏重画 | 现象 2、4 |
| **cell 宽度求法** | cols 由实测字形推进宽度 **floor()** 得出，宁可少一列不可多一列 | 现象 1 |
| **scrollback 分页拉取** | 滚到缓冲顶部时按页向后端要更多历史，并入 buffer 后可继续滚 | 现象 3 |

## 边界

- **本任务不改产品代码**，只产出 `docs/` 下的对照文档
- 不需要跑浏览器、不需要模拟器；这是**读码对照**任务
- 若发现 Web 端某条也有问题，如实写——那说明问题在协议或服务端，不在安卓渲染，
  同样是重要结论
- 许可证约束：终端内核须 Apache-2.0 兼容（GPL 隔离红线）。
  **可以借鉴模型与算法，不得复制 GPL 代码**。xterm.js 是 MIT，可参考亦可引用其做法。
