**根因（leader 已定位，⛔ 不必重新调查，但你要自己核一遍）**：

`SessionViewModel` 里挂钩的条件只有一个总开关：

```kotlin
if (PerfTrace.isEnabled()) {
    emulator.onAsciiPrint = { ch -> PerfTrace.notePrintableEcho(ch) }
}
```

而 `TerminalEmulator.print` 里：

```kotlin
val hook = onAsciiPrint
if (hook != null && codePoint in 97..122) hook(codePoint.toChar())
```

⇒ **只要 PerfTrace 开着，每写一个小写字母就回调一次**。
而 `tools/perfbase/coldopen.sh` 正是从 `adb logcat -s PerfTrace` 取数 ⇒
**每一次开会话性能测量，PerfTrace 必然是开的** ⇒ 重放一屏 scrollback 时这个回调被打成千上万次，
**而那一轮根本没有人在打字**。

**为什么这条比「慢了 15%」更严重**：它会让**此后每一次**用带打点的包做的开会话测量
都比 20260822 基线悲观约 15%，**把基线的可比性污染掉**。
