## ⑤ 顺带：我方一个已坐实的缺陷（Q5，与你们的错乱**无关**，但会咬你们）

**这条是我方缺陷，`源码确定`，我方已立格在修（`ledger.fanout.v1`）。**

- **一个 pane 只有一条 pipe，新订阅者顶掉旧的**：
  `server/internal/bridge/stream.go:14-16`
  ```
  // One active pipe per pane (tmux's own limit): a new Subscribe replaces any
  // previous pipe, whose relay then sees EOF and closes its channel. The API
  // layer is expected to hold one subscription per pane at a time.
  ```
- **新订阅者进来先无参 `pipe-pane` 把别人的拆掉，再挂自己的**：
  `server/internal/bridge/stream.go:132-141`
  ```go
  _, _ = runTmux(context.Background(), socket, timeout, "pipe-pane", "-t", target)
  ```
- **被顶掉的那个零通知**：`server/internal/api/ws_conn.go:539-547`，relay 的 defer 里只
  `teardownSubscription(sub)`，**不发 error 帧**。客户端看到的就是「流突然不动了」。
- 且**第一个 relay 退出时对整个 pane 再拆一次**（同上 defer），**可能误伤刚接上的第二个订阅者**。

**这条能解释什么**：「某一端画面停住 / 打开后不再更新 / 白屏」——
**尤其是你们多列分屏、或手机端和桌面端同时看同一个 pane 的时候。**
