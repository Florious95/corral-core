# 069 App 端：进菜单即时刷新

- 契约：`requirement-base/entries/069-进菜单必触发一次即时刷新.md`
- 服务端约定（`.team/nodes/rf-srv/说明.md`）：一级每次 `list` 真实重扫；二级每次 `level2_subscribe`（含同一连接再订）`wakeLevel2` + 同步 `publishLevel2`。
- 施工目录：**仓根 `app/`**（ledger.refresh.v1 r11）。派单顶部已明示：下方「必须在 `.worktrees/wt8.app` 干活」是框架自动生成、本工程不适用；判据 `cwd` 是仓根，改 worktree 会全红。未 `git worktree add`，未 `git checkout`/`git restore` 仓根。

## 改了什么

- `WorkspaceViewModel.enterLevel1()`：保留已画列表，发一次 `list`。
- `enterLevel2`：先画该 cwd 缓存（062），**每次进入都发 `level2_subscribe`**（含未退订再进）。不再对同 cwd 早退。
- `suppressNextEnterRefresh` + `MainActivity` 在 `savedInstanceState != null` 时置位：旋转重建不发 list / 不重订。
- `WorkspaceScreen`：旋转 `isChangingConfigurations` 时 `DisposableEffect` 不 `leaveLevel2`（避免「假离开 → 再订」）。
- `onConfigurationChange` / `onListScroll`：空操作，单测锁死「滚动/旋转不是进入」。
- 下拉仍走 `refresh()`。失败时本层不写空表；新 listing / level2 到了才原地替换。

## 单测 `TestRefreshOnOpen`

- 进一级：1 次 list，列表不被清空；新 listing 到了才换内容。
- 进二级：先缓存后订；离开再进再订；未退订再进也再订。
- 滚动 / 旋转 / suppress 后再 enter：list 与订阅计数不变，画面仍是缓存。
- `ConnectionManager.subscribeLevel2` 连发两次 = 两帧 `level2_subscribe`。

`L2PushOnlyNoPollTest` 同步：同 cwd 再进订阅 1→2（事件驱动再订，不是轮询）；仍 0 list。
