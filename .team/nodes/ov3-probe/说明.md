## 实测红证据（exit 1）

### sessionSocketFromRef 操作数

```
listing_ref="s1"
listing_sep=-1
listing_extracted="s1"
structural_ref="/tmp/tmux-1000/default\u001f%3"
structural_sep=-1
structural_extracted="/tmp/tmux-1000/default\u001f%3"
structural_ref_codepoints=47,116,109,112,47,116,109,117,120,45,49,48,48,48,47,100,101,102,97,117,108,116,92,117,48,48,49,102,37,51
```

`s1` 是契约 listing 金样 / 现有悬浮窗单测用的 ref（`OverlayOpensFromSessionTopRightTest`）。**没有 U+001F**，`sessionSocketFromRef` 回落整段。

结构 ref：服务端 `sessionRef = socket + U+001F + pane_id` 写成 listing JSON（`\u001f` 转义）再经 App `FrameCodec` 解出。解完后码点 `92,117,48,48,49,102` = 字面 `\` `u` `0` `0` `1` `f`，**不是 U+001F(31)**。分隔符没进 App 字符串，`sep=-1`，整段回落。

## 红的那条指出什么

**不是「socket 字段缺省 / JSON 里为空」**——两条线上帧都带了 `"socket"`，Go `Validate` 的 `TrimSpace==""` **没有命中**（所以 `ErrInvalidField → bad_frame` 这条在「空字符串」上此时打不红）。

红在「别的」，而且是同语言闭环永远绿的那种：

| 路径 | 线上 socket 原值 | Go Validate | 探针 |
|---|---|---|---|
| listing 金样 `ref=s1`（现有 App 单测） | `"s1"` | 非空 ⇒ 过 | 红：不是 tmux socket 路径 |
| 服务端结构 ref 经 App 解码 | `"/tmp/tmux-1000/default\u001f%3"`（字面六字符） | 非空 ⇒ 过 | 红：U+001F 没解开，没切开 |

App 侧 `OverlaySubscribeCarriesCurrentSocketTest` 用 App 解码自己发出的帧，看到的是 Kotlin 对象上的 `socket="s1"`，断言非空就绿。服务端自己构造 `OverlaySubscribe{Socket: "/tmp/ov-a/sock"}` 也绿。**跨过语言接缝才看见：发出去的字节要么是 listing 整段回落，要么是没解开的 `\u001f`。**

070 §2「空 ⇒ bad_frame」在「空字符串」上未复现；坐实的是 **socket 有值但不是可订阅的 tmux socket**，Validate 拦不住。真机 `bad_frame` 仍可能来自其它空字段路径，但这一格能指出的红因是上面两行原值。
