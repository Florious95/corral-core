## 试了什么（客户端闭包）

- `SessionViewModel.onBinary(SNAPSHOT)` → `emulator.replaySnapshot`；`DELTA` → `feed`。`replaySnapshot` 会 `flushDamage`，presenter `markScreenRowsDirty` 必 `onFrameRequested`。`TermViewFrameWakeTest` 只锁了 **feed/delta** 唤醒，snapshot 同链路。
- `SessionViewModelTest.snapshotReplaysGridNotAppends`：给非空 snapshot，内核有字。这条在当前码上是绿——**客户端「收到 snapshot 就会重建格子」这条不红**。
- `handleSubscribe`（只读 server）：**先 `Resize(cols,rows)` 再 `capture-pane -e -p` 做 snapshot**，再 pipe-pane 转 delta。静态 alt-screen 不响应 SIGWINCH 时，快照窗口容易空；之后又没有 delta，画布一直空。持续重绘 TUI 靠后续 delta 救回来。与复现矩阵同构。
- 092 §5：用户定性「较长时间白屏 / 疑服务端回退」，与 e12-close / e13-new-pane / gofix-scrubbedenv 换装同一条线。本席 write_paths 只有 `app/app/src/test/`，**不能把 Go 首帧探针合法落盘**。

## 为何不落探针文件

1. 断言「根因不存在」且 **main 必须红**：客户端「非空 snapshot → 格子有字」在 main 上已经绿（现有单测）。再写一条同构探针会绿，违反先验红，属于改判据让它变绿。
2. 若改写成「第二帧空 snapshot 不得把第一帧有字的屏清掉」：`replaySnapshot` 清屏重建是契约（004/协议 §6.2），这条在引入区间之前也红，**父 commit 不会绿**，钉不住「这次 land 引入的东西」。
3. 若写成 A/B（组合了 / 尺寸非 0）：main 绿，且钉错世界。
4. 引入 commit 仍未钉死：第 3 条回退验证无法做。猜 14 条里的某一个 = 造假。

缺：能让「当前 main 红、引入父 commit 绿」的**那条根因**的代码落点（更像 server subscribe 首帧，不在本格 write_paths）。
