# t.paired · 配对统计重算（不重测）

席位：`in-dev2`。worktree：`.worktrees/wt-paired`。本格**只重算、不重测、不改产品码**。

脚本：`tools/perfbase/paired.py`（`--a/--b/--out`，`--boot 5000` `seed=20260823`）。
产物：`.team/perf/paired-r2.json`、`.team/perf/paired-r3.json`。
解析口径与 `ca-emu/tmp/mkbaseline.py` 相同：`adb logcat -s PerfTrace`，跳过 `emitted=0`，相对该次 `ev=tap`。⛔ 没另立解析。⛔ 没往 `instr-ab2-raw/` / `instr-ab3-raw/` 里写。

6 段 × 2 轮全部配满。json 里 `dropped=0`，`dropped_reasons=[]`（没有静默丢）。不是 `blocked_pairing`。

## 两种口径对照（相对差，单位：百分点）

**旧** = `(p50_B − p50_A) / p50_A`（组中位数，交替信息丢掉）。
**新** = `median(d_i)`，`d_i = (B_i − A_i) / A_i`，外加对 `d_i` 有放回 bootstrap 5000 次的 95% 百分位 CI。

没有「配对 p95」——旧口径 12 个门里有一半是 p95，配对只重算 **first_draw / layout_settled 的样本相对差中位数**。旧 p95 红（尤其 R3 `redraw_tui` first_draw p95 +162%）**这一格重算不了**，照实算判不出。

## 回炉修复到底有没有效

**判不出「有效」或「无效」。** 理由：

1. 配对口径下 R2、R3 **都无法在 95% 下主张 B 变慢**（CI 都盖住 0）。旧口径那两轮 FAIL 不能当证据。
2. R2 与 R3 是两段不同时间、不同 B 包的实验，不是同一批里「修前/修后」成对；不能拿 R3 中位减 R2 中位当修复效应。
3. R3 `real_claude_idle first_draw` 配对中位从 R2 的 +9.5% 掉到 ~0，看起来像修好了，但 R2 那段 CI 已经是 [−17, +52]，掉到 0 完全可以是噪声。
4. 旧 p95 红（R3 两个 2475ms / 6648ms 极端值）配对层没有对应统计量。

能写的只有：在 n_pairs=20 的配对口径下，**看不出回炉前后有一个稳定的、能过 95% 的 10% 量级效应**。

## 这台量具能分辨多大效应

定义（写进 json `min_detectable_effect_definition`）：每个（夹具×段）的 bootstrap 95% CI **半宽** `(high−low)/2`，再取 **最大值**。比这个更小的效应，CI 往往会盖住 0。

| 轮 | Y = max CI 半宽 | 最吵的段 | n_pairs | 要把 Y 压到 10% 需 n_pairs（∝ (Y/10)²） |
|---|---|---|---|---|
| R2 | **34.3%** | real_claude_idle first_draw | 20 | **236** |
| R3 | **26.7%** | redraw_tui first_draw | 20 | **142** |

两轮 Y 都 **> 10%**。按 1/√n 估：n=20 只能分辨大约 27–34% 的相对差；要在最吵的那段上也把分辨率收到 10%，大约需要 **140–240 对**（R3 用 142，R2 用 236；取保守值 ≈ 240）。这是外推，不是再测出来的。

R3 最安静的段半宽已经 ~11%（`real_claude_idle layout_settled`），靠近 10%，但量具是按**最吵段**说话的——`redraw_tui first_draw` 有极端值，半宽 26.7%，把整台量具拖住。极端值未剔除（与前两轮同一铁律）。

## 判不出的部分

- 配对重算**不能**替旧口径的 p95 门做判决。
- **不能**回答回炉是否把真实 10% 效应抹掉（量具 Y > 10%）。
- **不能**把「CI 盖住 0」写成「B 与 A 一样快」——只是分不出。
- n_needed 是 CI 宽 ∝ 1/√n 的估算，若极端值主导，加样本不一定按这个比例变窄。

`sh tools/perfbase/judge-paired.sh` 核的是方法学产物齐不齐，⛔ 不核中位正负。
