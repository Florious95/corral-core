## 逐条（rework）

### 1. 守卫没走进去时 PerfTrace 沉默，分不出「该做而没做」与「做了但被吞」

问题：`subscribe` 未就绪只记簿、`send` 失败、`idFor==null`、`takeSubscribeSent` 已占用，全部不打点。断线重连后会话仍打开时，`replaySubscriptions` 会真的再发 SubscribeFrame，但 `takeSubscribeSent` 已是 true，日志里看不到这次 subscribe。光看 PerfTrace：缺 `subscribe_sent` 既可能是没接线，也可能是未就绪，也可能是 send 失败，也可能是 take* 吞了重放。

证据：`ConnectionManager.kt:341-348`

```
fun subscribe(ref: String, rows: Int, cols: Int): Boolean {
    if (state == ConnectionState.STOPPED) return false
    activeSubscriptions[ref] = rows to cols
    val conn = connection ?: return true // 已记簿，重连后重放
    if (!conn.isReady) return true
    val ok = conn.send(SubscribeFrame(ref = ref, rows = rows, cols = cols))
    if (ok) emitSubscribeSentAndGeom(ref, rows, cols)
    return ok
```

`ConnectionManager.kt:532-541`（`idFor` 空则 return；take 已占用则不 emit）：

```

```

同形：`TermSurfaceView.kt:438-446` 在 `cellsNonBlank > 0` 为假时不发 `first_draw`、也不留 glyphs=0 行；空屏会话会整段缺 7，无法判断是没画还是没字。

期望：每个守卫打一行带操作数（至少 `ready=` `conn=` `ok=` `take=` `glyphs=` 里参与比较的两边），或同一 `ev=` 带 `emitted=0 reason=`。重连重放必须能用日志看出「这次发出了」，不能被第一次打开的 take* 吃掉。

### 2. `layout_settled` 不触发/被取消时零行；触发时没有最终行列

问题：`noteReflow` 在 `opens[ref]==null` / 已 settled / `settleHandler==null` 时直接 return，不打点。`unbind` 只 `removeCallbacks`，不留「取消了、因为离开会话」。打开后立刻打字：delta 路径不 `noteReflow`（`SessionViewModel.kt:297` `DELTA -> emulator.feed`），500ms 窗口仍会到——这条本身符合「无 resize/reflow/全量重绘」的定义，不是本条理由。本条理由是：永远等不到第 8 行时，无法区分「还在等 / 被 unbind 取消 / 从未 noteReflow / 无 main looper」。另外 `layout_settled` 契约操作数只有 `quiet_ms=` `last_reflow_src=`，没有最终 `rows=` `cols=`；任务二只抓 `adb logcat -s PerfTrace`，geom_seed 之后的 resize 在 PerfTrace 里看不见对错。
