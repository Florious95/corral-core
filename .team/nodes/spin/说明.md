# t.spin · 一级菜单转圈不回弹

## 路径裁定

信封 / BASE / 验收命令 cwd 都是仓根。包装器写「只准写 wt16.spin」；最高优先级写忽略那段、一律仓根。代码与本文件落仓根 `app/`、`.team/nodes/spin/`。没有 `git checkout` / `git restore` / `git worktree add`。

## 先验红（改之前量的，两个数都有）

探测：一级已有 listing（5 个工作区）后再组合 `WorkspaceScreen` / 调 `enterLevel1`（同构 ServiceWire `lastListing` 补播后再进菜单）。静置路径用 `list_delta` 推 10s。

| 操作数 | 改前 |
|---|---|
| `list` 请求数（进入后） | **1**（不再涨） |
| `refreshing` 翻转序列 | **`[false, true]`**，末值 **true** |
| 树上不确定进度指示器 | 随 `isRefreshing=true` 挂着 |

失败原文（`./gradlew :app:testDebugUnitTest --tests '*SpinnerIdle*'` 改前 4 测 3 红）：

```
A-sp-idle：首帧已到后 refreshing 必须 false
W2 请求早停了但状态没回写 lists=1 refreshing=true flips=[false, true]

首帧已到：enterLevel1 不得把 refreshing 留在 true lists=1 last=true flips=[false, true]
```

三种世界（用操作数判，不是「转圈还在」）：

- **W1 请求一直在飞**：`lists_now > lists_enter`（本条未命中：list=1 停住）
- **W2 请求早停了但状态没回写**：`lists=1` 且 `refreshing=true` ← **本条红**
- **W3 状态回写了但 UI 没重组**：`refreshing=false` 但树上仍有不确定进度指示器（本条未到这一步）

不是 074 的 `list → 推送 → list` 自激环。一级列表内容已经对（补播/缓存），坏的是 `enterLevel1 → refresh()` 在首帧之后又把 `_refreshing` 置 true，然后只等下一次 `ListingFrame`。`handleList` 要先重扫再回 listing；重扫一慢/卡住，PullToRefresh 圆形指示器就悬在第 1、2 行之间不回弹。

## 修法（069 / 下拉都保留）

- `enterLevel1`：`cached > 0`（首帧已在）→ 仍 `requestList()`（069），**不**置 `refreshing=true`。
- `cached == 0`：仍走 `refresh()` 置转圈，等 `applyListing` 复位。
- `refresh()`（下拉）行为不变：置 true，listing 到达复位。
- 列表不写空（062）。
- 诊断日志把 `refreshing_prev` / `refreshing_next` / `cached` / `seq` 两边都记下。

## 修后

同一探测：`list=1`，`flips` 末值 `false`，树上指示器 0。下拉仍置 `refreshing`、listing 后复位。

`./gradlew :app:testDebugUnitTest --tests '*SpinnerIdle*'` 绿。
`./gradlew :app:testDebugUnitTest` 绿。
