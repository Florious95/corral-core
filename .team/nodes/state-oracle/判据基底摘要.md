# 判据基底摘要：Agent 工作状态（working / idle）检测判据

> 本文档是**零知识对照席（r.control）唯一允许阅读的判据文档**。
> 你什么都不带地来，你读它，然后做定点变异，验判据会不会真的红。
> 本文档自洽、自足、无内部引用——所有判据都是可重跑命令 + 期望退出码，不靠任何外部文档。
> 起草：r.advisor（t.oracle，2026-08-15）。

## 0. 你要验收的东西（一句话）

判据 = **一条命令**：`bash .team/nodes/state-oracle/run-probe.sh`。

- 被测对象（live 状态检测代码）**对** → 命令退出码 **0**。
- 被测对象**坏** → 命令退出码 **非 0**。
- 你能用「定点变异」验证它：把代码改坏一处，命令必须从 0 转非 0。转不动，判据无效。

## 1. 被测对象在哪个文件，判据怎么知道它「对」还是「坏」

被测对象 = 重建后的状态检测决策源码，落在 `server/internal/agentstate/`
（它读两个采集输入：屏幕尾部文本 `RecentOutput`、窗格标题 `PaneTitle`——取数链路保留，
不在本次验收范围）。

判据命令 `run-probe.sh` 做四件事：
1. 把 `server/internal/agentstate/` 的源码原样装进判据模块（`.team/nodes/state-oracle/scratch/`），
   只改一行 import 路径（指向判据模块内的协议副本），决策逻辑零改动。
2. 同步被测的 `server/internal/protocol/state.go`（协议层，判据模块有自己的副本）。
3. 跑探针测试 `go test ./probe/ -count=1`（`-count=1` 防 Go 缓存绿）。
4. 还原判据模块（判据模块默认载的是**归档的旧实现化石**，保证红测载体不被动坏）。
   退出码 = `go test` 的退出码，权威。

## 2. 判据的哲学：信息在「导数」里，不在字形里

过去三次修复（全部失败）都往**字形白名单**里加减字符（`⠋⠙…` braille、`✳`、`◐`），
像在调一张不含答案的表。两条实证：

1. **字形会改版**：白名单记的是 braille `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏`，而用户 2026-08-15 截图显示
   Claude Code 当前工作中吐 `◐`（半圆）、空闲吐 `✳`——字形一改，白名单**静默失明**。
2. **同一字形无法分辨两个状态**：真实屏面里完成态 `✻ Brewed for 6s` 与工作中 `✻ Galloping…`
   **共用同一个 `✻` 前缀**——任何「里面有没有某个字形」的判据，从根上分不出完成与工作。

所以判据**禁止用任何字形白名单**。判据只看两件事：
- **有没有**：有没有一个**结构性工作信号**（例如底部工作条 `esc to interrupt`）。
- **变没变（导数）**：同一窗格**连续两帧**的内容是否在变。在变 = 有活动 = working；
  连续帧全同 = 停了 = 非 working（真实完成态的秒数不自己涨，见守卫 G2 语料）。

## 3. 判据规范：判什么、每个输入要产生什么输出

只保留 **working / idle** 两态（`done` 已按 2026-08-13 用户裁定删除；blocked 不属本判据验收面，
沿用现有采集与聚合，不在本判据里判）。每条目标判据都必须能由探针测试断言：

| ID | 判据 | 输入语料 | 必须输出 |
|---|---|---|---|
| P1 | 窗格标题在动 → working | 同一 pane 两帧标题 `◐ w-librarian` → `◑ w-librarian`（都在动，屏面 idle） | **working** |
| P2 | 屏幕底部内容在动 → working | 同一 pane 两帧屏尾 `◐\n────\n❯\n` → `◑\n────\n❯\n`（块在动，无文本信号） | **working** |
| P3 | 真实工作中版式 → working | 屏面含 `esc to interrupt`（在最后一个 `❯` 提示符之后，真实 working 版式） | **working** |
| P4 | 真实完成态 → 非 working | 屏面 `✻ Churned for 4s` + 空闲状态栏，无 `esc to interrupt` | **idle**（不得 working） |
| P5 | 静置 idle → idle | 屏面裸 `❯` + 空闲状态栏，连续帧内容全同 | **idle** |

**判据自检（每一条）——如果被测对象是坏的，命令会不会仍返回 0？**

- 被测对象改成「永远返回 idle」→ P1/P2/P3 全 FAIL → 命令转非 0 → 判据响。
- 被测对象复活字形白名单（认 `◐`/`⠋` 当 working）→ 对 P1/P2（`◐` 单帧认不出或静止时）
  仍会红，因为判据要的是**两帧在动**，不是单个字符存在 → 命令转非 0 → 判据响。
- 被测对象对完成态误判 working → P4 FAIL → 命令转非 0 → 判据响。
- 探针测试本身写错了 → `go test` 编译失败或红 → 命令非 0（基线就红，变异就无从谈起）→ 判据响。

## 4. 探针测试具体断言什么（判据命令的判定逻辑）

探针测试在 `.team/nodes/state-oracle/scratch/probe/probe_test.go`，四条：

| 测试 | 断言 | 期望 |
|---|---|---|
| `TestProbeRotatingTitleReadsWorking` | 标题两帧 ◐→◑ 在动 → 经时序判 working | 期望 **PASS**（被测对象对） |
| `TestProbeRotatingBottomBlockReadsWorking` | 底部块两帧 ◐→◑ 在动 → 经时序判 working | 期望 **PASS** |
| `TestGuardRealWorkingStillWorking` | 真实 working 版式（esc to interrupt）→ working | 期望 **PASS** |
| `TestGuardRealDoneNotWorking` | 真实完成态 → 不得 working | 期望 **PASS** |

探针用了「两帧」语料，所以实现必须能表达**时序/差分**（单帧看不清时，第二帧判第一帧）。
判据模块保留了旧实现的决策缝（`Detect` 单帧 + `Track(prev, sample)` 时序），
重建的实现可以在同一缝上写新逻辑——判据不看实现内部，只看这四条断言。

## 5. 处理采样混叠（为什么用「两帧在动」而不是「拉长确认次数」）

采样有混叠风险：短间隔连采几帧，可能采到同一动画帧（看起来静止，其实在动）。
**不要靠拉长确认次数**（那样会把真实的快完成拖成永不停歇，且参数随采样周期漂移）。
正确做法：**短间隔连采几帧，做差分**——只要连续两帧内容不同，就是「在动」的证据；
内容全同（完成态的秒数不自涨）就是「停了」。差分判据天然对字形改版免疫。

## 6. 你的任务：定点变异（验判据真的会红）

拿到本文档后，只读它 + 执行判据命令。步骤：

1. **基线**：跑 `bash .team/nodes/state-oracle/run-probe.sh`，记录退出码。
   - live 当前是占位 stub（诚实报 unknown）→ 基线应**非 0**（探针红）。
   - 重建完成、判据被满足后 → 基线应 **0**。
2. **变异**：在 `server/internal/agentstate/` 的决策源码里**改坏一处**——制造一个本文档声称
   该被抓到的倒退（例如：把 working 判定删掉、永远返回 idle；或删掉差分、只认静止帧）。
   改一个字符/挪一位即可。
3. **重跑**：`bash .team/nodes/state-oracle/run-probe.sh`，记录变异后退出码。
   - 变异后必须**转非 0**（基线 0 → 变异 1；或基线已非 0 → 变异必须更红/仍非 0 且理由成立）。
   - 判不出差异 ⇒ 判据无效，报告 **refuses**。
4. 把基线退出码 vs 变异后退出码、变异点写进 `.team/nodes/state-control/mutation-report.md`。

**判据有效（supports）** ⇔ 基线绿且变异红，且你亲手能复现。判据无效（refuses）⇔ 判不出差异。

## 7. 判据命令不碰的东西（边界）

- 判据命令只**读** live 源码、写到判据模块 scratch/；不修改 live 任何文件 → 对照席可以放心变异。
- 判据模块默认载归档化石，跑完还原 → 红测载体（化石）不被破坏。
- 判据不碰生产 daemon、用户真实 tmux、模拟器——全部在隔离的 Go 测试环境里判定。
