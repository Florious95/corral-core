## 0. 一句话

二级菜单 = **服务端把每一行 pane 的「原样标题 + 结构字段身份」实时推给 App**，App 只做两件事：
**标题原样画（零解析）、点一行用结构字段身份进三级终端**。

## 2. 三条不变量逐条写死

### 不变量①：pane 标题原样显示，一个字符都不解析、不匹配、不映射、不美化

**怎么保证**：

- **服务端**：`pane_title` 作为**不透明字符串**进协议，走 `Session` 新字段 `title`。服务端**不 trim、不 strip 前缀、不匹配 ◐/✳、不映射成任何状态**。原样塞进 JSON。
- **App**：渲染行时 `Text(text = entry.title)` 原样画。**禁止**任何 `.trim()/.startsWith/.contains/.replace` 作用于标题字符串。
- **代码约束（机械可查）**：App 端新增的二级渲染代码里，对 `title` 字段**不得出现** `startsWith/contains/trim/replace/removePrefix/substring` 等字符串操作。服务端新增代码里 `pane_title` 只出现在 `-F` 格式串与 `Session.Title` 赋值处。
- **探针断言**：`probe.sh` grep 服务端实现——`title` 字段赋值 = 原样透传（无处理函数）；App 渲染 = 直接 `Text(title)`。

### 不变量②：会话身份只用 tmux 结构字段 session_name/window_index/window_name，禁止从标题字符串里抠

**怎么保证**：

- **身份 ref**：沿用 `sessionRef(p) = Socket + "\x1f" + PaneID`（结构字段）。**ref 永不包含标题字符**。
- **展示名 name**：二级列表行展示名用 `window_name`（fallback `session_name`，discovery 已有 fallback）。**名字不来自标题**。
- **点行进会话**：App 点一行拿到的是服务端推的 `ref`（结构字段身份），`onOpenSession(ref, name)` → `SessionRoute(ref)` → `subscribe(ref)`。**标题字段在整个跳转链路里不参与寻址**。
- **协议约束**：`Session` 的 `ref`/`name` 由服务端从结构字段组装；`title` 是独立字段，App 不能用它做任何身份判断。
- **探针断言**：服务端组装 Session 时 ref/name 来源是 discovery 结构字段；App 跳转只传 ref。

### 不变量③：实时流只在二级菜单打开时拉数据，关掉即停；不 attach tmux 客户端

**怎么保证**：

- **服务端**：新增「二级菜单订阅」计数（`level2Subscribers`）。**有 ≥1 订阅者才跑二级 scan**；**零订阅者时零 tmux 调用**。用独立于一级 listingLoop 的 gate（或复用 idle-gate 模式：`countLevel2() == 0` 即 park）。
- **App**：二级菜单**进入**（`selectedWorkspaceCwd` 非空，即点到会话列表层级）→ 发 `Level2Subscribe`；**退出**（返回一级 / 进会话页 / 离开工作区页）→ 发 `Level2Unsubscribe`。**生命周期绑定屏幕存在**（Compose `DisposableEffect` onDispose 退订），不依赖任何后台定时器。
- **不 attach**：服务端取数**只用 `list-panes -a`**（discovery 已如此），**从不** `attach-session`/`new-session -d`。这保证多客户端不参与尺寸谈判、不压小用户真实窗口。
- **探针断言**：①二级订阅者计数为零时服务端零 tmux 调用；②服务端命令集合（grep 实现）永不出现 `attach`。

## 3. 形态裁定：二级菜单可点，点一行进那个会话（三级唯一入口）

**裁定**：二级菜单行**必须可点**，点一行进该会话的三级终端。这是 App 通往三级终端的**唯一入口**。

**链路**：
```
二级行（title 原样 + ref 身份）
  → 用户点该行
  → App onOpenSession(ref, name)   // ref = 结构字段身份
  → navState.activeSession = ref to name
  → AgentMirrorApp AppRoute.Session 分支
  → SessionRoute(ref, name) → createSessionViewModel(ref) → manager.subscribe(ref)
  → 三级终端流（snapshot/delta 镜像）
```

**为什么必须可点**：060 §二明确「二级菜单 = Ctrl-B w 的重绘」，Ctrl-B w 的每一行就是「点它进那个 pane」的入口。做成只读 = App 无法从任何路径进三级终端 = 产品失去核心功能（镜像+输入）。所以**二级菜单只读是倒退，必须可点**。

**实现分工**：
- t.server：服务端推行时，`Session.ref`（可寻址）必须保留——App 点行用 `ref` 进 `subscribe`。
- t.app：二级行 `onClick` 绑 `ref`，进既有 `SessionRoute`。

## 4. 协议设计（服务端 + App 两侧对齐）

### 4.1 `Session` 结构扩展（`server/internal/protocol/frames.go` + `app/.../conn/Frames.kt`）

```go
type Session struct {
    Ref   string `json:"ref"`             // 结构字段身份（socket\x1fpaneid），不进标题
    Name  string `json:"name"`            // window_name（fallback session_name）
    Cwd   string `json:"cwd"`             // 一级分组键
    Title string `json:"title"`           // 【新增】pane_title 原样，零解析
    Rows  uint16 `json:"rows"`
    Cols  uint16 `json:"cols"`
}
```

- `Title` = 不透明字符串，服务端原样透传，App 原样画。
- **不需要**结构字段单独暴露给客户端——ref 已由服务端从结构字段组装，客户端只认 ref。

### 4.2 二级菜单订阅帧（C→S）

新增两个控制帧，语义与 `Subscribe`/`Unsubscribe`（会话镜像）并列但独立：

```go
// Level2Subscribe: 客户端进入二级菜单时发，服务端开始推该客户端所在工作区的实时流。
type Level2Subscribe struct {
    Workspace string `json:"workspace"`   // cwd；空 = 订阅全部工作区（一级进入即刷场景）
}

// Level2Unsubscribe: 客户端离开二级菜单时发，服务端停止推。
type Level2Unsubscribe struct{}
```

- 服务端维护 per-connection `level2Subscribed bool` + 全局 `level2Subscribers int64`。
- **有订阅者才 scan**：二级实时流用独立 gate——`countLevel2Subscribers() == 0` 时零 tmux 调用（同 listingLoop 的 idle-gate 模式，但计数是二级订阅者而不是 authed）。

### 4.3 服务端推送（S→C）

- **复用现有 `Listing`/`ListDelta` 帧**（二级菜单视图 = 一个工作区下的会话集合）？**否**——一级/二级视图语义不同，二级要的是「单个工作区的会话实时流」，混用会把一级 diff 与二级订阅纠缠。
- **新增 `Level2Frame`**（S→C）：携带单个工作区的会话数组 + seq，服务端在二级订阅者存在时按 cadence 推送。

```go
// Level2Frame: 服务端推给二级菜单订阅者的实时快照（每次 scan 后全量替换该工作区视图）。
type Level2Frame struct {
    Workspace string    `json:"workspace"`
    Seq       uint64    `json:"seq"`
    Sessions  []Session `json:"sessions"`   // 每个 Session 含 ref/name/title/rows/cols
}
```

### 4.4 为什么用「全量替换」而不是 delta

- 二级菜单行数少（一个工作区通常 <20 会话），全量替换成本低。
- 全量替换**天然免 diff 复杂度**：每次 scan 把工作区会话整体推一次，App 端 `replaceAll`。
- 简化：不引入二级 delta 机制，只做全量 + seq（App 端可检测 seq 跳变重连）。

## 5. 服务端实现（t.server，Go）

### 5.1 数据源（已就绪，复用 discovery）

`discovery.Discover(ctx)` 已产出 `Model{Workspaces: [{CWD, Panes: [{Session, WindowIndex, WindowName, PaneTitle, ...}]}]}`。
二级 scan = 一次 `Discover`，取目标工作区的 Panes。

### 5.2 新增文件：`server/internal/api/level2.go`

```
- level2Subscribers atomic.Int64        // 全局二级订阅者计数
- level2GateCtx / level2GateStop         // 二级实时流循环（独立于一级 listingLoop）
- handleLevel2Subscribe / handleLevel2Unsubscribe   // ws_conn 帧路由接入
- level2Loop(ctx)                        // 二级 gate：countLevel2()==0 → park；>0 → scan+push
```

**核心逻辑**：
```go
func (s *Server) level2Loop(ctx context.Context) {
    for {
        if s.countLevel2Subscribers() == 0 {
            select { case <-ctx.Done(): return; case <-s.level2WakeCh: }
        } else {
            select {
            case <-ctx.Done(): return
            case <-s.level2WakeCh:
            case <-time.After(s.level2Interval):
            }
        }
        s.publishLevel2(ctx)   // 一次 Discover → 对每个订阅者所在工作区组装 Level2Frame 推送
    }
}

func (s *Server) publishLevel2(ctx context.Context) {
    model, err := s.discoverer.Discover(ctx)   // list-panes -a，零 attach
    if err != nil { log; return }
    // 对每个 level2 订阅者，取其 Workspace 字段，从 model 找到该 cwd 的 Panes，
    // 组装 []Session（ref=sessionRef, name=window_name||session_name, title=pane_title 原样），
    // 推 Level2Frame。
}
```

`case protocol.Level2Unsubscribe: c.handleLevel2Unsubscribe(t)`。

## 8. 工程红线对照

- **静默经济（红线①）**：二级实时流有订阅者才 scan、零订阅者 park（gate 模式），空闲 CPU 趋近 0。
- **进程卫生（红线②）**：二级循环由 Server.Close 终结；退订幂等；不 attach 不产生额外 tmux 客户端。
- **资源有界（红线③）**：每次 scan 全量替换，不累积；订阅者计数有界（每连接至多一）。
- **可达性（红线④）**：Level2Frame 走既有 WS 通道，与一级 listing 同链路。
- **失败可见（红线⑤）**：订阅帧校验失败明确报错；scan 失败日志 + 保留上次视图。

## 9. 与一级菜单刷新模型的关系（不冲突）

- **一级**（保留）：`listingLoop` idle-gated 周期扫描 → `Listing`/`ListDelta`（cwd 聚合）。进入即刷 + 下拉刷 + 零周期（refresh-and-contract 账本已落地）。
- **二级**（本次新建）：`level2Loop` 独立 gate → `Level2Frame`（单个工作区会话流）。只在一级进入二级时活跃。
- 两套循环**互不干扰**：一级的「进入即刷」触发一级 scan；二级的「打开即订阅」触发二级 scan。App 端一级进二级时，一级 view 保留（可返回），二级流单独订阅。
