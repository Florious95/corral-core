## 真相源：这是已裁定但未实现的需求，不是新缺陷

`requirement-wiki/raw/019-键盘弹出视口上推.md`（IMMUTABLE），标题本身就是规则：

```
# 019 键盘弹出：视口上推，不触发重绘

键盘弹出时**终端 rows/cols 不变**（不触发 tmux resize），但**视口要上推**
——像聊天软件一样内容区平移，露出当前内容。当前实现是锁死不动，内容被键盘遮挡，错。
```

配套 `requirement-wiki/raw/041-捏合缩放闪烁重绘.md`：

```
捏合过程中只做**本地视觉缩放**（Canvas scale），手指松开后才算最终 rows/cols 发一次 resize。
即「捏合时预览，松手时生效」。
```

taskbook `fix-terminal-resize-cluster` 已把该裁定写成规则：
**「仅首次进入 CLI 时 resize 一次，此后键盘/输入框不触发 resize；
捏合缩放松手后发一次 resize（过程中只做本地视觉缩放）；退出时恢复原始尺寸。」**

## ⚠️ 与 D-20 的边界（极易混淆，上届就混过）

同一条裁定有两半：

| | 状态 |
|---|---|
| ① 键盘弹出**不遮挡**内容（视口上推） | ✅ 已修（`ui-redesign` commit「IME 空洞根治」，在 git HEAD 内） |
| ② 键盘/输入框变化**不触发 resize**（rows/cols 不变） | ❌ **从未实现，本任务就是它** |

交接文档把 D-20 记作「已修已验证」，那只覆盖了①。
**「不遮挡」不等于「不 resize」，两者不可互相代替。** 不要因为 D-20 已修就以为本条已做。

## 关键判据：要测的是「有没有发 resize 帧」，不是「边界变没变」

终端 View 的 bounds 变化是布局的必然结果（输入框变高，终端可用区域变小）。
**真正要消灭的是 rows/cols 变化引发的服务端重排。**

所以红测的断言对象应是：
- IME 弹起时，**是否向服务端发出 resize 协议帧**？（应：否）
- 输入框由一行变两行三行时，**是否发出 resize 协议帧**？（应：否）
- 首次进入 CLI 时发一次 resize（应：是，这是唯一允许的一次）

协议侧参考：`docs/protocol.md`；服务端已有 no-op resize skip（D-27 已修已提交）。
