# 任务书 · t.e2emouse · 端到端：在模拟器里点一下，看工具调用会不会展开

## 一、为什么有这一格

输入透传四步全部并线、各自单测全绿，**但四步从来没有连在一起跑过**。
没人在 app 里点过一下，也没人看见工具调用展开。

本工程铁律（CLAUDE.md「眼见为实」）：

> **单元测试绿 ≠ 问题修了。** 测试验证代码正确性，模拟器验证用户体验，两者不可替代。
> ⛔ 不允许标记「已修」除非有实测截图。

**用户的原始需求就是这一句**：「我在 Agent 的界面用鼠标点击一个工具调用，它会展开吗？
就像我在电脑上用鼠标左键去点。」

⇒ 这一格要回答的**就是这一句**，⛔ 不是「字节到没到 pty」（那已经验过了）。

## 二、已验过的（⛔ 不必重做）

1. Claude Code 的 pane 确实开着 **SGR 1006 + 1002/1003**（tmux format `mouse_sgr_flag` 等）
2. 经 `send-keys` 注入的 SGR 字节**逐字节到达 pty**，与 tmux `mouse` 开关无关
   （隔离实验各 10/10，`.team/perf/tmuxmouse-*.json`）
3. 四步各自单测全绿

## 三、这一格要排除的三个断点（⛔ 一个都不许跳过）

**B1：点击有没有被壳里既有的手势处理先吃掉。**
第 4 步的采集加在 `TermSurfaceView`，但若有更早的 handler 消费了 tap
（唤起键盘 / 滚动 / 长按菜单），新路径根本不会被调用。
**判据：在模拟器上 tap 之后，logcat 里要能看到我方发出了 `InputFrame.bytes`。**

**B2：像素→行列换算对不对。**
单测用的是我们自己造的网格参数，⛔ 不是真实渲染出来的。
**判据：点屏幕上某个已知字符所在位置，注出去的 SGR 坐标要与那个字符的真实行列一致。**
（做法自定：可先让 pane 里显示带坐标标记的内容，再点特定标记。）

**B3：点在「工具调用那一行」上，对面会不会展开。**
这取决于 Claude Code 自己的命中区域。
⚠️ **如果 B1、B2 都通了而 B3 不展开，那不是我方缺陷**——照实报，写清你观察到什么。

## 四、怎么做

1. 起模拟器（**先核 `free+inactive ≥ 2500MB` 且 `load1 ≤ 12`**；不满足就等或报 `blocked_env`）。
   ⚠️ 当前实测 free+inactive≈2589MB，**很紧**，⛔ 不要同时开别的重活。
2. 装 APK：`.team/nodes/_driver/agentmirror-mouse.apk`（md5 `e285492e547b`）。
3. **隔离 daemon + 隔离 tmux**（⛔ 不碰生产 `:9900`、⛔ 不碰用户真实 tmux），
   在 pane 里跑一个**会开鼠标上报**的东西。
   ⚠️ **优先跑真的 Claude Code**（那才是被测场景）；跑不了就退而用一个自制 TUI，
   但必须**在说明里写清你用的是哪种**，⛔ 不许把自制 TUI 的结果说成 Claude Code 的结果。
4. 用 `adb shell input tap <x> <y>` 点击，从 `adb logcat` 取我方的发送记录，
   并 `adb exec-out screencap` 取**点击前后各一张截图**。
5. B1/B2/B3 各自给结论。
