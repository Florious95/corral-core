# 069 进菜单即时刷新

- 探针：`.team/nodes/rf-probe/probe-rf.sh`（未改）
- 契约：`requirement-base/entries/069-进菜单必触发一次即时刷新.md`

## 一级

`handleList` 每次都走 `refreshListing`（真实 `rebuildCatalog`），不再在有快照后被 `ensureInitialScan` 短路。

- 回复里的 `listing` 是这次重扫后的世界（A-rf-l1）。
- 重扫失败：保留原快照并把它作为 listing 回给客户端，**不发空列表**。日志带 `had_cache / prev_sessions / cur_sessions / refresh_err`。
- 进入瞬间的画面由客户端 062 缓存承担；服务端 list 回复负责「内容是对的」。失败时服务端回的就是缓存快照。

## 二级

`handleLevel2Subscribe` 每次进入都 `wakeLevel2`（含同一连接重订阅，不靠 0→1），并**同步** `publishLevel2` 一帧，不等 2s cadence。

`publishLevel2` 在 Discover 失败时直接 return，不推空 `sessions=[]`。

## 经济

零 level2 订阅者时 loop 仍 park。进入是事件驱动的一次扫。一级 listingLoop 的 cadence 不变（探针把它拉到 60s 就是为了证明不是 loop 救场）。
