# 069 进菜单即时刷新（服务端）

- 契约：`requirement-base/entries/069-进菜单必触发一次即时刷新.md`
- 探针：`.team/nodes/rf-probe/probe-rf.sh`（只读，未改）
- 施工目录：`.worktrees/wt8.srv/server/`（派单写隔离）

## 一级

`handleList` 每次走 `refreshListing` → `rebuildCatalog`（真实 Discover），不再被 `ensureInitialScan` 在有快照后短路。

- `list` 的 `req_id` 回复是这次重扫后的世界（A-rf-l1 / 探针 ①）。
- 进入瞬间画面由客户端 062 缓存承担；服务端这一帧负责「内容是对的」。若把缓存作为同一 `req_id` 的第一帧发出去，探针 `waitFrame(req_id)` 会吃到旧世界，① 永远红。
- 重扫失败：保留原快照并作为 listing 回给客户端，**不发空列表**。日志带 `had_cache / prev_sessions / cur_sessions / refresh_err`（操作数，不是只记判决）。

## 二级

`handleLevel2Subscribe`：

- 首次订阅：`markLevel2`（0→1 仍唤醒 loop）
- 同一连接再订阅：也 `wakeLevel2`，**不只靠 0→1**
- 两种路径都同步 `publishLevel2` 一帧，不等 2s cadence

`publishLevel2` 在 Discover 失败时直接 return，不推空 `sessions=[]`。

L2 序号改走 `nextLevel2Seq`，不再占用 listing `nextSeq`（避免 list_delta 断号逼客户端重 list）。

## 经济

零 level2 订阅者时 `level2Loop` 仍 park，进入是事件驱动的一次扫。一级 `listingLoop` cadence 不变。未把轮询改成常开。
