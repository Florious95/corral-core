## 死 socket 怎么造的（`dead_socket_recipe`）

与 `server/internal/discovery/scan_test.go` 的 `createStaleSocket` 同类：Python `socket.AF_UNIX` **bind + listen + close**，inode 留在盘上、没有 listener。自检：`tmux -S <f> list-sessions` 得到 `rc=1`、`no server running`。

文件名 `dead-000`… 只放在隔离目录 **`/tmp/e2e-sockfix/`**。恒定 1 个活 socket：`/tmp/e2e-sockfix/live`（`/bin/cat` 复制为名为 `claude` 的文件，`exec claude`；`ps -o comm=` = `claude`）。用户真实 tmux 目录本格未操作。

listingLoop 在 0 个已认证客户端时会 park。本格始终挂着 1 条 WS 订阅，否则扫不到死 socket、曲线会假平。第一次 before 跑用了带 2s `Read` 超时的旧客户端，连接 2 秒后被掐掉，daemon 日志出现 `ws: sendq health` + `read_error`，随后整条曲线 mean=0——**那次作废**，下文数字全部来自订阅一直活着的重跑。

## 改了哪几行

只动 `server/internal/discovery/`（外加 `doc.go` 一句说明）。**没改 `list-interval`。**

| 位置 | 做什么 |
|---|---|
| `scan.go:79-97` `DiscoverWithDirs` | 每个文件先 `probeSocket`；只有探活成功才 `scanServer`（fork `tmux list-panes`） |
| `scan.go:283-284` | `staleTTL=30s`，`probeTO=80ms` |
| `scan.go:334-353` `probeSocket` | 非 unix socket 直接跳过；命中黑名单（同 path+inode/mtime 且未过期）跳过；否则 `net.DialTimeout("unix", path, 80ms)`，失败 `markStale` |
| `scan.go:267` `fileIdent` | `dev`+`ino`+`mtime`。文件被换掉（死→活）inode 变，立刻再探，不等 TTL |
| `scan.go:161-164` | 测试钩子 `scanServerHook`，生产为 nil |

黑名单策略：探活失败或 `scanServer` 失败 → 记 `{path, ident, until=now+30s}`。同 ident 在 TTL 内不再 Dial、更不 fork。TTL 到期会再 Dial；仍死则再记 30s，**仍然不 fork**。活 socket 每次都 Dial + fork（发现集合不缓存）。

## 判不出的部分

- 隔离 1 活 + 140 死的 **mean 4.9%**，对不上生产「21 活 + 140 死、mean ≈23%」。能坐实的是「CPU 随死 socket 数涨、修完不涨」；不能把 4.9% 说成生产 23% 的逐点复现。生产瞬时 `top` 与本格 TIME 差分也不是同一口径；本格 N=140 的 p95 已是 11.9%。
- 没有在生产进程上采样（红线）。
- 没有用并行扫描；单线程 Dial 140 个死 socket 仍然廉价，after 曲线已平，没再加并行。
- 第一次 before（订阅 2s 后断）的全 0 曲线作废，不写入 json。
