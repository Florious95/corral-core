## 一、命中项（按关键词逐项，含命中编号与原文关键句）

### 1. daemon 常驻
- **命中 010** 原文："一个**在节点（主机）上运行的后台进程**（服务端）。"（验收标准之二——后台常驻进程本就是交付物本体）
- **命中 004** 原文："后台期间的感知交给推送，不交给保活。"（服务端常驻、客户端不保活，常驻面在主机侧）
- **命中 011** 原文："推送/后台 | Android **前台服务 + 常驻连接**，不依赖 FCM/Google 服务"（服务端为常驻连接面）

### 2. 失败可见
- **命中 003** 原文："发送必达：注入后有回执（确认字节已进 pane），失败明确报错，不允许'发出去了没反应'。"（标准二——失败必须可见、静默等待即缺陷）
- **命中 016** 原文："用户真实手机走完**首触清单**，全程无阻断、失败必有明确报错"
- **命中 018** 原文："状态可视：加载/空态/错误态每页专门设计（不是白屏或裸文本）"（失败/空态须专门设计，功能绿≠失败可见）

### 3. 进程卫生
- **命中 001** 原文："服务端是 sidecar——attach 到用户**已经在跑**的 tmux 会话上，而不是要求任何东西为它重新启动"；"以'不动用户的 tmux'为第一原则"（daemon 非侵入、不搅动既有进程面）
- **命中 004** 原文："客户端彻底无状态：App 只是渲染器 + 输入框，所有状态在主机"（进程被系统回收亦无残留负担）
- **命中 011** 原文："服务端语言 | **Go**，单静态二进制"（单二进制、零依赖进程面）

### 4. 静默经济
- **命中 004**（近似）原文："轻量化是结果不是手段：因为无状态所以内存占用极小，iOS 倾向挂起而非杀死。用户原话'后台的本质是轻量化'"
  ——客户端侧空闲资源趋零的近似条款；服务端侧"零连接/零订阅空闲 CPU 趋近 0、无固定子进程派生"的静默经济红线在 CLAUDE.md 工程常识红线，不在需求库（见无命中项）。

### 5. 日志
- **无命中**：requirement-base 无 daemon 日志落盘、失败路径可观测的直接条目（010 隐含后台进程需可观测，但未明写日志条款；日志接管/探针要求出自现场基 FIELD.md 与工程常识红线，非需求库，不引用）。

### 6. 重启恢复
- **命中 004** 原文："冷启动 → 重连 → 首屏快照，1 秒内恢复到被杀前一模一样的画面"
- **命中 003** 原文："状态零丢失：事实源在主机 tmux，链路只是投影。WiFi 切蜂窝、App 被杀、隧道闪断，重连后重放当前屏幕即完全恢复。"
- **命中 013** 原文："老化实验：20 轮杀-恢复循环，验证无状态免疫（[[004]]）；flaky 靠复跑统计，不靠单次通过判定"
- **命中 015** 原文："老化实验：daemon-restart 20/20 + connection-drop 20/20——[[004]] 无状态免疫实证。"

### 7. 生产验收
- **命中 008** 原文："**不是 MVP，是生产可用的完整产品。**"
- **命中 010** 原文："一个**生产级别可用的安卓 APP**。一个**在节点（主机）上运行的后台进程**（服务端）。"
- **命中 013** 原文："失败四归因：product / harness / baseline / flaky 四类归因。**判错归因比失败本身危害更大**"（直接映射审计任务 product|environment|unknown 三选一结论的归因哲学）
- **命中 016** 原文："生产级验收 = 真机首触零阻断"；"自动化测试与门禁是**必要非充分**条件"；"未验证清单…禁止计入'已验收'"
