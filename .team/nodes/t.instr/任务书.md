# 任务书 · t.instr · 做「按键 → 回显」量具（第 0 步的另一半）

## 一、为什么需要它（⛔ 别跳过这段，跳过就会做成一个量错东西的量具）

工程里已有量具 `PerfTrace`，它的八事件链是
`tap → route_enter → subscribe_sent → geom_seed → first_frame_recv → snapshot_applied → first_draw → layout_settled`。
**这条链量的是「打开一个会话有多快」。**

接下来六步要改的是**输入透传**——按键、鼠标点击怎么送到对面那个 Agent。
这件事**基本不碰**打开会话那条链。所以：**改完拿现有量具一测，`first_draw` 纹丝不动，
判据给绿灯——但它根本没量你改的东西。**

用户的硬要求是「每一个步骤都要有性能基线的回测」。**在这把量具做出来之前，这条要求兑现不了。**
这一格就是把它做出来。

## 二、要量的东西的精确定义

**从「客户端把一个按键交给传输层」到「这个按键的回显字符出现在屏幕上」的耗时。**
输出 p50 / p95，可复跑。

### 已定的设计（⛔ 这几条是裁定，不是建议）

1. **远端 sink 用 `cat`，⛔ 不用 shell。**
   理由：`cat` 对收到的每个字节**原样回吐一份**，一对一、确定、无提示符/补全/高亮噪声。
   用 shell 会混进提示符重绘、历史搜索等等，量到的不是回显。
2. **每次迭代打一个不同的字符**，在 `a`–`z` 里循环。
   理由：这是 **send 与 echo 一一配对**的手段。全打同一个字符就无法判断屏上这个 `a`
   是第 3 次还是第 4 次的回显——配不上对，p50 就是编的。
3. **两个新 PerfTrace 事件**（沿用现有 PerfTrace 机制，⛔ 不要另起一套）：
   - `key_send`：客户端把这一次输入交给传输层的那一刻，**带序号 seq 与字符**；
   - `key_echo`：终端仿真器消费到该字符**且这一次绘制完成**的那一刻，**带同一 seq 与字符**。
   两事件必须能凭 `(seq, char)` 配对。⛔ 只打时间戳不打配对键 = 白做。
4. **PerfTrace 必须保持「setprop 可关、关时零成本」**。这是本工程既有约定，
   ⛔ 不许为了这个量具在热路径上留下无条件开销。
5. **采集与计算**：从 `adb logcat -s PerfTrace` 取数（与既有 `tools/perfbase/` 一致，
   ⛔ 不要另找数据源），算 p50/p95，落成 json。

### ⚠️ 你必须先核实的一件事（核不出就照实说，⛔ 不许假设）

**今天的协议能不能只发一个字符？** 现状是 `Input` 帧只有整行 `Text` 与闭集 `Keys`
（见必读坐标）。如果 `Input{Text:"a"}` 这种**单字符整行**是合法的、且服务端会走
`tmux send-keys -l "a"` 送出去，那么**这把量具在今天、在一行产品码都不改的情况下就能量出一个基线数**——
这正是第 1/2 步改动的「改前」对照。

- **能**：照上面的设计做，并在报告里写明你是怎么核实的（`文件:行号` + 实跑输出）。
- **不能**（比如服务端强制追加回车、或单字符被拒）：**照实写清楚是哪一行代码挡住的**，
  并给出你认为最小的可行替代（例如量「一行文本 → 整行回显」作为过渡指标，
  并注明它与真正的按键延迟差在哪）。**⛔ 不要为了让量具跑起来而偷偷改产品行为。**

## 三、交付物（路径级）

1. **量具脚本** `tools/perfbase/keyecho.sh`
   - 参数化迭代次数（默认 ≥30），跑完输出 json 到 `.team/perf/keyecho-<时间戳>.json`
   - json 至少含：`n`、每个夹具的 `p50`/`p95`、原始样本数组、被测 APK 的 `md5`、
     采集时的 `load1`（⚠️ 换负载区间不可直接比较，必须带负载读数）
   - **配不上对的样本必须单独计数并写进 json**（字段 `unmatched`），⛔ 不许静默丢弃——
     丢弃会让 p95 好看
2. **产品侧打点**：`key_send` / `key_echo` 两个事件（改动应当很小，⛔ 只加打点，不改行为）
3. **一次实测结果** `.team/perf/keyecho-baseline.json`（n≥30）
4. **说明** `.team/nodes/t.instr/说明.md`：怎么跑、配对率是多少、
   **这把量具量不到什么**（例如它量不到网络抖动 / 量不到鼠标），以及你核实「单字符能不能发」的过程与结论
