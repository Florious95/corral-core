## 用户三症状（各有基线 vs 当前，d480 / d440）

数据：`jank-compare.txt`。脚本：`perf-check.sh`（trap：keyevent 111 + `wm density reset`）。

### S1 进入重排

从二级列表点进会话，导出 `viewport` / `reflow` / `grid`。

| | resized=true | reflow | grid | 点进到会话页墙钟* |
|---|---|---|---|---|
| baseline d480 | **1** | 2 | 1 | 14.4 s（含 12 次 screencap） |
| current d480 | **1** | 2 | 1 | 14.5 s |
| baseline d440 | **1** | 2 | 1 | 14.1 s |
| current d440 | **1** | 2 | 1 | 13.5 s |

\*墙钟被连拍 screencap 拉长，**不是**用户感知的进页时间。可比的是 **resized=true 次数：两边都是 1**（081：进 CLI 只允许一次 resize）。

**结论：进入重排不是 085 引入的。** 层：081 首帧 cols 协商 + Compose 进页布局。再砍次数会弱化 081。未做「排好再展示」。

### S2 滑动掉帧（≥600 帧，量具有效）

`gfxinfo reset` → 160 对上/下 swipe（80ms）→ 读数。

| | total | janky% | p95 |
|---|---|---|---|
| baseline d480 | 743 | **94.75** | 32 ms |
| current d480 | 747 | **95.05** | 34 ms |
| baseline d440 | 771 | **90.66** | 34 ms |
| current d440 | 777 | **90.09** | 34 ms |

判据：当前相对基线**不劣化**（d480 95.05 vs 94.75 在 8% 容差内；d440 略降）。**janky% 没有可见下降。** p95 两边 32–34 ms。

**结论：滑动掉帧不是 085 投影引入的。** JVM 上 colorFor 快 10×，模拟器 swipe 的 p95 纹丝不动 ⇒ 热路径剩下 `TermSurfaceView.onDraw` 铺格/drawText/GPU，外加 swipe 输入。未节流输入来把 janky% 做绿。

### S3 进入白屏

点进后 12 次 `screencap` 原始帧，内容区（避开顶栏/键条）唯一颜色数 ≤6 算「空内容」（白或纯底都算，**不把改底色当修好**）。

| | 空帧 | 首帧已有内容的上限（ms） |
|---|---|---|
| baseline d480 | 0/12 | 1269 |
| current d480 | 0/12 | 1273 |
| baseline d440 | 0/12 | 1523 |
| current d440 | 11/12* | 1236 |

\*current d440 会话截图 `shot-current-d440-session.png` 有真实 CLI 内容（状态行/提示符）；11/12 是 **alt-screen 大面积纯底让均匀度启发式误报**，不是白屏回归。screencap 单次 ~1.2s，**亚秒白闪测不到**。

**结论：在现有采样粒度下，085 没有把「进会话白屏」变坏。** 层：snapshot 到达前 `onDraw` 若 presenter 未就绪会提前 return（默认 View 底）；有 presenter 后画的是主题纸色空格。未把白改成主题色冒充修复。亚秒白闪需要更密的帧采样才能定罪。
