# 现场基 · research-oss-terminal-solutions

## 用户原话（本任务的由来）

> 「我还是认为这个东西应该有**开源的办法**。就比如说 herdr 它本来是一个 CLI，
>  然后它可以在 SSH 的客户端里面被使用，那也意味着它**对移动窗口做了优化**，
>  这些问题都应该能找到解决办法。」

leader 起初把这条缩水成「对照我们自己的 Web 端」，被用户指出没照做。
**本任务是真正去看外部开源实现怎么解决的。**

## 要解决的四类问题（用户真机反复报告，历史上从未真正解决）

1. **右侧文字被截断**：最右一列跑出屏幕，只能看到半个字（第 4 次报告）
2. **整屏自上而下重刷**：发消息后有概率整屏重画，导致底部最新消息看不到（第 4 次报告）
3. **向上滑完全失效**：App 只加载了一屏；捏小字体完全滑不动，捏大字体才「像能滑」，
   滑的仍是同一屏而非历史。用户要的是「像在 CLI 滚鼠标滚轮那样翻到最开始」
4. **捏合后整屏重绘闪烁一段时间才好**，且字号不持久化

## 调研对象（至少覆盖，可增补）

- **xterm.js**（MIT）—— 本仓库 `web/` 已在用，`web/vendor/xterm/` 有 dist；
  建议另取其源码仓库读 `Buffer`/`BufferLine`/`reflow`/`Viewport` 实现
- **libvterm / vte** 类终端状态机 —— 屏幕缓冲与 scrollback 的分离方式
- **alacritty / wezterm**（Apache-2.0 / MIT）—— grid 数据结构、resize 时的 reflow 与锚定
- **mosh** —— 预测式本地回显与重绘最小化策略
- **移动 SSH 客户端**（Blink、Termius 等）对窄屏 cols 的处理
- **herdr**（用户点名）—— 若能取到其实现，看它在 SSH 客户端里对移动窗口做了什么优化

## 每类问题要回答的

- 哪个开源实现解决了它
- **具体怎么做的**（数据结构 / 算法 / 关键函数）
- **出处**：仓库 + 文件 + 函数名
- 许可证，以及能否直接采用
- **落到我们**：要改 `app/.../termview/` 或 `app/terminal/` 的哪个函数的什么行为

## 硬约束

- **许可证**：终端内核须 Apache-2.0 兼容（工程 GPL 隔离红线）。
  Termux 系是 GPLv3，**不可用**。MIT / Apache-2.0 可引用。
  借鉴模型与算法始终安全，复制 GPL 代码不行。
- **不改产品代码**，写盘范围仅 `docs/`
- 需要联网取源码可用 `git clone` / `curl`；只读，不要把外部仓库落进本工程目录，
  用 `/tmp` 下的临时目录，用完清理

## 为什么这条值得认真做

这四条已经修过至少四轮、每轮都「修好了」、每轮你一用还在。
**从零发明终端视口模型是这个工程一直在做且一直失败的事。**
本任务的价值就是终结它：把别人验证过的模型拿过来，而不是再猜一次。
