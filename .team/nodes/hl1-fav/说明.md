根因=收藏页 `FavoriteList` 把 [FavoriteBook.rows] 的加入序又套了一遍会话页 `sortSessions`（运行中靠前），显示被打乱；随后用 `items.zip(rows)` 把**重排后的展示项**和**未重排的源行**按下标对齐，点击按这个错位 map 回源。于是「zeta 显示在上面，点下去打开的是 alpha」。会话页（`SessionListScreen` / `L2SessionList` / 浮层 `byRef[item.id]`）本来就是按 id/ref 查，不是下标。
修法=收藏页去掉 `sortSessions`，展示序=传入 rows 序；点击改为 `rows.associateBy { it.ref }[item.id]`（身份绑定）。会话页保持 `sortSessions` 合法重排，点击继续按展示项 id（= ref）回源，并在 L2 / WorkspaceScreen / SessionSwitchSheet 标明 094，⛔ 不是靠关排序遮掩绑定错位。
先验红输出=修产品代码之前跑 `FavoriteOrderAndClickBindingTest` 两条全红，原文见下（完整 XML：`.team/nodes/hl1-fav/tmp/prior-red.xml`）。
