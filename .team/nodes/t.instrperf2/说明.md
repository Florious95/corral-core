## 这轮结论能说到什么程度

`sh tools/perfbase/judge-instr-ab.sh` → **FAIL rc=1**
（4 段 B 相对同批 A 超过 +10%）。全文 `.team/nodes/t.instrperf2/judge.log`。量测三闸都过了：release、load1=11.92≤12、每组每夹具 n=20。所以这不是「不可判」，是门红了。

红的四段：

- `real_claude_idle first_draw p50` +15.0%（620.0 → 713.0）
- `real_claude_idle layout_settled p95` +15.0%（1546.9 → 1778.9）
- `redraw_tui first_draw p50` +16.9%（551.5 → 644.5）
- `big_scrollback first_draw p95` +13.0%（772.1 → 872.8）

同时：`redraw_tui first_draw` 的 **p50 +16.9% 而 p95 −13.0%，符号仍不一致**；`big_scrollback first_draw` p50 是 −8.6%（B 更快）而 p95 是 +13.0%。所以：

- **能**写成：在 release + load1≤12 + n=20 的达标条件下，判据按 10% 门给出 FAIL。
- **不能**写成「打点让打开会话稳定地全面变慢」（有的段 B 更快，同一夹具 p50/p95 会反向）。
- **不能**写成「一点没退」。
- **不能**写成已经验证「打点关着时的代价」。
