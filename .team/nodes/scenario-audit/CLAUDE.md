# 知识基底 · scenario-audit（用户场景全景审计与覆盖设计）——Fable 5 攻坚

## 0. 任务
- 目标：产出本产品的**用户场景全景覆盖设计** `docs/scenario-coverage.md`，以对抗性思维（假设每个角落都会坏）穷举"用户旅程 × 环境变量"矩阵，并对每一格标注四态之一：
  ①已覆盖（指认具体测试/门禁）②可自动化-未覆盖（给出测试形状与优先级）③不可自动化（进真机首触/回归清单，给出人工步骤）④设计缺失（产品行为本身未定义，列为需求议题）。
- 交付：docs/scenario-coverage.md（矩阵+缺口清单）+ 按优先级排序的**自动化补齐任务清单**（每项含建议 id/goal/acceptance 形状，leader 据此分波派发）+ 真机验收清单 v1。
- 验收：`bash -lc 'test -s docs/scenario-coverage.md && python3 -c "import sys; s=open(\"docs/scenario-coverage.md\").read(); assert s.count(\"|\")>100"'`（矩阵实质存在）+ leader 逐节审。
- 写范围：docs/scenario-coverage.md。**只审计不修码**。

## 1. 审计入口（起点不设限，对抗性补全）
维度轴（至少）：首触与配对（扫码/手填/错token/坏QR/服务端未启/版本不匹配/换WiFi再配）；日常会话（打开/滚动历史/输入含中文输入法与联想/多行粘贴/发图相册与拍照/捏合字号/旋转/暗色）；真实终端内容（Claude Code 实际 UI 全要素/256色真彩/宽字符emoji/大输出洪峰/alt-screen 如 vim/htop/进度条控制序列）；舰队（几十目录几百会话的列表性能/状态徽章/通知点击深链/并发多会话切换）；网络角落（WiFi↔蜂窝切换/弱网/断网重连/服务端重启/tailnet 场景/多网卡）；生命周期（杀App/锁屏久置/系统回收/手机重启/低电量优化白名单/厂商ROM杀后台）；异常与安全（错地址/错token/token轮换/多设备同时连/上传超限文件/服务端磁盘满）；无障碍与国际化（可后置但要列出）。
环境轴：真机（多厂商ROM）/模拟器/暗色/横屏/小屏/Android 版本跨度（minSdk 26→35）。
