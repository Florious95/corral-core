## 0. 裁定（实现席位只执行这一段，不要自己再选）

**选定：方案 1「本地缓冲 + 光标锚定回读」。否决方案 2「镜像 + 按键捕获」。否决把手机框改成 Heeler 那种「本地起草、Send 一次投递」。**

理由一句话：成熟 Agent 伴侣 APP **不是**在 1/2 之间二选一去「追上 CLI 输入行」，而是把「起草」和「操控 TUI」拆成两条通道，从而让矛盾不成立。我们被 084/059 锁死必须实时差分，**不能**抄它们的投递通道，但 **必须**抄这条通道拆分，并在控制键改写了远端输入行之后，用仿真器光标（不是写死行号）把 `已同步文本` 读回来。

实现席位若改成方案 2 或改成「发送才同步」，E2–E5 与 087 验收全部作废。

## 1. 成熟产品实际怎么消解这个矛盾

矛盾的本质是：**同一个字符串不能有两个作者**。手机框若自称「CLI 输入行的完整编辑器」，CLI 自己的 Tab / Esc Esc / ↑ 历史就是第二个作者；084 的 `已同步文本` 会变成过期信念（契约 087 §1）。

公开文档里，成熟产品用三种互斥策略把「两个作者」拆开。没有一家在 alt-screen 上靠写死行号回读输入行来维持「本地框 == CLI 行」的实时差分。

### 1.1 Agent 伴侣：本地 Composer + 一次投递 + 控制键走 PTY（Heeler / herdr）

公开行为（不是源码）：

- 详情页上面是 **libghostty 直播终端**（显示、回滚、触摸滚动驱动全屏 TUI），下面是 **原生 Composer** 用系统键盘本地起草。Send **一次性**投递完整消息。文字在终端下方本地起草；工具键盘的 Agent 控制键直接操控实时 TUI。
  来源：[Heeler README](https://github.com/ZingerLittleBee/Heeler/blob/main/README.md)、[README-zh](https://github.com/ZingerLittleBee/Heeler/blob/main/README-zh.md)
- 连接层把两通道写死：**草稿留在本地 Composer，直到 Send 发出一次 `agent.prompt` RPC；只有工具键盘的显式 Agent 控制键直接经 PTY 下发。**
  来源：同上 README「How it connects」段
- 架构裁定：终端是显示面，键盘/粘贴/指针点击 **不进 PTY**。工具键盘的 Esc / Tab / Shift-Tab / 方向键 / Enter / Backspace **直达 PTY**；Snippet / Skill 改的是 **本地草稿**。Send 走一次 `agent.prompt`。Agent 处于 Blocked 时 `agent.prompt` 会被 herdr 以 `agent_blocked` 拒绝（自动 Enter 会误确认对话框），此时 Send 改为把草稿打进 Attach PTY **但不按 Enter**，再交出工具键盘让用户按 Enter 或 Esc。
  来源：[docs/adr/0013-live-terminal-with-local-composer.md](https://github.com/ZingerLittleBee/Heeler/blob/main/docs/adr/0013-live-terminal-with-local-composer.md)、[CHANGELOG 0.1.1 #217](https://github.com/ZingerLittleBee/Heeler/blob/main/CHANGELOG.md)、[CHANGELOG 0.1.0 #182](https://github.com/ZingerLittleBee/Heeler/blob/main/CHANGELOG.md)
- 控制键 **不改草稿**：「Its Agent controls send Esc, Tab, Shift-Tab, arrows, Enter, and Backspace directly to the Agent **without changing the draft**.」
  来源：[CHANGELOG 0.1.0](https://github.com/ZingerLittleBee/Heeler/blob/main/CHANGELOG.md)
- 附件：加号在 Send 左侧；SFTP 暂存后 **把路径插入本地草稿且不提交**。
  来源：README「Attachment staging」；[CHANGELOG 0.1.0 #182](https://github.com/ZingerLittleBee/Heeler/blob/main/CHANGELOG.md)；[docs/design/composer-staging-store.md](https://github.com/ZingerLittleBee/Heeler/blob/main/docs/design/composer-staging-store.md) 不变量 7
- herdr 侧投递语义：`agent prompt` 尊重 bracketed-paste，提交「文本 + 编码后的 Enter」；已 Blocked 则 `agent_blocked` 且不写终端。另有 `agent send-keys` / `agent read`（含 `detection` = 「agent 屏幕检测用的 **bottom-buffer 快照**」）。
  来源：[herdr CLI reference](https://herdr.dev/docs/cli-reference/)、[herdr socket API](https://herdr.dev/docs/socket-api/)、[herdr agent automation](https://herdr.dev/docs/agent-automation/)

**这消解了什么：** Composer **从来不是** CLI 输入行。Tab 补全发生在终端画面里，草稿不受污染，所以不存在 F-087-1/2 那种「本地信念过期 → 退格发不出去」。代价是：补全/历史必须走工具键盘对着 **终端里那一行** 做，不能对着 Composer 做；Composer 与 CLI 行在 Send 之前可以长期不一致。这正好是 084 方案 B（发送才提交），已被用户否决（084 §2）。

**许可：** Heeler 仓库 LICENSE 为 AGPL-3.0（README 徽章与 [LICENSE](https://github.com/ZingerLittleBee/Heeler/blob/main/LICENSE)）。本格只引用上述 README / CHANGELOG / `docs/adr` / `docs/design` 与 herdr 文档站。实现席位禁止打开 `Sources/**`、禁止 clone、禁止 `gh api .../contents/`、禁止反编译 IPA。上游 libghostty 文档按 MIT 终端仿真器公开文档引用（[Ghostty about](https://ghostty.org/docs/about)、[Ghostty features](https://ghostty.org/docs/features)）；Heeler 选用它的公开理由见 [docs/adr/0004-libghostty-terminal.md](https://github.com/ZingerLittleBee/Heeler/blob/main/docs/adr/0004-libghostty-terminal.md)（终端引擎负责仿真/渲染/IME；应用自有两模式键盘与「控制键发原始终端序列」）。

### 1.2 手机 SSH 终端：没有独立输入框（Blink / Termius / Prompt）

公开产品形态是「整屏就是 PTY」。系统键盘的按键被编码后写入远端；屏幕即真相。不存在「本地 `已同步文本`」。

- Blink 自称专业 iOS 终端，SSH/Mosh，按键进会话。近期版本另加 **Prompt Mode**：为 AI prompt **本地起草**（语音、文本控件），写完再提交——这是在「纯终端」之上又长出一截 Composer，与 1.1 同类。
  来源：[Blink App Store 18.5.1 说明（New Prompt Mode & Snips）](https://apps.apple.com/us/app/blink-shell-build-code/id1594898306)；IME 光标问题在 18.6.x 作为缺陷修过（同页 release notes「Fixes IME cursor issues」）
- Termius 是跨平台 SSH 管理器 + 终端，不是 Agent Composer。
  来源：[Termius 站点对比综述](https://getmoshi.app/articles/blink-vs-termius)（二手综述；Termius 自家是否在 Android 上拆 Composer **查不清**）

**这消解了什么：** 方案 2 的极限形态——框就是终端。F-087-1/2 不存在。代价：CJK IME、中间改字、系统听写都要跟 PTY 抢；Blink 自己都为 IME 光标单开过修复。084 方案 A（逐键翻译中间编辑）正是因为「不知道 CLI 光标」被否决。

### 1.3 对本产品的映射（084 C + 059 不可推翻）

| 通道 | Heeler（公开行为） | 我们今天 | 087 之后必须变成 |
|---|---|---|---|
| 打字 / IME / 中间改字 | 本地 Composer，Send 才 `agent.prompt` | 本地 `TextFieldValue` + `DiffSync` 实时发键（084 C） | **保持 084 C**。框仍是本地缓冲。 |
| Esc / Tab / 方向 / Ctrl-C | 工具键盘 → PTY，**不改草稿** | `sendKey` 走 **与发送共用的 Sending 闸**，且 **不使 `syncedText` 失效** | 控制键走独立通道：**不占发送闸、不抢焦点、不打断 IME**；凡会改写远端输入行的键，事后 **光标锚定回读** 覆盖本地框与 `syncedText`。 |
| 附件 | 路径插入 **本地草稿**，不提交 | 上传成功预贴进 **CLI pane**（057），路径不进本地框 | UI 收到框内（E4）；协议仍走 057 预贴，不改成 Heeler 的「插入草稿」。 |
| 终端 | 显示面，不接受键盘 | `TermSurfaceView` 镜像 | 保持镜像。回读的数据源是 **已有 `TerminalGrid` 光标**，不是新开一条屏幕刮取 RPC。 |

我们 **没有** herdr 的 `agent.prompt`，也 **不许** 把 084/059 退回「发送才同步」。所以 1.1 的投递通道抄不了。1.1 里真正可落地的是 **通道拆分 + 控制键不污染草稿 + Blocked/补全发生在终端侧时用另一条路对齐**。对齐手段在我们这里只能是回读（方案 1），不能是「放弃实时」。

## 2. 选定方案在 F-087-1 / F-087-2 / F-087-3 上的代价

算法（实现必须按此，不许改成「最后 3 行」）：

```
打字：       084 DiffSync.plan(syncedText, current) → BackSpace×N + 后缀；组合期 hold
控制键：     发 keys 帧（不走 sendDraft 闸）
回读触发：   Tab / Esc / ↑ / ↓ / Ctrl-C 的 input_ack 之后，等下一帧终端快照
            （Left/Right 见 §2.4）
回读：       remote = extractByCursor(grid)     // 锚 = cursorY，禁止 rows-k
            日志必须带：cursorY cursorX altScreen remote_len synced_len equal 触发源
            若 remote != syncedText：
                 组合期？ → 只记日志，不覆盖（避免 IME 被远端回写打断）
                 否则 → syncedText = remote；本地 TextFieldValue 设为 remote（光标到行尾）
删除：       用户在已回读的本地框上退格 → 084 按新的 syncedText 算 → 会真的往 CLI 发 BackSpace
```

`extractByCursor`（新纯函数，禁止写死行号）：

1. 读 `TerminalGrid.cursorY` / `cursorX`（已存在于 `app/terminal/.../TerminalGrid.kt`）。alt-screen 下 Claude Code / Grok 的光标就在其输入区——这是仿真器不变量，不是行号魔法。
2. 从 `cursorY` 向上扩、向下扩，直到碰到 **边界行**：整行空白、或盒线/宽装饰字符（`─│┌┐└┘╭╮╰╯` 及反色条带若 Cell 暴露反色）、或一行可见宽度明显小于 `cols` 且不含光标。
3. 把锚点所在的连续逻辑行拼成字符串，去掉行尾空白。软折行（`pendingWrap` / 末列非空接到下一行且下一行不是边界）并进同一段。
4. 光标不在可见网格（查不清的病态）→ 返回失败而不是猜最后一行。失败时 **halt 可见**：状态区报「远端输入行无法读取」，**不许**用空串覆盖 `syncedText`（空串覆盖会把 F-087-2 再引入一次：本地以为没字，退格发 0 键）。

herdr 的 `detection` 源公开写成 bottom-buffer（[CLI reference · Read sources](https://herdr.dev/docs/cli-reference/)）。那是 **他们** 的屏幕检测快照，**不是** 我们的输入行定义。087 明文禁止写死行号，实现席位不得把 `detection` 的「从底部切 N 行」搬过来。

### 2.1 F-087-1 的代价（远端改写后两边文本不一致）

- **仍会 residual 的窗口：** ack 到下一帧快照之间（TUI 还没画完补全）。窗口内若用户继续打字，084 仍按旧 `syncedText` 算。代价 = 必须 **在回读完成前挡住 DiffSync 发出**（加 `resyncPending`：为 true 时 `onPassthroughInput` 只更新本地框、不发键；回读完成后用 `DiffSync.plan(新synced, 本地当前)` 一次补齐。补齐必须记 `backspaces` 与 `typed_len`）。
- **提取错区：** 把状态行/token 计数拼进 remote，本地框会出现垃圾。代价 = 单测必须用「光标在盒内、盒外有装饰」的夹具，断言提取结果 **不含** 装饰行。
- **查不清：** Claude Code / Grok 是否发出 OSC 133 提示符标记。Ghostty 公开 VT 能力页未给出 OSC 133 条目（[features](https://ghostty.org/docs/features) 的 VT 索引仍是 WIP；本格打开 `https://ghostty.org/docs/vt/osc/133` 为 404）。**本方案不依赖 OSC 133。** 若将来能证实 CLI 发出该序列，可作为增强边界，不是 v1 判据。
- **查不清：** 仅凭公开 README 无法证明 Heeler 在 Tab 之后会不会回读 Composer。CHANGELOG 写明控制键 **不改草稿**，因此他们 **接受** F-087-1 在 Composer 上成立，用「Composer 不是 CLI 行」消解。我们不能接受，所以才加回读。

### 2.2 F-087-2 的代价（该状态下删除而 CLI 长度不变）

- 回读成功后，084 的退格数 = `len(synced)-prefix`，prefix 对新 remote 重新算，删除会真正出门。这是本方案修 F-087-2 的路径。
- **失败模式：** 回读失败却用空串覆盖 → 本地空、CLI 有字 → 退格 0。所以失败 **禁止覆盖**。用户此时仍可能删不掉——必须让失败可见（状态区），并提供控制键 Backspace/Ctrl-C 作为逃生（Ctrl-C 已在键条）。
- **组合期：** 回读被 hold 时用户按退格，删的是 IME 组合区，084 本来就不发键（`A-df-ime`）。上屏后再发。不要为了 F-087-2 在组合期强行发 BackSpace。
- 代价数字：多一次「ack → 等快照 → 提取」的往返。必须打日志：`resync_wait_ms`、`snapshot_gen`、`trigger=Tab|Esc|Up|Down|Ctrl-C`。超时（建议 400ms，与 084 §6 的 50ms 合并窗不是一回事）仍失败可见，不静默。

### 2.3 F-087-3 的代价（破坏 084 §5 四条）

| 084 判据 | 本方案是否动它 | 代价 / 守卫 |
|---|---|---|
| `A-df-append` 纯追加退格==0、键序=逐键直通 | **不许动。** 回读只在控制键触发后发生。纯追加路径 `resyncPending==false` 且 `synced==current` 前缀满。 | 新测：回读代码存在时重跑 `DiffSyncTest` + `passthroughTypedChar_sendsOneCharText`。若回读在追加路径被误触发 → F-087-3 命中，必须回滚触发条件。 |
| `A-df-edit` 中间改字两边最终相等 | 保持 084 C。回读会把本地框整段换成 remote，光标到行尾——这是 084「同步后光标在行尾」的恢复，不是方案 A 的逐键翻译。 | 代价：回读那一帧用户正在中间编辑会被拽回行尾。可接受：控制键本就是「把焦点交给 TUI」。守卫：回读不得在 `composition != null` 时覆盖。 |
| `A-df-ime` 组合期零按键 | 回读 hold；`onPassthroughInput` 组合期继续 return。 | 代价：组合期赶上 Tab 回读，对齐推迟到上屏。日志两边都记。 |
| `A-df-latency` 英文无额外延迟 | 追加路径禁止引入 delay/post。`resyncPending` 只在控制键后为 true。 | 实现若把「每帧都回读」做成定时泵 → 直接违反静默经济 + `A-df-latency`。**禁止**对输入行做固定频率轮询。 |

方案 2 在 F-087-3 上的代价（故否决）：手机框不再是可编辑缓冲，中间改字退回 084 A（要知道 CLI 光标）或整段重打；IME 必须在本地 composition overlay 再一次性灌键——`A-df-edit` / `A-df-ime` 的现有测试语义会被推翻。E2「膨胀」也会从「TextField 变多行」变成「多映几行终端」，和 084 本地完整编辑冲突。

### 2.4 Left/Right 的额外代价（084 行尾约定）

键条 Left/Right 会把 CLI 光标移开行尾，而 084 差分 **假设光标在行尾**。这在 Tab 补全之前就已经能让后续退格打到错误位置。

裁定：Left/Right **仍发给 TUI**（方向键是 Claude 菜单/Grok 选择的刚需），但：

- 发出 Left/Right 后置 `eolUncertain=true`；
- `eolUncertain` 期间 **禁止** `DiffSync` 发退格（只允许纯追加？也不安全）。更干净：**`eolUncertain` 期间把本地框改为只读镜像**（显示回读结果），直到用户点输入框 → 发送 `Ctrl-E` 或一串 `End` **之前先回读**，再恢复 084。
- v1 最小：点输入框 = 「我要继续 084」→ 回读 → 若光标不在提取段末尾，先发 `Ctrl-A`+`Ctrl-K` **禁止**（会清行）。正确做法：发 `End` / `Ctrl-E` 把 CLI 光标拽回提取段末尾，再 `syncedText = remote`。`Ctrl-E` 在 readline 是行尾；**查不清** Claude Code alt-screen 是否把 `Ctrl-E` 当行尾还是当编辑器绑定。v1 用键条已有的 `→` 连发直到回读显示光标在提取段末单元格，并打日志 `cursorX vs line_end`。若 20 次仍不在末尾 → halt 可见，不要死循环。

## 3. E2 点击膨胀多行

现状：`DraftField`（`app/app/src/main/java/dev/agentmirror/app/ui/screens/SessionShellScreen.kt`）`singleLine = true`，高度锁死 `Dims.inputHeight = 40.dp`（`DesignTokens.kt`）。加号与发送在输入框 **外面** 同一 Row。

改什么：

1. `DesignTokens.kt`：保留 `inputHeight` 为收起高度。新增 `inputHeightExpanded`（建议 120.dp，约 5 行，不要无界）。不要改其它 token。
2. `SessionShellScreen.kt` `DraftField`：
   - 增加 `expanded: Boolean`、`onToggleExpand: () -> Unit`。
   - 收起：`singleLine = true`，高度 `inputHeight`，点击框体（不是加号/发送）→ expand。
   - 展开：`singleLine = false`，`maxLines = 5`，高度 `inputHeightExpanded`，垂直滚动；再点一次或发送成功后收起。
   - `BasicTextField` 保持 `TextFieldValue` 重载（084 前置）。
3. `SessionScreen.kt`：`var composerExpanded by remember { mutableStateOf(false) }` 传入 shell；`onSend` 里置回 `false`。
4. **不要**去改 `TermSurfaceView` 的可视行数来「显示更多镜像」——那是方案 2 的 E2，已否决。

判据：

- `A-e2-expand`：点击 `testTag("session-draft")` 后，输入框高度 ≥ `inputHeightExpanded` 的 0.9 倍，且 `singleLine` 语义上可插入 `\n`（`onValueChange` 收到的 text 可含换行；换行 **仍走 084 差分**，不发 Enter——Enter 只属于发送键。现有 `passthroughMultiline_typesEachLineDelta` 必须仍绿）。
- `A-e2-collapse-on-send`：发送后高度回到 `inputHeight`。
- `A-087-nore`：上述过程纯追加时退格数仍为 0。

## 4. E3 按键条与打字并存（不能互相打断）

现状的两处互相打断（实现必须改，不是「看起来已经并存」）：

1. **发送闸抢用：** `SessionViewModel.sendKey` 在 `inputStatus is Sending` 时直接 return；成功则把 `inputStatus = Sending`。`SessionScreen` 的 `sendEnabled = viewModel.inputStatus !is Sending`。点 Tab 会让发送键和（若仍有旧 `KeyBar`）整条键条进入 Sending，打字虽走 `onPassthroughInput` 不占闸，但 **下一次 Tab 会被吞掉**，发送键也会灰。单测 `sendKeyEmitsKeysFrameWithoutText` 现在 **断言** `inputStatus == Sending`——实现时这条要改语义，不要假装没看见。
2. **焦点：** `SessionShellScreen` 的 `KeyCap` 是 `clickable` 的 `Box`。默认可聚焦。点 Esc 可能让 `BasicTextField` 失焦 → IME 收起 → 「打字被打断」。

改什么：

1. `SessionViewModel.kt`
   - `sendKey` **不再**写入 `InputStatus.Sending`。控制键回执用独立字段（例如 `controlKeyStatus`），失败仍要可见（003），但 **不得** 让 `sendDraft` 的闸变红、不得让 `sendEnabled` 变 false。
   - `sendKey` **不得** `if (inputStatus is Sending) return`。发送在途时仍应能按 Ctrl-C / Esc。
   - 在 `Tab/Esc/Up/Down/Ctrl-C` 的 ack 后置 `resyncPending`，走 §2 回读。`Left/Right` 走 §2.4。
   - `onPassthroughInput`：`resyncPending` 时不调用 `applyDiffSync`；回读结束再一次 `applyDiffSync`。
2. `SessionShellScreen.kt` `KeyCap` / `ArrowKeyCap`：`Modifier.focusProperties { canFocus = false }`（或等价「不可获焦」），保证点键条 **不** 抢 `session-draft` 焦点、不收 IME。
3. `SessionScreen.kt`：不要把键条 `enabled` 绑到 `Sending`。旧 `KeyBar` composable（同文件底部）若已不被 `SessionShellScreen` 调用，**不要顺手删**（本格禁顺手）；新行为以 shell 的键帽为准。
4. 公开对标：Heeler 工具键盘与系统键盘切换时 **保持同一测量高度**，避免 Composer/终端网格跟着跳（[CHANGELOG 0.1.0 #182](https://github.com/ZingerLittleBee/Heeler/blob/main/CHANGELOG.md)）。Android 上我们 **不** 做「用工具键盘替换 IME」——键条已经画在 IME **上方**。E3 的并存 = IME 保持升起 + 键条可点。不要引入「切到键条就 hide IME」。

判据：

- `A-e3-no-gate`：`sendDraft()` 进入 Sending 后立刻 `sendKey(TAB)` → 必须发出 keys 帧（今天会被闸吞掉，这是先验红）。
- `A-e3-focus`：Compose 测试：draft 聚焦后 click Esc 键帽，`session-draft` 仍 focused（或 IME 仍可见——Robolectric 若测不了 IME，至少断言 focus）。
- `A-e3-ime`：`onPassthroughInput` 组合期中点 Tab：组合期仍 0 键；Tab 的 keys 帧仍发出；回读等上屏后再覆盖。日志含 `composing=true trigger=Tab → hold overlay`。
- `A-087-tab` / `A-087-esc` / `A-087-del`：见契约 087 §5。CLI 侧文本用测试夹具的假终端网格填 cursor 行，**不要**只断言手机框。

## 5. E4 附件与发送收进框内

现状：`ConsoleBar` 里 `PlusButton` | `DraftField` | `SendButton` 三列，加号和发送在圆角输入框 **外面**。附件菜单是 `SessionScreen` 里叠在左下的 `DropdownMenu`，不在框内。

改什么：

1. `SessionShellScreen.kt` `DraftField` 扩成「输入表面」：同一个 `clip(RoundedCornerShape(Radii.input))` + `background(p.inputBackground)` 的容器 **内部** 放：
   - 左：加号（现 `PlusButton` 尺寸可略缩到 32.dp，不要另做一套视觉语言）
   - 中：`❯` + `BasicTextField`（展开时这块变高）
   - 右：发送 `↑`
   - 若 `pendingAttachmentPaths` 非空：在文本上方或左侧显示一枚路径芯片（只读，点 × 不在 v1 除非已有删除 API——**查不清** 现有 VM 是否支持撤一张预贴；没有就不要编）。芯片 **不是** 把路径写进 `TextFieldValue`（057：路径贴 CLI pane，不掺进逐键文字）。
2. `ConsoleBar` 的外层 Row 不再并排加号/发送。键条仍在输入表面 **上方**、同一 `consoleBackground` 块里（已经是一块，保持）。
3. `SessionShellScreen` 需要 `pendingAttachmentCount` 或芯片文案参数；`SessionScreen` 从 `viewModel.pendingAttachmentPaths` 传入。
4. 上传成功仍走现有 `uploadAttachment` → 预贴 CLI。不要改成「插入本地草稿等发送」——那是 Heeler Composer 语义，和 057/059 冲突。
5. 加号菜单：放到加号锚点的 `DropdownMenu`（拍照 / 相册），不要再用屏幕左下绝对坐标那份（可把 `SessionScreen` 里那份菜单改成由 shell 回调；旧 `AttachmentButton` 若未被调用，不顺手删）。

判据：

- `A-e4-inside`：UI 测试，`session-draft` 的父节点 bounds 包含加号与发送（`getUnclippedBoundsInRoot`，发送中心 x 落在输入表面右缘内）。先验红：今天发送在 DraftField **外面**，这条必须先红。
- `A-e4-no-submit-on-attach`：选图只触发上传+预贴，不调用 `sendDraft`，本地 `TextFieldValue` 不被改写成路径。
- 上传失败仍走 `UploadStatus.Failed` 可见（现有行为，回归）。

## 6. E5 观感对标（user gate，单测绿不算）

对标的是 **公开截图与 CHANGELOG 描述的布局结构**，不是像素抄 AGPL 实现。实现席位用我们已有的 `LocalAppPalette` / `Dims` / `Radii`，不要新建一套主题。

公开截图：[composer-iphone.png](https://github.com/ZingerLittleBee/Heeler/blob/main/docs/images/composer-iphone.png)、[agent-iphone.png](https://github.com/ZingerLittleBee/Heeler/blob/main/docs/images/agent-iphone.png)（README Screenshots 表）。结构摘要（来自 README + CHANGELOG 0.1.0 #182，不是源码）：

- 终端占详情页几乎全高；Composer 贴底。
- 输入是一条圆角起草区；加号在发送左侧、同属 Composer。
- 系统键盘升起时，键条/工具面在键盘之上；切换工具键盘不改变 Composer 高度、不让终端网格抖动。
- 点终端正文 **不会** 切键盘（CHANGELOG：「Tapping the terminal body no longer toggles the software keyboard」）。

我们对应的改动（均在已列文件内）：

1. E2 展开 + E4 收进框内完成「一条 Composer」。
2. 终端 `AndroidView` 继续 `fillMaxSize`；不要为了「像」去加第二套标题栏。
3. 点终端 **不要** 抢 draft 焦点、不要 hide/show IME。若 `TermSurfaceView` 会 requestFocus，在 `SessionScreen` 的 `AndroidView` factory 里关掉（`isFocusable = false` / `isFocusableInTouchMode = false`），滚动手势保持。**查不清** 当前 `TermSurfaceView` 是否可获焦——实现席位先 `adb dumpsys` 或 Compose focus 测一下，改之前用日志证明「点终端 → draft 失焦」是否发生；没发生就不要改 SurfaceView。
4. 深浅两主题各截一帧（`emulator-manual-test` skill）。user gate 看：圆角一体框、加号/发送在框内、展开多行、键条与 IME 同时在。

判据：`A-087-ui` 按契约 087 §5，真机/模拟器截图，不是单测。

## 8. 明确不做什么

- 不引入 `agent.prompt`、不依赖 herdr、不把 Send 改回整段注入（059 仍是裸 Enter）。
- 不把手机框改成终端镜像的可滚动裁切（方案 2）。
- 不写死「最后 3 行 / 底部 25%」为输入行。Heeler CHANGELOG 里「bottom quarter of the screen」是 **点按唤起键盘的命中带**（#95），不是输入行提取；不要张冠李戴。
- 不读 Heeler `Sources/**`，不把 ADR 里的 Swift 类型名抄进 Kotlin。
- 不对输入行做固定频率轮询。
- 不在本格改产品代码（本文件只出思路）。
