# 判据基底摘要：会话列表刷新模型（进入即刷 / 下拉刷 / 零周期）

> 本文档是**零知识对照席（r.control）唯一允许阅读的判据文档**。
> 你什么都不带地来，你读它，然后做定点变异，验判据会不会真的红。
> 本文档自洽、自足、无内部引用——所有判据都是可重跑命令 + 期望退出码，不靠任何外部文档。
> 起草：r.advisor（t.refresh-oracle，2026-08-15）。

## 0. 你要验收的东西（一句话）

判据 = **一条命令**：`bash .team/nodes/refresh-oracle/run-probe.sh`。

- 被测对象（刷新模型源码）**对** → 命令退出码 **0**。
- 被测对象**坏** → 命令退出码 **非 0**。
- 你能用「定点变异」验证它：把源码改坏一处，命令必须从 0 转非 0。转不动，判据无效。

## 1. 被测对象在哪个文件，判据怎么知道它「对」还是「坏」

被测对象 = App 端会话列表刷新触发链路，落在
`app/app/src/main/java/dev/agentmirror/app/workspace/`（Compose 屏 + ViewModel 包）。

判据命令 `run-probe.sh` 对这个目录的 **.kt 源码**做**结构检查**（grep 判据，见 §2 三条），
全 PASS 退出 0，任一 FAIL 退出 1。判据只看**结构有没有**，不看运行结果、不启动模拟器、
不碰生产 daemon、不连任何网络——是纯静态、可重跑、秒级出结果的检查。

## 2. 判据规范：判什么、每个输入要产生什么输出

产品要的是三条不变量（用户 2026-08-15 原话，转录在 docs/rulings 同名文件第四节「刷新模型」）：

> 就外部的第一级就是 Tmux Socket。我希望**每次到一级的时候，它自动的刷一遍，拉最新的**。
> 此外，**我手指向下滑，它手动刷一遍，并且没有周期性自动刷新**。
> 同理，我点开一个工作目录，到了第二级，它是会话的列表。**第一次到的时候刷新，往下拉、往下滑，手动刷新一次，没有周期性刷新。**

| ID | 判据 | 机械检查 | 必须输出 |
|---|---|---|---|
| R1 | **进入即刷**：进入一级（工作区列表）/ 二级（会话列表）都必须触发一次全量列表刷新 | workspace 包 .kt 里存在对 `list()` 的调用（触发 `ConnectionManager.list()` → 服务端 ListFrame 全量重拉） | **PASS** |
| R2 | **下拉手动刷**：手指下滑要触发一次刷新 | workspace 包 .kt 里存在下拉刷新入口（`pullRefresh` / `PullToRefresh` / `onRefresh`）**且**与 `list()` 调用共存 | **PASS** |
| R3 | **零周期性自动刷新**：没有周期性自动刷新（这条是**禁令**，不是"频率低一点"） | workspace 包 .kt 里**没有**周期结构（`while(true)` 重复拉取 / `scheduleAtFixedRate` / `scheduleWithFixedDelay` / `Timer(` / 协程固定延迟循环） | **PASS** |

## 3. 判据自检（每一条）——如果被测对象是坏的，命令会不会仍返回 0？

- **删掉进入/下拉的 list() 触发** → R1 或 R2 FAIL → 命令转非 0 → 判据响。
- **加了 `while(true)` 周期刷新** → R3 FAIL → 命令转非 0 → 判据响。
- **grep 模式本身写错（漏了该抓的结构）** → 对应判据对坏代码仍 PASS → 命令仍 0 → **判据无效，
  报告 refuses**。这就是你要用定点变异抓的东西。

## 4. 为什么判据这么写（不是随便抓三个字符串）

判据落在**结构三态**上，不落在字符/数字上，三态正好卡住用户三句话：

1. **「每次到一级的时候自动刷一遍」** → 必须有一条**导航/进入路径**发出 `list()`。当前
   被测对象缺这条：`ConnectionManager.list()` 在主源码里**零调用点**——这就是用户实测
   「所有界面都不刷新」的代码侧根因。
2. **「手指向下滑手动刷一遍」** → 必须有一个**下拉手势**绑定 `list()`。缺这个，用户连
   手动刷的手段都没有。
3. **「没有周期性自动刷新」** → 必须**没有周期结构**。这条是禁令，`while(true)` 重复
   拉列表、定时器周期 list 都算违反。

判据只要求**有进入/下拉刷新、无周期刷新**，不指定刷新用什么动画、下拉用什么第三方库——
实现自由度留给开发席，判据只管「那段行为在不在」。

## 5. 边界（判据命令不碰的东西）

- **只扫 workspace 包**。会话页（session 包）有一个 `while(true)` 是**本地视口信号泵**
  （`syncFromPresenter`：滚动到顶按页补历史），它不是列表刷新、不适用本判据——R3 的 grep
  明确限定在 `workspace/` 目录，不会误伤 session 包。
- **只做静态结构检查**：不启动模拟器、不跑 gradle、不连服务端、不碰生产 daemon 与用户
  tmux（全部在本机隔离的 grep 进程里判定）。
- **判据命令只读**被测源码，不写任何文件（红测日志由 r.advisor 单独落盘）。

## 6. 你的任务：定点变异（验判据真的会红）

拿到本文档后，只读它 + 执行判据命令。步骤：

1. **基线**：跑 `bash .team/nodes/refresh-oracle/run-probe.sh`，记录退出码。
   - live 当前**无刷新模型**（R1/R2 红、R3 绿）→ 基线应**非 0**（探针红）。
   - 刷新模型实现完成、判据被满足后 → 基线应 **0**。
2. **变异**：在 `app/app/src/main/java/dev/agentmirror/app/workspace/` 里**改坏一处**——
   制造一个本文档声称该被抓到的倒退。两种变异性（任选其一）：
   - **删刷新型**：把进入/下拉触发 `list()` 的调用删掉（或把 `onRefresh` 回调改成空体），
     制造「进入不刷新」→ R1/R2 必须 FAIL。
   - **加周期型**：在 workspace 包某文件加一行 `while (true) { }`（或 `Timer(`）→ R3 必须 FAIL。
   改一个字符/加一行即可。
3. **重跑**：`bash .team/nodes/refresh-oracle/run-probe.sh`，记录变异后退出码。
   - 基线 0 → 变异必须转**非 0**；基线已非 0 → 变异必须**仍非 0 且理由成立**（FAIL 项变化）。
   - 判不出差异 ⇒ 判据无效，报告 **refuses**。
4. 把基线退出码 vs 变异后退出码、变异点写进 `.team/nodes/refresh-control/mutation-report.md`。

**判据有效（supports）** ⇔ 基线绿且变异红，且你亲手能复现。判据无效（refuses）⇔ 判不出差异。
