## 选定

**主方法：`pane_title` + 契约 062 探测器表（与 Go `classifyPaneTitle` 共用 `tools/nodeprobe/fixtures/titles.tsv`）。**

| 对照 | 观测 | 判定 |
| --- | --- | --- |
| 正控 advisor | 标题 `⠋ - … - grok`（`⠋`=U+280B 盲文） | 062 Grok 探测器 → working |
| 反控 control / dev-app / dev-server | 无前导符号、以 ` - grok` 结尾 | → idle |
| 反控 leader 窗 `claude_code`（同 socket，只读 list） | 标题 `✳ 保留V5…`（U+2733） | Claude 探测器 → idle |

两头都过。恒返回 working 的尺子会栽在反控上。

`unknown` 只留给「有前导符号且无探测器认领」，证据必须带码点 + 完整原始标题。**不许把判不出回落成 idle。**

`provider`：标题能认（Grok 标记 / Claude 符号）就写 `grok` / `claude_code`；认不出写 `unknown`，不许猜。

辅助量（只进 `evidence`，**不得推翻**标题的 working，也不得把 unknown 改成 idle）：

- `pane_tty` 上 `comm` 列表（basename）：补 provider 线索（`grok` / `claude`）。**不要**从 `pane_pid` 做 `pgrep -P`——本实验 advisor 的 grok 不在 pane_pid 子树里，会假死。
- 短间隔 capture 哈希：画面在变可作旁证。隔离正控 CHANGED、反控 same；advisor CHANGED、空闲席 same。

## 逐项结果

### 0. team-agent `worker_state` / `last_output_at`（对照，已证伪）

| 对照 | 结果 |
| --- | --- |
| 正控 advisor 正在跑命令 | `PROBABLY_IDLE`，`last_output_at` 冻在更早时刻 |
| 反控 其它 grok 席 | 也是 `PROBABLY_IDLE`（与正控不可分） |

**弃用。** 与契约 063 / F-04 一致。只有正控不够：它连正控都过不了。

### 1. `pane_title` 前导符号 + 062 表 — **采用**

优点：厂商为给人看而维护；与 062 / Go 探测器同一套语义；不碰进程、无 argv 风险。

弱点：每接一个 CLI 要加探测器 + 语料行。这是可维护的，前提是 unknown 带码点。

正控 / 反控见上，通过。

### 2. pane 内容哈希短间隔变化

隔离：idle `sleep` hash 不变；work `printf` 循环 CHANGED。  
本 socket：advisor CHANGED；control/dev-app/dev-server/claude_code same。

| 对照 | 本方法 |
| --- | --- |
| 正控 | 过（advisor 变了） |
| 反控 | 过（空闲不变） |

弱点（契约已点名，本实验未反驳）：转圈动画会变（假 working）；卡在「等网、画面不动」的真 working 会假 idle。  
**不单独采用。** 可作 evidence。

### 3. 进程树 CPU 增量

必须用 `ps -t $pane_tty -o pid=,comm=,%cpu=,time=`，不能 `pgrep -P $pane_pid`（advisor 会只看到 `sh`，漏掉 `%cpu=7.2` 的 grok）。

| 对照 | 本方法 |
| --- | --- |
| 正控 advisor tty 上 grok `%cpu=7.2` | 过 |
| 反控 空闲席 grok `%cpu=0.0`，time 不涨 | 过 |
| 已知弱点 | 等网络时 CPU=0，正是工作态（契约已写；标题此时仍有盲文） |

**不单独采用。**

### 4. CLI 会话文件 mtime

`~/.grok/sessions` 下本工作区文件 age≈0.1s（有人在写），与 advisor 正控同向。  
**不能按 pane 拆开**，路径是 provider 私货，且 macOS `find -newermt` 已证伪（F-05）。  
**不采用**为节点级主尺。

### 5. tmux `pane_in_mode` / `alternate_on` / `window_activity_flag`

全员 `pane_in_mode=0`、`alternate_on=1`、`window_activity_flag=0`（含正在干活的 advisor）。  
`pane_current_command` 全是 `bash`/`sh`。  
**正控失败。弃用。**

### 6. 补：`pane_tty` + 只读 `comm`（不是判活主尺）

用来认 provider、找该量 CPU 的进程。macOS 上 `comm` 可能是可执行路径，只用 basename，仍不是 argv。

### 7. 补：隔离合成负载

自建短路径 socket（`unset TMUX`，`-S` 后 `list-sessions` 自检），不碰用户 default、不在 team socket 上 `new-window`。  
证明哈希/CPU 在「真在吐字 / 真在睡」上能分开；不能替代标题尺去覆盖「等网的 TUI」。

## 实现约束（给 t.impl）

1. 状态只来自 062 规则扫 `#{pane_title}`；语料 `tools/nodeprobe/fixtures/titles.tsv` 逐行全过（Go 与 Rust 同一份）。
2. unknown 必须带 `codepoint` + 原始标题；禁止回落 idle。
3. 源码不得出现读 `/proc/*/cmdline`、`KERN_PROCARGS`、`pgrep -f`、`ps -o args` / `command`。
4. 只读：不 attach、不 `send-keys`、不改 pane。
5. 不在 tmux 下的节点：标 unknown，不在范围。
