# 任务书 · t.instrperf · 第 0 步的性能回测（打点有没有让「打开会话」变慢）

## 背景

第 0 步给 app 加了 93 行 PerfTrace 打点（`key_send` / `key_echo`），**只加仪表、零行为改动**
（已并线，见 `.team/nodes/t.instr/说明.md`）。

用户的硬要求是「**每一个步骤都要有性能基线的回测**」。第 0 步是一步 ⇒ 这一格补它的回测。
**加在热路径上的仪表也是代码**，不能因为「只是打点」就免检。

## 要证明什么

**B（带打点的包）相对同批 A（打点之前的包）在「打开会话」链上没有慢超过 10%。**

## 已定的方法（⛔ 这几条是裁定）

1. **同一台机器、同一时段、A,B,A,B 交替测。**
   ⛔ 不许拿今天的数跟存档基线比。**证据**：2026-08-22 实测同一个 A 包在两批之间
   自己从 p50 142.0 漂到 165.5（+16.5%），**机器漂移量大于要检测的效应**。
2. **A 包 = 打点之前的 commit 构建出来的包。**
   取法：`git archive` / `git worktree` 到 `input/instr-v1` 的**父提交**，在那棵树上构建。
   ⛔ 不许拿 `.team/perf/` 里任何存档 APK 顶替——包内容不同就不是对照。
3. **两个包的 md5 必须不同**，相同说明构建错了（判据会当场判不可判）。
4. **取数沿用 `tools/perfbase/coldopen.sh`**（`adb logcat -s PerfTrace`），
   段取 `first_draw` 与 `layout_settled`，每组每夹具 **n ≥ 10**。
5. ⚠️ **输出目录必须是你自己的**。`coldopen.sh` 的默认 OUTDIR 是 `.team/perf/raw/`，
   2026-08-22 曾因此**把基线原始证据覆盖掉**。⛔ 不许写进 `.team/perf/raw/`。

## ⚠️ 必须写进说明里的一句实话

现噪声底约 **±10%~16%**。这一轮真正能证明的是「**没退超过噪声**」，
