```
## 缺陷现象
图片上传永远失败，HTTP 401。`fix-upload-bearer` 已加 Bearer 头，
但**运行时 token 传递链路断裂**（头加了、token 没传进去）。

## 修复方向
图片上传请求必须带上运行时可用的认证 token，修复 Bearer 传递链路。

## 关联
[[003]] 附加输入能力（图片 = 手机上传 → 主机落盘 → 文件路径注入 CLI 输入；
本条是这条能力链路的实现缺陷）。
```

**注意**：需求已把根因方向裁定为「传递链路断裂」而非「没加头」。
`fix-upload-bearer` 那一轮加头的工作是对的，缺的是 token 实际流到那里。

## 命中二：母能力 raw/003 附加输入能力

图片链路的完整语义：**手机上传 → 主机落盘 → 文件路径注入 CLI 输入框**。
即上传成功后应把主机侧文件路径注入到输入框光标处。

**与 D-30 的边界**：D-30「上传填输入框」已修并已提交
（upload 不触碰 textFieldValue 的那条约束）。修 D-22 时不得破坏 D-30 的已修状态。

  只允许打印「是否为空 / 长度 / 来源」这类不泄露内容的判据。
- 证据文件、report_result 正文、截图一律不得出现 token 值。
