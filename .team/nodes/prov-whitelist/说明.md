# t.prov · 白名单认出 `pi` 与 `cursor`

## cursor 识别办法及理由

**办法**：共用 TSV 给 `cursor-agent` 行加上第 4 列 `path-segment`。匹配仍只读 comm（`ps -axo pid=,ppid=,comm=`），先按 basename；basename 未命中时，若 comm 完整路径含 `/<comm-basename>/` 这一目录段，则命中该行。

实测 comm：

`/Users/alauda/.local/share/cursor-agent/versions/2026.08.11-e8db854/node`

basename 是 `node`，旧逻辑永远对不上表里的 `cursor-agent`。路径里有 `/cursor-agent/`，path-segment 命中 provider=`cursor`。

**不选其它候选的理由**：

- 068 §2 实测 Cursor 不设 pane 标题（= 主机名），§8 的 identity-first 是「身份已由 comm 确定之后」的状态回落，不能用来认出 cursor。
- ⛔ 不把裸 `node` 写进 TSV：会把所有 node 系 CLI 认成 cursor。
- ⛔ 不读 argv（凭据红线）。
- 不加硬编码 `/cursor-agent/` 字面量：规则写在共用 TSV，Go / Rust 读同一张表（表头 `Do not fork this table`）。`pi` 只走 basename，不加 path-segment，避免 `/home/pi/...` 误伤。

`pi` 一行：`pi → pi → Pi`，基名直接命中。

`intern_expect` 增加 `pi`，否则 nodeprobe 把已识别的 pi 输出成 `provider=unknown`。
