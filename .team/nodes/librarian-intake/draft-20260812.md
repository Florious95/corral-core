## 缺陷（用户真机实证，必修）

### D-20 键盘弹出时终端内容被遮挡
用户原话：「我呼出输入框之后，它把整个 UI 给挡住了。它应该是往上顶…但是它不会让整个 UI 去重绘」「每多说一句话，整个界面都会重绘。重绘的结局那就是整个界面的变化、闪烁以及扭曲」
裁定行为：键盘弹出时**终端 rows/cols 不变**（不触发 tmux resize），但**视口要上推**（像聊天软件一样，内容区平移露出当前内容）。当前实现是锁死不动，内容被键盘遮挡。
规则（用户裁定）：「仅在第一次进入 CLI 时重排一次，此后都不再重绘」

### D-21 退出会话不恢复终端原始尺寸
用户截图实证：退出会话后 tmux 窗口仍为手机的小尺寸，电脑上看到的终端被压缩。
裁定行为：退出会话页时 resize 回主机终端的全尺寸。

### D-22 图片上传永远失败（HTTP 401）
必现。fix-upload-bearer 加了 Bearer 头但运行时 token 传递链路断裂。

### D-23 侧滑返回直接退出 App
安卓手势导航（从屏幕边缘向内滑）直接退回桌面，应该是返回上一级页面。
Android predictive back / edge gesture 处理缺失。

### D-24 会话别名（window name）未生效
scan.go 已改用 #{window_name}，但生产 daemon 是旧二进制未重编，App 上看不到变化。

### D-25 App 内 Tailscale auth key 填写后无法入网
用户实测：必须在外部（小火箭）先连通 TS 才能用 App。App 内置的 TS 入网流程不工作。

### W-04 回炉的工程原理（用户 2026-08-12 阐述）
回炉不只是流程，背后有工程原理：
1. 问题没解决却上了线 = 对应代码本身有问题
2. agent 上下文有限，项目越大理解代码越耗上下文，视角受限 → 加代码比删改代码更安全（agent 倾向加而不是改）
3. 腐败代码越堆越多形成正反馈循环——坏代码吸引更多坏代码
4. 回炉首先删除问题代码，打断腐败堆叠的正反馈循环

核心洞察：回炉的价值不只是"重做"，而是**先删再做**——删除本身就是治疗。
