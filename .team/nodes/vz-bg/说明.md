## 1. 颜色类型定案（不许猜，先抓字节）

### Claude Code → **256 色索引 `48;5;254`**（能重映射）

| 证据 | 内容 |
|---|---|
| 既有 recap 夹具 | `TermBgCjkAlignTest` / `TermThemeTest` 用真实字节 `ESC[48;5;254;38;5;16m` |
| CLI 二进制 | `claude.exe` 命中 `48;5;254`、`48;5;236`、`userMessageBackground`；`48;2` 仅 1 处且落在 debug 类型串，**不是真彩 UI** |
| 用户截图 `11-浅色下框线断点与logo黑底.jpg` | 浅色外壳上，「我发的消息」仍是一块**更浅的白条** |

结论：用户消息块是 **ANSI 256 索引 254**（暗主题下同源还有 236）。  
旧路径只把 254 写进 `xterm256[]`；浅底上若 CLI 再发近白（231/255 或真彩白）会原样画出纯白。  
本格：254 / 近白索引 / 近白真彩 → `TerminalPalette.userBlockBackground`（浅 `E6F5F2`，比纸色 `F7F8FB` 深）。

### grok → **整屏按「终端黑」发：索引 0 / 16，并具备真彩能力**

| 证据 | 内容 |
|---|---|
| 用户追加 + 截图意图 | 「不再是黑底」但「灰底不是纯白」——灰 = 浅色 `ansi[0] = #E7EAF0`（暗格），不是纸色 `#F7F8FB` |
| 设计注释 | `TerminalPaletteLight.ansi[0]` 写明「浅底上作为暗格用」，**给局部色块，不是整屏** |
| 隔离 tmux | socket `/tmp/e2e-vz-bg/tmux.sock` 自检 `probe:` 在该 socket 上。`grok` 启动 splash 的 `capture-pane -e` 只有 `SGR 0/1/2`（默认色），**没有** `48;2`。grok 二进制含 `truecolor` / `SetBackgroundColor` / doctor 要求 `terminal-features *:RGB` |
| 故双路径 | ① `40` / `48;5;0` / `48;5;16` → **纸色 `background`**，⛔ 不走 ansi[0]；② 真彩近黑 `48;2;r;g;b` luma≤32 → 同一纸色（亮度守卫，真彩翻不了索引表） |

隔离 splash 没抓到 40m，不能声称「grok 会话 UI 一定发 40m」。按用户「灰=暗格」现象 + 索引 0 映射表，**整屏黑按 index 0/16 + 近黑真彩**处理；局部仍用 ansi[8] 等。

## 2. 修法

色值仍只在 `TerminalSpec.kt`。重映射入口 `TermPalette.colorFor`（绘制层 `TermSurfaceView.colorFor` 只转调）：

| 输入（背景） | 浅色落点 | 深色落点 |
|---|---|---|
| Default | `background` `F7F8FB` | `0A1120` |
| Indexed 0 / 16（整屏黑） | **`background`** 不是 `E7EAF0` | `background` |
| Indexed 254 / 231 / 253 / 255 | `userBlockBackground` `E6F5F2` | `10241F` |
| Rgb luma≤32 | `background` | `background` |
| Rgb 近白（chroma≤8 且 luma≥220） | `userBlockBackground` | `userBlockBackground` |
| Rgb 亮且有色相 | 通道缩到 userBlock 亮度（保色相） | userBlock |
| Indexed 8 等局部 | 仍走 ansi[8] 暗格，**不等于纸色** | ansi[8] |

前景不把黑抬成纸色（否则字消失）。反显仍走 `resolvedBg/Fg` 换旗标，不改 SGR 7 语义。

`publishThemeChrome` 在 token 变化时记 `term-bg-remap`：`defaultBg` / `ansi0` / `userBlock` 原值 + luma + `paper_ne_ansi0`。
