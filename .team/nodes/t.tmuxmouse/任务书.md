# 任务书 · t.tmuxmouse · tmux 的 `mouse` 开关到底影不影响我们的注入路径

## 一、为什么有这一格（⛔ 先读，它决定你的态度）

`docs/输入透传契约.md` §1 写着一条**推论**：

> 外层 tmux 的 `mouse` 必须关掉，否则点击被 tmux 自己吃掉去切窗格，永远到不了内层 Agent。

**leader 已经按这条建议告诉了用户「去关 tmux mouse」，但 ⛔ 从没验证过它。**

**现在怀疑它是错的**，理由：

- tmux 的 `mouse` 开关管的是 **tmux 自己那个 attach 终端收到的鼠标事件**怎么处理
  （切窗格 / 进 copy-mode / 转发给应用）。
- 而**我方不是以终端身份 attach 在 tmux 上**——我方是把 SGR 字节经
  `send-keys`（第 1 步 `server/internal/bridge/inject_raw.go`：可打印 `-l`、控制 `-H`）
  **直接注进 pane 的 pty**。那条路径**可能根本不经过 tmux 的鼠标处理**。
- **更要命的反向可能**：`mouse off` 时 tmux 不在外层终端开启鼠标上报，
  于是内层 app 反而更收不到——**如果注入路径受它影响的话**。

**这一格就是把这件事测死。** 结论无论哪个方向都是合法结果；
⛔ **不许为了让契约那句话成立而把实验做成想要的样子**。

## 二、已知事实（leader 只读查过用户真实 tmux，⛔ 不必重查）

用户那台主机上跑 Claude Code 的 pane：`std=0 btn=1或0 all=1或0 sgr=1`
⇒ **内层 app 确实开了鼠标上报，用的是 SGR 1006 + 1002 或 1003。**
（tmux format：`mouse_standard_flag`/`mouse_button_flag`/`mouse_all_flag`/`mouse_sgr_flag`）

## 三、实验（⛔ 全在隔离 tmux 里做）

起隔离 tmux（⛔ 不碰用户真实 tmux、⛔ 不碰生产 `:9900`），
`mkdir -p /tmp/e2e-tmxm`（短路径且预建）→ `unset TMUX` → 建会话 →
**`list-sessions` 自检**（建 socket 失败会静默回退到用户真实 socket）。

**被测对象**：一个**会开鼠标上报并把收到的字节原样吐出来**的 sink。
建议做法：一个小脚本，先输出 `\e[?1002h\e[?1006h`（或 1003），然后 `cat -v` 读 stdin。
⚠️ 用 `cat -v` 能把控制字节可见化，便于逐字节断言。
**sink 怎么做由你定，但必须：① 真的开了模式（用 tmux format 核 `mouse_sgr_flag` 等）
② 能把收到的字节原样呈现。**

**变量**：隔离 tmux 的 `mouse` 设为 **on** 与 **off** 两档。

**动作**：用与第 1 步**同一条路径**注入一串 SGR 1006 鼠标序列
（例如左键按下于第 3 行第 5 列 = `\e[<0;5;3M`，抬起 `\e[<0;5;3m`）。
⚠️ **必须走 `send-keys`**（可打印 `-l` / 控制 `-H`），
⛔ 不许直接写 pty 绕过 tmux——那就不是我方的真实路径了。

**每档重复 ≥10 次**，断言 sink **有没有原样收到那串字节**。

## 四、必须回答的三个问题

1. **`mouse on` 时，注入的 SGR 字节能不能到达内层 app？**
2. **`mouse off` 时，能不能到达？**
3. **两者有没有差别？** 若无差别 ⇒ **契约 §1 那条推论对我方注入路径不成立**，
   leader 给用户的建议要撤回。

⚠️ 顺带核一件事（若能顺手做）：`mouse on` 时 tmux 会不会**同时**把注入的序列
当成自己的鼠标事件去切窗格 / 进 copy-mode（即「双重生效」）。
若会，那是另一种坑，照实报。
