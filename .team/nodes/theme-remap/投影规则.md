**角色**：思路席。本文件是实现席改 `TermPalette.colorFor` 的施工说明书。
**写于**：2026-08-20。仓根 `/Volumes/nvme/Projects/远程Agent安卓`。
**不许做的**：改 `app/`（本格只出方案）；跑 `gradlew`；重新设计 `t.plan` 的主题清单 / 设置页 / 许可边界。

用户 2026-08-20 的语义（契约 §1.5，压过旧理解）：终端是一层**重新着色**。CLI 发 ANSI 16、256 索引、24 位真彩都不作数，**画到屏幕上的颜色必须落在选中主题的色板上**。用户选 Dracula 就该看见 Dracula。

`t.plan` §3.2 写过「主题库只改 Scheme 从哪来，不改 `colorFor` 的分支表」——那条是给 **`t.wire`（换数据源）** 的。本格被 085 §1.5 单开，专门规定 **256 / 真彩漏出分支怎么收进色板**。实现席落地投影时**可以也必须**改 `colorFor` 的 16–255 与 `Rgb` 漏出路径；**不许改** 083 三条触发条件（见 §5）。

---

## 0. 实现席一句话怎么做

在 `TermPalette.colorFor` 里，083 特例命中则仍返回纸色 / `userBlockBg`；`Default` 与 `Indexed(0..15)` 仍是主题槽的恒等。其余 **256 立方/灰阶** 与 **24 位真彩** 先还原成 sRGB，再按 §1 投到「当前 Scheme 的候选槽」，必要时按 §3 做前景对比度修补。输出 ARGB **必须等于某个槽的字面量**（容差 0），禁止 `scaleLuma` 再造一个不在色板上的中间色。

漏斗仍是唯一入口：`TermSurfaceView.colorFor` → `TermPalette.colorFor`。禁止在绘制层另开一套。

## 1. 投影规则本体

### 1.1 色板（闭合集合）

主题 X 的**单元格渲染色板**记作 `R(X)`：

```
R(X) = { defaultBg, defaultFg }
     ∪ { ansi16[0] … ansi16[15] }
     ∪ { userBlockBg }
```

- `userBlockBg` **不是** iTerm 主题字段，是 083 §2 的 APP 灰底（`t.plan` §3.1：不归主题库）。它必须进 `R(X)`，否则 254 用户块判据与 085「⊆ 色板」互相打架。
- `cursor` / `selection` **不进** `colorFor` 的投影候选，也不进 §6 的单元格颜色集合（光标与选区是外壳叠层，不是 SGR）。
- 实现席拼 Scheme 时（`t.wire`）：`defaultBg/Fg/ansi16` 来自当前槽的上游文件；`userBlockBg` 仍按 `dark` 取 APP 值。

### 1.2 选定：OKLab 欧氏距离 + 色度分闸

**选定**：把 sRGB 8-bit 三元组转成 **OKLab** `(L, a, b)`，距离

```
d² = (L1-L2)² + (a1-a2)² + (b1-b2)²
```

取 `d` 最小的候选槽。转换矩阵用 Björn Ottosson 的标准式（与下面 Python 金样同一套系数），**不要**用 CIE Lab / XYZ 再转一层。

色度 `C = hypot(a, b)`。分闸（先闸再最近邻）：

| 输入 C | 候选槽过滤 |
|---|---|
| `C ≥ 0.08`（有色） | 只保留 `C ≥ 0.06` 的槽（通常是 ansi 1–6、9–14） |
| `C < 0.08`（灰） | 只保留 `C < 0.06` 的槽（通常是 bg/fg/0/7/8/15） |
| 过滤后空集 | 退回该角色的全候选（见 §1.4），并 `DiagLog` 记下主题 `source`、输入 RGB、空集原因 |

角色候选（过滤之前）：

| 角色 | 候选 |
|---|---|
| 前景 `background=false` | `{defaultFg} ∪ ansi16[0..15]`（**不含** `defaultBg`、**不含** `userBlockBg`） |
| 背景 `background=true` | `{defaultBg} ∪ ansi16[0..15]`（**不含** `defaultFg`、**不含** `userBlockBg`——userBlock 只走 083 特例） |

并列打破：`d` 差 `< 1e-6` 时，优先 **更小的 ansi 下标**；再 `defaultFg`；再 `defaultBg`。必须确定，禁止随调用顺序漂。

256 索引 16–255：用 **标准 xterm 立方体/灰阶** 还原成 RGB（与今天 `Scheme.xterm256` 在 `i>=16` 且非 254 时的公式相同：`cube(v)=0 或 55+40*v`；灰阶 `8+10*(i-232)`），再当真彩投影。**不要**把 `xterm256` 数组里已经写进的 `ansi16[0..15]` / `userBlockBg` 再投一次——那两段走恒等或 083，不走本节。

### 1.3 为什么不选另外两个

| 方案 | 不选的理由 |
|---|---|
| **sRGB 欧氏** `√(ΔR²+ΔG²+ΔB²)` | 绿通道权过大、蓝饱和被低估。当前深色板上纯蓝 `(0,0,255)` 会落到 **ansi8 灰**（`d_euclid` 对 ansi8 更小），关键字蓝变成灰色。语法高亮的「不可接受塌」（§2）会在这个度量上系统性发生。 |
| **加权 RGB / redmean** | 比裸欧氏好，仍在 sRGB 非线性里比。同一纯蓝在当前深色板上 **redmean 同样选 ansi8**。省不了多少：候选最多 17 个槽，OKLab 一次转换 + 17 次乘加，格子绘制相比可忽略。 |
| **CIEDE2000** | 感知更细，公式长、要调 `kL/kC/kH`，16 色槽上赢家几乎与 OKLab 相同。本格不引入。 |

OKLab 本身仍会把纯蓝投到「最近的有色槽」——当前深色板的蓝是偏亮的 `8FA9F5`，距离 0.35，看起来不像「原蓝」，但这是 **主题蓝**，符合 085。色度分闸的作用是阻止它塌进灰槽。

### 1.4 伪代码（照这个写）

```
fun colorFor(color, background, dark, againstBg: Int? = null): Int {
    pal = of(dark)
    when (color) {
        Default -> return background ? pal.defaultBg : pal.defaultFg
        Indexed -> {
            if (hit083(index, background, pal, dark)) return 083sink
            if (index in 0..15) return pal.ansi16[index]
            rgb = xtermCubeOrGray(index)          // 16..255，254 已在 083 拦截
            return project(rgb, background, pal, againstBg)
        }
        Rgb -> {
            raw = pack(r,g,b)
            if (background && hit083Luma(raw, pal, dark)) return 083sink
            return project(raw, background, pal, againstBg)
        }
    }
}

fun project(argb, background, pal, againstBg): Int {
    rgb = unpack(argb)
    lab = toOkLab(rgb)
    slots = roleSlots(background, pal)           // §1.2
    slots = chromaGate(lab.C, slots)              // 空则退回 roleSlots
    picked = min(slots, key=d(lab, slot.lab), tie=§1.2)
    if (!background) {
        ref = againstBg ?: pal.defaultBg
        picked = contrastRepair(lab, picked, slots, ref)   // §3
    }
    return picked.argb   // 必须是槽位字面量
}
```

Scheme 构造时预计算：每个槽的 OKLab；256 项 LUT（`Indexed` 16–255 的最终 ARGB，083 槽除外）。真彩每格现算 17 次距离。切主题只重建 LUT。

## 2. 丢信息怎么办（本格最重要的一问）

16+2 槽装不下 256 / 真彩。投影是有损的。下面把「塌」分成可接受 / 不可接受，并规定**不做**哪些看似能保区分度的办法。

### 2.1 可接受的塌

- **同色相、不同深浅**落到该主题的普通/亮一对（ansi `n` 与 `n+8`）。例如 xterm 立方体里一串绿 → 主题绿 / 亮绿。语法高亮里「注释绿」和「字符串绿」若本来就是同族，塌成一对是主题该有的味道。
- **灰阶 232–255** 塌进 `{bg, fg, 0, 7, 8, 15}` 里最接近的一档。
- **真彩与 256 表示同一 sRGB**（196 与 `38;2;255;0;0`）必须落到**同一槽**（投影前先还原 RGB，禁止按「编码路径」给不同答案）。

### 2.2 不可接受的塌（规则必须挡住的）

- **不同色相族**落到同一槽：红 vs 绿 vs 蓝 vs 黄 vs 青 vs 品红。这是语法高亮的语义轴（错误 / 成功 / 关键字 / 类型 / 字符串 / 常量）。色度分闸就是为了禁止「纯蓝 → 灰」「纯绿 → 浅底近白」。
- **有色输入落到无色槽**、**无色输入落到有色槽**（灰字变青、青字变灰）。双向色度分闸。
- **前景落到纸色 / 与背景对比度 < 3.0**（字消失）。§3。

规则**不能**挡住的（接受为代价，见 2.4）：

- 主题自己的 ansi4 和 ansi12 色相很近时，两种「蓝」仍会并成一对。
- 橙色 `(255,121,0)` 在当前深色板上离 ansi1（粉红）比离 ansi3（黄）更近 → 落红族。这是这块 APP 色板的几何，不是 CLI 的错；换 Dracula 后同一橙色应落到该主题的红或黄，以那时的 OKLab 为准。
- 十几种语法色只有 6 个有色族：第 7 种色相没有槽，只能并进最近族。

### 2.3 不做「先聚类再分配」或「保色相只归一亮度」

| 备选 | 为什么不做 |
|---|---|
| 整屏 k-means / 匈牙利分配 | `colorFor` 是**逐格、无帧状态**的漏斗。同一 RGB 在滚动/delta/scrollback 里必须永远同一槽，否则半屏刷新会闪。聚类依赖「这一屏还有谁」，同一段字节流在不同窗口尺寸下会换色——085 判据要求固定字节流 → 固定集合，做不到。 |
| 保色相、只把亮度拧到主题 | 输出不在 16+fg+bg 里，直接违反「⊆ 色板」。那是滤镜，不是主题。 |
| 动态加槽 / 生成中间色 | 同上，扩色板。 |

相对区分度只靠三件**局部**工具：色度分闸、普通/亮成对仍都在候选里（深浅绿可分到两档）、对比度修补只在前景、且优先在**同一色相族**里换档（ansi `n` ↔ `n+8`，见 §3）。

### 2.4 代价（不许假装没有）

1. **色相分辨率上限 ≈ 6**：再多的真彩语法主题都会并族。用户选 16 色主题，就是接受这件事。
2. **CLI 原作者心中的「那一抹蓝」会变成主题蓝**，饱和度/明度以主题为准。这是 085 的本意，不是缺陷；但截图对比「主机上的 Claude」会永远不一致。
3. **对比度修补会再丢一档**：浅底上的近白字可能从 ansi0 被抬到 ansi7，灰阶层次少一档。
4. **色度阈值 0.08 / 0.06 是在当前 APP Light/Dark 上标定的**。Vesper / Dracula / Solarized 的槽 C 值本格**没有**逐份计算（生成物还不在仓里）。某主题的「蓝」若 C < 0.06，有色输入会进不了它——见 §7，失败则 halt，不准暗调阈值去凑某一份主题。
5. 083 把近白背景钉死成 APP `userBlockBg`（薄荷灰），**浅黄高亮块会失去黄**。这是 083 与 085 同时成立的代价，见 §5。

## 3. 前景 vs 背景：规则不同

### 3.1 为什么不能共用一条

| | 背景 | 前景 |
|---|---|---|
| 083 | 整屏黑 → 纸；近白块 → userBlock | **禁止**把黑抬成纸（字会消失）。今天注释已经写了这条 |
| 候选 | 含 `defaultBg`，不含 `defaultFg` | 含 `defaultFg`，不含 `defaultBg` |
| 近黑真彩 | 守卫到纸色 | 投到 ansi0/8/15 等，再按对比度修补 |
| 近白真彩 | 守卫到 userBlock | 投到 ansi15/7/fg |

背景是「场地」，前景是「字」。同一 RGB `(0,0,0)` 两种角色答案必须不同。083 的亮度守卫**只留在背景路径**。前景走 §1 投影 + 本节修补。

### 3.2 可读性下限（可判定）

对**同一单元格**最终绘制的 `(fgArgb, bgArgb)`：

```
contrast(fg, bg) = (L1 + 0.05) / (L2 + 0.05)     # L1≥L2
L = 0.2126*Rlin + 0.7152*Glin + 0.0722*Blin      # WCAG 2.1 相对亮度
```

**硬下限：`contrast ≥ 3.0`**（WCAG AA Large Text）。不采用 4.5（AA 正文）：4.5 会把浅色主题上大量有色槽逼进 `defaultFg`，§2 的色相轴会先于可读性被牺牲。3.0 是「能看清字形」的地板，不是印刷正文标准。

修补算法（只改前景）：

1. 已得 `bg'`（083 或背景投影，**不再改**）。
2. 前景最近邻得 `fg0`。若 `contrast(fg0, bg') ≥ 3.0`，用 `fg0`。
3. 否则在**当前色度闸后的候选**里，先找「同族换档」：`fg0` 是 ansi `n∈0..7` 则试 `n+8`，反之试 `n-8`；`defaultFg` 则试 ansi7 与 ansi15。谁达标且 `d` 更小用谁。
4. 仍不达标：在候选里所有 `contrast≥3.0` 的槽中取 OKLab 最近。
5. 仍空：`defaultFg`。`DiagLog` 记 `fg_rgb, bg', contrast_before, contrast_after, source`（两边操作数都记，不要只记「未触发」）。

`TermSurfaceView` 现有反显约定保持：`resolvedBg` 先算（`background` 旗标按今天的互换），`resolvedFg` 后算并把 **已解析的 bg ARGB** 传入 `againstBg`。禁止为了对比度去改 083 的纸色/userBlock。

单测若只调 `colorFor(..., background=false)` 不传 `againstBg`，对照默认 `defaultBg`。这对 §6 夹具足够。

## 4. 例外清单（穷举）

下面是**全部**允许「不走 §1 通用投影」的情况。不在表里的 = 必须投影。没有「视情况」。

| ID | 情况 | 判据（代码里怎么认） | 落点 |
|---|---|---|---|
| E1 | 默认色 | `TerminalColor.Default` | `defaultBg` / `defaultFg` |
| E2 | ANSI 16 | `Indexed` 且 `index∈0..15`，且未命中 E3 | `ansi16[index]`（已经是主题槽，恒等） |
| E3 | 083 三条 | §5 的触发表 | 纸色或 `userBlockBg` |
| E4 | 光标 | 绘制路径用 `TerminalPalette.cursor` / Scheme 无此字段时的 APP cursor，**不经过** `colorFor` | 主题 cursor（`t.plan`）。不进 §6 单元格集合 |
| E5 | 选区叠层 | `selection` 半透明，不经过 `colorFor` | APP 或上游 Selection Color。不进 §6 |
| E6 | APP 外壳 | 列表/设置/导航/`DesignTokens` | 与终端主题无关 |
| E7 | 会话页附件预览等非网格位图 | 不是 `TerminalColor`、不是 `TermSurfaceView` 单元格 | 原图像素。今日无 sixel 实现（`app/` 内零命中）；**将来若加 sixel/iTerm 内嵌图，像素仍不进 `colorFor`**，本条即其判据。单元格 SGR 不得借本条透传 |

**明确不存在的例外**（写出来防止实现席「补」）：

- ⛔ 主题声明「支持真彩透传」。iTerm2-Color-Schemes 的 `.itermcolors` 没有这个字段；`t.plan` 的 `TermSchemeColors` 也没有。不许加开关。
- ⛔ 用户设置「关闭重新着色 / 跟随 CLI 主题」。085 用户原话已经否了。
- ⛔ 某主题「看起来像真彩」就跳过。
- ⛔ OSC 4/10/11：今日解析器对 OSC **默认忽略**（`AnsiParser` 注释：窗口标题等）。若以后实现 OSC 改默认色，仍须把结果当成 `Default`/`Rgb` 再进 `colorFor`，不得把主机调色板写进格子。
- ⛔ bold 当亮色：那是模拟器把 SGR 1 映到 ansi 8–15 的事，映完仍是 `Indexed(0..15)`，走 E2。
- ⛔ 反显 SGR 7：继续用今天的 `resolvedFg/Bg` 旗标互换，两边都进 `colorFor`，不是透传。

## 5. 与 083 §2 / `t.bg` 的合流

**三条特例全部保留为特例，不被 §1 通用投影吸收。** 触发条件一字不改；**目标值**随 Scheme（主题纸色 / APP userBlock）。不得推翻 083 §2（浅色白底 + 灰底用户消息块；grok 整屏黑走纸色不是 ansi0）。

### 5.1 触发表（与今天 `TermPalette.kt` 对齐）

| # | 触发（机制，不动） | 今日落点 | 主题化后落点 |
|---|---|---|---|
| S1 | 背景且 `Indexed(0)` 或 `Indexed(16)` | `defaultBg` | 当前主题 `defaultBg`（纸色）。**禁止**改走 ansi0，即使 OKLab 认为 ansi0 更近 |
| S2 | `Indexed(254)`（任意角色）；背景且 index ∈ `{231,253,255}` | `userBlockBg` | 仍是 APP `userBlockBg`（按 `dark`，不按主题） |
| S3 | 背景且 `Rgb` / 非 083 的 256 扩展色，走亮度守卫：`luma≤32` → 纸；`luma≥220` 且 `chroma≤8` → userBlock | 同左 | 同左，操作数是当前 Scheme |

`USER_MESSAGE_INDEX=254`、`CUBE_BLACK_INDEX=16`、`NEAR_WHITE_INDEXES`、`SCREEN_BLACK_LUMA_MAX=32`、`HIGHLIGHT_WHITE_LUMA_MIN=220`、`ACHROMA_MAX=8`、`luma()` 公式全部保留。

### 5.2 S3 的 `else` 与 `scaleLuma`（今日漏出点）

今天 `guardRgbBg`：

- 命中 S3 前两支 → 已在 `R(X)`。
- `!dark && luma≥220 && chroma>8` → **`scaleLuma` 保色相**，产出不在 `R(X)` 的中间色。
- `else` → **`raw` 原样**，256/真彩背景漏出主题。

085 要求 ⊆ `R(X)`。处理：

1. **`else` 改为 `project(...)`**（§1）。这是本格要修的漏。
2. **`scaleLuma` 分支取消，改与深色相同：落 `userBlockBg`。** 触发仍是 `luma≥220`（浅底近白高亮块），机制还是 083 的「近白当用户块」，只是不再造一个不在色板上的粉彩。

代价（已在 §2.4.5）：浅黄/浅粉高亮背景会变成 APP 薄荷灰，不再保留 CLI 色相。083 用户原话要的是灰底用户块，不是「浅黄也算用户块但保持黄」。若实现席把 `scaleLuma` 留着，§6 的 ⊆ `R(X)` 会在浅色 + `48;2;255;255;200` 上红——那是本格的预期，不是要他放宽容差。

### 5.3 顺序（禁止调换）

```
Default / 083 S1–S3 / Indexed 0–15 恒等
        ↓ 未命中
§1 投影（256 立方或真彩）
        ↓ 仅前景
§3 对比度修补
```

S1 必须在「index 0 恒等 ansi0」之前（今天已经是这样）。S2 的 254 必须在 256 LUT 之前（今天 `xterm256[254]` 已写 userBlock，但 `colorFor` 仍应先走 `if (index==254)`，不要只靠数组，避免 LUT 重建时漏）。

`t.plan` §3.2「不许重写 `indexed` / `guardRgbBg` / `USER_MESSAGE_INDEX`」对 **S1–S3 触发** 仍然成立；允许动的是 `guardRgbBg` 的 `else`/`scaleLuma` 以及 `indexed` 在 16–255 非特例上的 `raw` 返回值。

## 6. 判据设计（契约 §1.5 最硬的一条）

给定**固定字节流** F：主题 X 下单元格颜色集合 `S(X) ⊆ R(X)`（容差内）；主题 Y 下 `S(Y) ⊆ R(Y)`；且 `S(X) ≠ S(Y)`。

这同时验 ① 没有颜色漏出主题 ② 换主题世界变了。只验默认背景变了 = 不及格。

### 6.2 集合怎么取

**A. 单测 / `colorFor`（主判据，先验红用这条）**

```
S_unit(X) = { colorFor(c, bg, darkX) | (c,bg) in probes }
assert(S_unit(X) ⊆ R(X))          // 每个 Int 必须 == 某个槽，见容差
assert(S_unit(Y) ⊆ R(Y))
assert(S_unit(X) != S_unit(Y))
```

主题 X/Y：`t.wire` 落地前用 `dark=false` vs `dark=true`（今天的 Light/Dark）；落地后用同一 `dark`、两个族（建议深槽 **Vesper vs Dracula**，纸色 `#101010` vs Dracula 上游值，且 16 色板不同）。不要用两个「深浅同文件且色值碰巧接近」的族去验 ≠。

再加一条渲染：`TerminalEmulator.feed(REMAP_FIXTURE_V1)` + `TermSurfaceView.draw`，收集 `Canvas.drawRect` 的 `paint.color` **和** `drawText` 的 `paint.color`（今日 `TermBgRemapTest.RecordingCanvas` 只记了 rect，**必须补 text**，否则真彩前景漏出测不到）。`S_draw ⊆ R(X)`。

**B. 像素采样（模拟器，世界变了）**

抄 `t.bg`：`screencap` raw + SurfaceView bounds。在 F 渲染后的终端垫上均匀取 N≥9 个点（避开光标）。每个像素 RGB 必须与 `R(X)` 中某一槽的 Manhattan 距离 `≤ 48`。换主题后同一点集的颜色集合不等，且各自 ⊆ 对应色板。

双 density 480 与 440（083 §0 / `t.plan` §6.7）。记日志：每个点的 `(x,y,rgb,nearest_slot,dist)`，两边操作数都写。

### 6.3 容差

| 层 | 容差 | 为什么 |
|---|---|---|
| `colorFor` 返回值 | **0**（`assertEquals` 槽位字面量） | 投影输出就是 `Int` 常量，没有合成。放宽 = 允许再漏。 |
| Robolectric `Canvas` paint.color | **0** | 同左。 |
| 模拟器 screencap | Manhattan `\|ΔR\|+│ΔG\|+│ΔB\| ≤ 48` | 与 `t.bg` / `t.plan` §6.5 同一量纲（他们用 Vesper/Afterglow 的 `3×17=51` 论证 A≠B 门槛）。这是采集噪声，不是投影误差。禁止改成截图 md5（077 §2）。 |

「⊆ 色板（容差内）」：单测层容差 0；像素层允许像素落在槽的 48 邻域。二者不要混用。

## 7. 风险与查不清

1. **OKLab 色度阈值 0.08 / 0.06**：只在当前 `TerminalPaletteLight/Dark` 上标定。51 份 iTerm 主题的槽 C 值**查不清**（生成物未进仓，本格不许跑网络去拉）。某主题 1–6 全是灰调（Solarized 的「绿」有时很脏）时，有色分闸可能把真正的主题绿滤掉。实现席生成后必须对每个 `sourceFile` 断言：ansi 1–6 中至少 4 个 `C≥0.06`。失败 **halt 那一个主题**，不要全局改阈值。
2. **Dracula / Vesper 的 16 色 hex**：`t.plan` 只钉了 Vesper/Afterglow 的 Background。本格例子用 APP 深色板，**不是**上游 Dracula。实现席不要把 §1.5 的 `F0879F` 抄进 Vesper 测试。
3. **对比度 3.0 会不会把浅色主题的 ansi8（常是灰）全部抬成 ansi7**：Light 上灰 128 已经发生（2.42 → ansi7）。这是规则的预期代价。会不会让「注释灰」和「正文」同分？查不清，取决于该浅色主题 ansi7 vs fg 的距离。不要为这加第二套阈值。
4. **反显 + 083**：`resolvedBg` 用 `colorFor(fg, background=false)`。若 CLI 反显的「底」来自 index 0，不会走 S1（S1 要 `background=true`）。这是今天已有行为，本格不改。反显格子对比度是否仍 ≥ 3，本格**没有**拿真实 Claude 反显字节验证。
5. **`t.bg` 可能还在改 `colorFor` 签名**（`t.plan` §8.6 已警告）。实现席开工前再读仓根 `TermPalette.kt`，把投影接在当时的 083 之后，不要按本文件里的行号打补丁。
6. **glyph 几何色（`BoxBlockGeometry`）**：若框线/色块用 `paint.color` 取自 `colorFor`，会自动合规；若内部还有写死 RGB，本格**没把 TermSurfaceView 的几何路径逐行核对**。实现席 grep `0xFF` 字面量，发现绘制层私货再收进漏斗，不要在本规则里开新例外。
7. **Web 端**：085 是 App 设置/终端。本格不规定 `web/`。若 web 以后要同一语义，另开任务，禁止本格顺手改。
8. **没有**在真机/模拟器上看过「投影后的语法高亮是否还能读」。单测 ⊆ 色板 ≠ 好用。这是 085 已知难点，验收仍要眼睛（emulator-manual-test），本格不假装 LUT 绿了就完了。
