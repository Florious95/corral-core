## 三种成因怎么分开（先补仪表，再动修法）

081 要求日志能分清：

| 成因 | 日志长什么样 |
|---|---|
| 1 按错误宽度发了 resize | `resize sent cols=N` 且 `N` 与 `derived_cols` 不等，或 `resize skipped cols=0` |
| 2 重连没按当前列宽重发 | `reconnect ok resend_resize=no`，或重放 subscribe 的 cols 仍是首次 `40×120` |
| 3 当前屏协商对了、历史按旧列宽定形 | `derived_cols==frame cols` 但画面仍两套折行（那是产品决策，不是 cols bug） |

本轮实测导出（改后 `diag-after.log`）里有两边操作数：

```
[reflow] resize sent rows=49 cols=51 reason=user ok=true bookkept_rows=49 bookkept_cols=51
[reflow] frame cols=51 render cols=51 bookkept_rows=49 emulator_rows=49
[reflow] source=resume view_width_px=1128 cell_width_px=22 derived_cols=51 last_sent_cols=51
```

本次 65s 后台 **本机 daemon + adb reverse 没有掉线**，所以没有 `reconnect ok` 行。那不是仪表缺口——掉线路径由单测 `termReflowReconnectReplaysLatestColsNotInitialSubscribe` 打穿。

## 根因（成因 2，代码里坐实）

`SessionRoute` 首次 `subscribe(ref, 40, 120)`。视口建立后再 `resize` 到真机列宽（这次是 51）。

旧契约：`ConnectionManager.resize` **不改订阅簿记**。后台掉线 → `replaySubscriptions` 按 **40×120** 重订 → 服务端按 120 折行重拍快照，App 仍按 51 解释 ⇒ 同一屏两套换行。用户说「必然乱」对应这条。

## 改了什么

- `ConnectionManager.resize(ref, rows, cols, reason)`：成功发出后更新簿记；非正行列 / 未就绪记下两侧操作数后跳过。
- 重连 `onReady`：`reconnect ok resend_resize=yes cols=… rows=…`（subscribe 携带最新簿记，一次，非周期）。
- 回前台 `onRealViewportChanged`：`view_width_px` `cell_width_px` `derived_cols` `last_sent_cols`（`derived_cols` 用已扣左右内边距的可用宽）。
- SNAPSHOT：`frame cols=`（簿记，服务端认的）vs `render cols=`（emulator）。

未改成周期性 resize / 全屏重绘（061）。078 左右 14dp 仍走 `usableWidthPx` → `colsFor`。
