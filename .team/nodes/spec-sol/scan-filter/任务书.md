# t.scan-filter.impl — tmux socket 扫描前置过滤

## 一、背景与必读坐标

产品要发现的是当前 uid 的用户真实 tmux 中运行的 Agent CLI。team-agent 私有 socket、测试/隔离自建 socket 和归属不明的 socket 不是产品发现对象；若 daemon 每 2 秒对目录内每个 socket fork 一次 `tmux list-panes`，会抬高空闲 CPU，并污染真机性能体验。

本格只修“候选 socket 在任何 tmux 子进程产生前完成分类”这一件事，不扩大到扫描周期、daemon 生命周期或其它协议。开工前按顺序读：

1. 本任务书；
2. `CLAUDE.md` 中稳定性能基线、全自动编排、凭据/tmux 红线、诊断日志纪律；
3. `server/internal/discovery/scan.go` 的 `DiscoverWithDirs`、`DefaultSocketDirs`、`listSocketFiles`、`scanServer`、`probeSocket`；
4. `server/internal/discovery/scan_test.go` 的隔离夹具与现有回归测试；
5. `.team/ledgers/acceptance/scan-filter.sh`。

先执行 `python3 tools/basegen.py scan-filter`，把影响闭包作为知识基底；不得靠通读整棵 `server/` 替代。

### leader 已裁定的分类正本

分类只使用 uid、候选路径/文件名和当前进程环境 `TMUX` 的第一段；**分类阶段禁止 fork tmux**。显式禁止优先于允许：

1. **禁止**：任一路径 basename 匹配 `ta-*`；其它 uid 的 `tmux-<uid>` 目录；以及下列本任务明确列出的测试/隔离路径。其它 uid 目录必须在 `listSocketFiles` 前跳过；其余禁止项必须在 `probeSocket` / `scanServer` 前跳过。所有禁止项的 `tmux list-panes` 次数严格为 0。
2. **允许**：排除上述禁止项后，当前 uid 的 `tmux-<uid>` 目录中 basename 恰为 `default` 的 socket；以及候选清理后路径与进程环境 `TMUX` 第一段清理后路径完全相同的 socket。
3. **未知**：同目录其它文件名 fail-closed 跳过；记录路径和分类结论，不调用 `tmux list-panes`。
4. **合取**：过滤之后，允许项里的用户 Agent CLI 仍必须被发现。关闭全部扫描来换取零禁止调用，判失败。

本任务明确列出的测试/隔离路径为：

- basename 匹配 `test-*` 或 `e2e-*`；
- 任一祖先目录 basename 匹配 `e2e-*` 或 `agentmirror-tmux-test-*`；
- 位于仓内 `.team/nodes/*/tmp/` 之下的 socket。

若同一路径同时命中允许与禁止规则，以禁止为准。`TMUX` 只取第一个逗号之前的 socket 路径，不打印或记录其余字段。

## 二、精确交付物

实现席只允许修改/新增：

1. `server/internal/discovery/scan.go`：在目录/候选进入 `probeSocket`、`scanServer` 之前完成上述分类；不得新增产品配置面或后台轮询器。
2. `server/internal/discovery/scan_filter_test.go`：新增聚焦测试，测试名逐字为 `TestDiscoverScanFilterCommandBoundary`。
3. `server/internal/discovery/scan_test.go`：只做新分类契约所必需的既有夹具/断言调整；不得删掉现有发现、聚合、取消、死 socket 不 fork 等回归覆盖。
4. `server/internal/discovery/doc.go`：只同步扫描边界的外骨骼说明；若正文已准确则不为凑 diff 修改。
5. `.team/nodes/scan-filter-impl/IMPL.md`：记录基线红、修复后绿、完整测试命令/退出码、改动文件坐标、spy 原始 argv 证据摘要、分类日志的路径+结论操作数，以及未验证项。不得写“性能优化成功”。

`TestDiscoverScanFilterCommandBoundary` 必须是可执行的真实行为夹具，不得只 grep 源码：

- 临时根只写仓内 `.team/nodes/scan-filter-impl/tmp/`，测试自行创建唯一短子目录并清理；禁止 `/tmp`、`/private/tmp` 和真实 tmux socket。
- 用自建 UNIX listener 让候选 socket 可探活；不启动真实 tmux。
- 在 PATH 前置一个自建 `tmux` spy，记录完整 argv，并对允许 socket 返回合法的假 `list-panes -F` 行；spy 不得转发到系统 tmux。
- 机械判据还会在测试 PATH 外层放置 fail-closed `tmux` guard；测试自己的 spy 必须截获预期调用，任何落到外层 guard 的调用都判失败，保证系统 tmux 不可达。
- 当前 uid 目录至少放 `default`、`TMUX` 第一段精确指向的自定义用户 socket、`ta-*`、未知名 socket；另放一个本任务列明的隔离 socket 和一个其它 uid 目录的 `default`。
- 显式触发一次 `DiscoverWithDirs`；断言允许的两个用户 socket 各产生一次 `list-panes` 且两个 Agent pane 均进入 Model；`ta-*`、隔离、未知、其它 uid 的 `list-panes` 次数均为 0。
- 捕获 debug 日志并逐项断言跳过项同时带原始 `socket/path` 与 `classification/action`，能从日志判断“分类为什么跳过”，不能只有“skipped”。
- 通过时逐字输出两行：

```text
SCAN_FILTER_EVIDENCE default_list_panes=1 tmux_env_list_panes=1 ta_list_panes=0 isolated_list_panes=0 unknown_list_panes=0 other_uid_list_panes=0 user_agents_found=2 spy_argv_recorded=true
SCAN_FILTER_CLASSIFICATION_EVIDENCE ta=skip isolated=skip unknown=skip other_uid=skip path_operand=true classification_operand=true
```

## 三、硬约束与机械验收

1. **先红后绿**：先只加聚焦测试；在未改产品实现的基线树上必须“能编译、能运行、因 spy 记录到禁止项 `list-panes` 而失败”。缺测试文件或编译不过不算先验红。红证据落入 `IMPL.md` 后才改实现。
2. 分类必须发生在任何 `probeSocket` / `scanServer` / `exec.Command*` 之前；禁止通过先 fork 再丢结果来伪装过滤。
3. 不扫其它 uid；未知 socket fail-closed；禁止项必须留路径与分类结论两边操作数。允许项的外部调用日志仍须含 socket 路径和 `list-panes` argv。
4. 不得关闭全部扫描。默认用户 socket 与 `TMUX` 指向的用户 socket 均须保留发现能力；pane 的 `Socket` 身份不得丢失。
5. 不连接/重启生产 daemon `:9900`，不读取凭据、真实 tmux、用户会话、provider profile、`tailnet-test.env`、Shadowrocket plist、`tailscale_keys.bin` 或生产明文日志；不移动真实鼠标。
6. 不改扫描周期、不加固定频率进程、不改性能阈值、不删除现有 PerfTrace 仪表，不借本格宣称真机性能优化。
7. 新增/修改代码维持现有风格与外骨骼注释；只动第二节列出的路径。相邻无关问题只写进 `IMPL.md`，不顺手修。
8. 测试禁止缓存：

```sh
cd server && go test -count=1 ./internal/discovery/...
cd .. && sh .team/ledgers/acceptance/scan-filter.sh
python3 tools/archwiki/build_wiki.py --check --strict-t3
```

必需机械判据为 `sh .team/ledgers/acceptance/scan-filter.sh`，`expected_exit_code=0`，`unjudgeable_exit_codes=[2]`。实现席自跑绿只是交付证据，最终由独立判者重跑。

### 破坏齿

破坏齿由实现完成后的独立判者选址；任务书只规定性质：在离禁止外部调用最近、且不修改测试/判据的位置，临时让一个 `ta-*` 或隔离 socket 穿过分类边界。必须证明“改坏必红、还原必绿、同一坏树上用户 socket 的阳性臂仍绿”，从而排除“关掉全部扫描”的假绿。验完还原并证明独立判者工作树无残留。实现席不得预选具体代码行或为破坏齿留后门。

## 四、四态与合法出口

- **通过 / exit 0**：聚焦测试确实运行；两个允许 socket 各一次 `list-panes`、两个用户 Agent 被发现；四类禁止/未知项均零调用；分类日志两边操作数齐；两行固定证据均出现。
- **失败 / exit 1**：量具有效但任一禁止/未知 socket 产生 `list-panes`；用户阳性臂缺失；要求的测试/交付物缺失；测试或产品代码在有效环境中编译/断言失败。
- **不可判 / exit 2**：Go 工具链不可用、仓根/`go.mod` 无法确定、仓内夹具目录不可写，或量具无法证明 spy/阳性路径真的运行。不可判不是绿也不是红，禁止改脚本、弱化断言或改阈值放行。
- **不适用**：仅由账本在本机 tmux 发现分支从未派发时表达；本脚本不为不适用分配退出码。已经派发后“没有跑起来”是不可判，不是不适用。

若第二节写路径不足以实现裁定、分类规则再次冲突，或必须碰真实 tmux/生产面才能验证，立即停止产品修改，落 `IMPL.md` 写清已试、阻点和需要的裁定，并如实报不可判；不得猜测扩 scope。

所有 required artifacts 落盘后，正常收工的唯一出口是调用标准 `report_result` 一次。实现格不得 merge、不得改 main、不得打 tag；提交/PR 按 leader 审核后的账本与工程既有流程执行。
