# ledger.baseline-bundle.v1 — 金标准基线资产恢复、A2 重基线与不可变归档

## 一、冻结事实与目标

旧性能基线 A 的权威身份是 tag `baseline-20260822-release`、commit `26f46642d3960b1bd96a39753b3f25516c5821eb`、参考 APK md5 `0907d6881bb1e034ef33a49f89afaa44`、大小 `35044459` bytes、Android Debug signer certificate SHA-256 `ea427eb4e14f95654a66802b6558fbbf6f93f1ca69d8117795fb7cef376cb13b`。最终行为金标准仍是用户在蜂窝网络加广州中转路径打开真实会话“秒开、没有空白”。历史 `.team/perf/baseline-20260822.json` 是 null/`INCONCLUSIVE`，不是可执行性能门。

现有 `ledger.perf-regress.v1` revision 4 的 impl 为 `failed_retryable`，精确 A 已知不在仓内；按 tag 重建得到同体积但 md5 `2fda1fdec68f5aba9389b6a0a1e8598d`，不能冒充旧 A。旧链继续重试只会重复 `measurement: unjudgeable`。本链必须同时解决：诚实分类、A2 建立、私有不可变归档、取回/安装前置、旧 park 安全迁移、fresh A/B/A/B 和用户 gate。

## 二、两条合法恢复路线

执行席先写 `.team/nodes/baseline-bundle-impl/ROUTE.md`，固定字段：

```text
legacy_status: blocked_missing_baseline
route: recover_exact_artifact|rebaseline_with_equivalence_proof
exact_reference_found: true|false
```

- `recover_exact_artifact`：只接受 md5、大小、signer 三项都匹配的旧 A。候选来源限任务书点名的仓内私有 inbox、已知本仓产物目录或用户明确提供的本地路径；禁止扫用户目录、网络公开分发或读取凭据。
- `rebaseline_with_equivalence_proof`：精确旧 A 不存在时的正常路线，不是失败重试。A2 必须从上述冻结 commit 的干净、独立构建树做两次 `assembleRelease --rerun-tasks --no-build-cache`；两次运行内容归一化摘要相同、签名身份相同、包身份相同、无缓存测试全绿、归档可恢复且用户真机 gate 通过后，才可成为新 A。
- 如果两条路线都因 SDK、构建工具、授权输入或证据缺失而不能完成，则 exit 2；不得把“旧 A 缺失”本身再次写成 `failed_retryable`。

## 三、Baseline Bundle v1

实际 debug 签名 APK 只能落在 `.team/private/baseline-vault/` 与 `.team/private/baseline-backup/` 的本地忽略路径，不得 commit、push、上传 Release 或写入 report_result 正文。可提交的 manifest 至少包含：

1. `source`：tag、commit、干净状态、完整 source closure SHA-256；
2. `runtime`：`normalized_runtime_sha256`、条目数、package=`dev.agentmirror.app`、versionCode/versionName；
3. `artifact`：APK SHA-256、md5、字节数、signer certificate SHA-256；
4. `build`：Gradle wrapper、JDK、SDK/build-tools/AGP 身份、完整无缓存命令和两次独立构建摘要；
5. `equivalence`：路线、参照物、逐项相等/不等与报告 SHA-256；
6. `archive`：内容寻址 bundle id、primary/backup 相对位置、两份摘要、恢复后摘要、`sealed=true`、两份无写位且非 symlink/非同 inode 证明；固定路径只能是 `.team/private/baseline-vault/<bundle_id>/baseline.apk` 与 `.team/private/baseline-backup/<bundle_id>/baseline.apk`；
7. `reports`：构建、等价、安装、归档与取回报告的 SHA-256；
8. `implementation`：固定 git provenance HEAD、bundle shell/Python、迁移脚本、聚焦测试与测量 runner 的仓内相对路径和 SHA-256，禁止调用方替换输入根。

运行内容归一化算法必须按 APK ZIP 条目路径排序，对每个条目的“路径、解压后字节数、解压后 SHA-256”再做总 SHA-256；忽略 ZIP 顺序、压缩方法和时间戳，只排除签名容器 `META-INF/MANIFEST.MF`、`META-INF/*.SF|*.RSA|*.DSA|*.EC`，APK Signing Block 本来不属于 ZIP 条目。`AndroidManifest.xml`、`classes*.dex`、`resources.arsc`、`res/`、`assets/`、`lib/` 与其它非签名条目都必须纳入。改变任一运行条目必须改变摘要。

`bundle_id` 精确定义为 canonical JSON identity projection 的 SHA-256：projection 只含 `source/runtime/artifact/build/equivalence/implementation`，按 UTF-8、key 排序、无空白分隔编码；归档与报告位置不参与以避免循环引用。bundle 目录以该摘要命名，创建后拒绝覆盖；primary 与 backup 必须是两份独立可读文件，不能是 symlink 或同 inode。完成前必须从 backup 恢复到新路径，再重新核 manifest、APK 摘要、signer 和静态可安装性。

## 四、性能门与迁移

任何 fresh 测量前必须按序机械通过：bundle 可取回、manifest/实际 APK 摘要匹配、signer/package 匹配、静态 APK 校验与隔离 adb 安装成功、backup 恢复成功、`sh tools/perfbase/envcheck.sh --gate` exit 0。随后仍用三夹具四段、同批 A/B/A/B、每包每格 n>=10、nearest-rank p50/p95，所有 B/A 必须 `<=1.10`；每份 raw 非空且用同一 batch/runner/A2/B 身份头绑定，机械门必须从 raw 单调事件链重算数组、统计与比例，不得信任结果 JSON 自报。缺环境/身份/顺序/样本为 exit 2，有效样本超阈值或证据对账矛盾为 exit 1。

旧 `ledger.perf-regress.v1` 只允许在 bundle verify 与用户 gate 都通过之后迁移。迁移格先只读核 ledger id/revision、impl=`failed_retryable`、末行 `measurement: unjudgeable`、lease pid 与 pidfile 相同、窄字段 `comm=ledger-run`、没有 `dispatching|dispatched|running|awaiting_result|acceptance_pending` 格；任一不符停止且 exit 2。前置全绿才可 TERM 精确 PID，有限等待、核 PID 消失，再用 ledgerdsl plan/apply 将旧源与编译账本置 `desired_state="paused"` 并保留 revision/历史备份。禁止 `pkill`、`killall`、删历史、抢 result 或杀其它 driver。

## 五、任务图与共同纪律

`repro → (impl ∥ test ∥ probe) → verify → user-gate → migrate → measure → final`。impl/test/probe 三席使用不同 worktree、写集不重叠；verify/final 由 `sampler-review-luna2` 独立裁决，用户 gate 不得由 agent 自证替代。

所有 shell 判据必须 POSIX sh、0=通过、1=产品/测试/交付失败、2=环境或证据不可判；Go 测试 `-count=1`，Gradle `--rerun-tasks --no-build-cache`。不启动/连接生产 daemon，不碰真实 tmux，不读 `.team/current/profiles/*.env`、`tailnet-test.env`、Shadowrocket plist、`tailscale_keys.bin` 或生产 daemon 明文日志；`ps` 只取 `pid,ppid,etime,stat,comm`。席位正常收工只调用一次标准 `report_result`，不 commit、push、merge、打 tag，不另发进度消息。
