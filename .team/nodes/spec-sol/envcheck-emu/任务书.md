# t.envcheck-emu.impl — 拆分测量前环境闸与本次模拟器测量闸

## 一、背景与必读坐标

r10 已在无模拟器时见到宿主 load 约 8–9，随后启动本次自建 AVD `agentmirror_test_b`，`adb -s emulator-5554 shell getprop sys.boot_completed` 为 `1`；再次跑现有 `envcheck --gate` 时 load1=16.55，高于既有阈值 12，于是得到不可判并关闭模拟器。这里不是阈值太严，而是把“开跑前必须干净”和“测量中本次被测基础设施必然占资源”混成同一阶段：如果内部闸不识别本次测量模拟器，流程将稳定自相矛盾。

本格只修性能采样工具的两阶段环境闸与自建模拟器收尾，不改 App、server、性能阈值或历史基线。开工前按顺序读：

1. 本任务书；
2. `CLAUDE.md` 的稳定性能基线、环境闸、凭据/进程/tmux 红线与测试禁缓存纪律；
3. `tools/perfbase/envcheck.sh` 文件头与现有四类检查；
4. `tools/perfbase/run-input-ab.sh` 的 envcheck 调用、fixture setup、采样循环和退出路径；
5. `.team/nodes/input-full-auto/perf-design/CONTRACT.md`；
6. `.team/ledgers/acceptance/envcheck-emu.sh`。

先执行 `python3 tools/basegen.py envcheck-emu`，只读其影响闭包；不得为本格通读 App/server 大树。

### leader 冻结的两阶段契约

1. **开跑前闸**：本次测量模拟器尚未启动。`envcheck --gate` 必须继续检查死 tmux socket、load1≤12、生产 daemon 空闲 CPU≤5%，并把任意已经存在的 `qemu-system` 视为非本次模拟器而返回 2。干净低负载、零 qemu 时返回 0。
2. **测量中闸**：只能在开跑前闸刚刚返回 0、随后由本次流程取得唯一所有权的模拟器上启用。允许该模拟器把 load1 推到 12 以上；这一个豁免不得扩散到死 socket、生产 daemon CPU、其它 qemu 或 adb 可用性。
3. **所有权必须机械可证**：至少绑定本次启动得到的 qemu PID 与明确 adb serial；遍历进程只读 PID/comm，不读 argv。观测到的 qemu 集合必须恰好只有该 PID；PID 不存在、comm 不是 `qemu-system*`、出现额外 qemu、adb serial 不处于 `device` 或 `sys.boot_completed!=1`，均返回 2。
4. **生命周期合取**：本次流程对它创建/接管的模拟器负责，在成功、失败、不可判与信号退出路径都关闭它；只准关闭已绑定的本次 PID/serial，禁止 `pkill qemu`、禁止杀既有/未知模拟器。没有所有权证据不得进入测量中豁免，也不得猜测清理目标。

## 二、精确交付物

实现席只允许修改或新增：

1. `tools/perfbase/envcheck.sh`：若选择在此承载测量中模式，只增加上述所有权明确的阶段入口；缺参数、身份不符或量具不可用均 fail-closed 返回 2。默认 `--gate` 语义必须保持严格开跑前闸。
2. `tools/perfbase/run-input-ab.sh`：若选择在此编排两阶段，必须保证顺序是“严格开跑前闸 0 → 启动/绑定本次模拟器 → adb 就绪 → 测量中闸 → 采样”，并安装只清理本次模拟器的 trap；不得靠调用方口头保证顺序。
3. `tools/perfbase/test-envcheck-measurement-emulator.sh`：POSIX sh 聚焦测试。测试临时件只写 `.team/nodes/envcheck-emu/tmp/`，用 PATH 前置假 `uptime`/`ps`/`tmux`/`lsof`/`top`/`adb`/模拟器 launcher 或等价注入面；不得读取真实 tmux、真实 qemu、真实 adb 设备或生产 daemon。
4. `.team/nodes/envcheck-emu/IMPL.md`：记录修前红、修后绿、两阶段接口、完整命令/退出码、假量具操作数、清理证据与未验证项。不得据此宣称真机性能优化成功。

聚焦测试必须真实执行修改后的闸/runner，至少覆盖下列八臂，并逐项核退出码：

| 臂 | 操作数 | 期望 |
| --- | --- | ---: |
| preflight clean | load1=8.50、dead≤10、daemon CPU≤5、qemu 集合为空 | 0 |
| preflight unrelated qemu | load1=8.50，但已有一个 qemu | 2 |
| owned high load | preflight 先为 0；随后仅本次 PID、serial=`device`、boot=1、load1=16.55 | 0 |
| extra qemu | owned PID 之外再有一个 qemu | 2 |
| dead sockets | owned high-load 臂中 dead>10 | 2 |
| daemon CPU | owned high-load 臂中生产 daemon idle CPU>5% | 2 |
| no adb | owned PID 存在但 serial 缺失/offline/非 `device` | 2 |
| unowned high load | 没有合法 owned PID，仅把 load 提到 16.55 | 2 |

测试还必须分别制造测量成功与测量失败，spy 证明两条路径都只清理绑定的本次模拟器；再制造信号退出，证明 trap 同样清理。通过时逐字输出：

```text
ENVCHECK_EMU_EVIDENCE preflight_clean=0 preflight_unrelated_qemu=2 owned_high_load=0 extra_qemu=2 dead_socket=2 daemon_cpu=2 no_adb=2 unowned_high_load=2 cleanup_success=true cleanup_failure=true cleanup_signal=true
```

## 三、硬约束与机械验收

1. `MAX_LOAD=12`、死 socket 上限 10、生产 daemon CPU 5% 判定不得调大、删除或改成警告；空闲机器 load>12 仍返回 2。不得通过伪造较高阈值让闲置机器放行。
2. 测量中只豁免 load 这一项，且仅在同一流程先有严格 preflight=0、随后唯一 owned qemu+可用 adb 的合取成立时。任何其它检查红仍是不可判。
3. 日志必须记录两边操作数：phase、load1/12、dead/10、daemon_cpu/5、owned_pid、observed_qemu_pid 集合或计数、adb_serial/state/boot 与最终分类；不得记录进程 argv、凭据或 `TMUX` 逗号后字段。
4. 测试只用假命令和仓内夹具；不连接/重启生产 daemon `:9900`，不碰真实 tmux、用户会话、真实模拟器/adb、provider profile、`tailnet-test.env`、Shadowrocket plist、`tailscale_keys.bin` 或生产明文日志。
5. 禁止全局清理：不得 `pkill`/`killall` qemu，不得杀不属于本次测量的 PID/serial；清理失败必须可见并返回 2，不能假装测完。
6. 不改 App/server/解析器/历史 JSON，不改 A/B≤1.10、样本数、三夹具四段或稳定 tag/md5 绑定；不增加后台轮询或固定频率子进程。
7. 先红后绿：实现前先运行 `sh .team/ledgers/acceptance/envcheck-emu.sh`，必须因缺少聚焦测试而 exit 1；把原始输出记入 `IMPL.md` 后才修改工具脚本。缺测试是交付红，不冒充功能先验红；功能先验红必须由聚焦测试的 `owned_high_load` 臂在旧实现上实际失败证明。
8. 测试禁止缓存：shell 聚焦测试每次直接执行；若实现确需增加 Go 测试，命令必须带 `-count=1`。不得以旧日志或缓存绿替代本轮执行。
9. 必需机械命令：

```sh
sh .team/ledgers/acceptance/envcheck-emu.sh
bash tools/perfbase/run-input-ab.sh --self-test
python3 tools/archwiki/build_wiki.py --check --strict-t3
```

`.team/ledgers/acceptance/envcheck-emu.sh` 的期望退出码为 0，`unjudgeable_exit_codes=[2]`。实现席自跑只算交付证据，最终由独立判者重跑并选择破坏齿：临时去掉“额外 qemu 拒绝”或“仅 owned PID 可豁免 load”之一，必须改坏红、还原绿；同一坏树的 preflight clean 阳性臂仍绿，排除关闭全部测量的假红。

## 四、四态与合法出口

- **通过 / exit 0**：聚焦测试真实执行八臂；严格 preflight 与 owned-emulator measurement 两阶段均符合表格；成功、失败、信号三条路径都只清理本次模拟器；固定证据行齐全。
- **失败 / exit 1**：量具有效但聚焦测试缺失/空/语法错误，任一臂退出码错误，load 阈值被调大，额外 qemu/死 socket/高 daemon CPU/无 adb 被放行，或清理合取失败。
- **不可判 / exit 2**：shell/bash/基础假量具不可用，仓内夹具目录不可写，测试无法证明修改后的真实脚本被执行，或运行时无法唯一绑定/清理本次模拟器。不可判不是失败或通过，禁止弱化判据放行。
- **不适用**：仅由账本在本格从未派发时表达；一旦派发，未执行起来是不可判，不是不适用。

若只改允许范围仍无法让同一流程机械证明 preflight 先于 owned emulator，或现有启动方式无法提供唯一 PID/serial 与安全 trap，停止扩大范围，在 `IMPL.md` 写清已试、阻点和需要 leader 裁定的接口；如实报不可判。所有 required artifacts 落盘后，正常收工只调用标准 `report_result` 一次；不得 merge、push 或打 tag。
