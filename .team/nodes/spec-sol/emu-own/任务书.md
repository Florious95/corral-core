# t.emu-own.impl — runner 真正启动并绑定测量模拟器

## 一、背景与必读坐标

r11 的测量前严格闸已经通过：load1=7.74、生产 daemon 空闲 CPU=2.3%，说明两阶段环境契约本身可执行。随后 `run-input-ab.sh` 返回 `UNJUDGEABLE qemu ownership count=0`，没有安装 APK、没有产生样本；退出后 qemu 已不在，但宿主 load1 一度升到 27.43。结论不是放宽 envcheck，而是 runner 已触发模拟器启动成本，却没有可靠地把实际 qemu PID 与 adb serial 绑定到本轮，也没有在绑定失败后等宿主恢复到可再次开跑的状态。

本格只修 runner 的“严格 preflight → 启动 → 唯一 qemu 绑定 → adb 绑定 → measurement gate → 采样 → 清理/恢复”所有权链，不改 App/server、A/B 判定或两阶段阈值。开工前按顺序读：

1. 本任务书；
2. `.team/nodes/spec-sol/envcheck-emu/任务书.md` 的 leader 两阶段裁定；
3. `tools/perfbase/run-input-ab.sh` 的 `run_emulator_phase`、PID 枚举、trap 和实际采样入口；
4. `tools/perfbase/envcheck.sh` 的 `--gate` / `--measurement PID SERIAL`；
5. `tools/perfbase/test-envcheck-measurement-emulator.sh` 与 `.team/ledgers/acceptance/envcheck-emu.sh`；
6. r11 的 `MEASURE.md` / `perf-ab.json`，只核上述操作数，不重做真机测量；
7. `.team/ledgers/acceptance/emu-own.sh`。

先执行 `python3 tools/basegen.py emu-own`，只读其影响闭包；不得为本格通读 App/server 大树。

### leader 冻结的不变量

1. 两阶段闸不变：runner 必须先在零本次 qemu 时拿到严格 `envcheck --gate=0`，再由自己调用 launcher。
2. runner 必须从本次启动之后出现的唯一 qemu 取得真实 PID，并与明确 adb serial 一起传给 `envcheck --measurement PID SERIAL`；不得把 launcher `$!`、ambient qemu 或自报 PID直接当成已绑定。
3. 进程识别只读 PID/PPID/comm，不读 argv。`comm` 可能是 basename，也可能是 `/.../qemu-system-aarch64` 全路径；必须先取 basename 再匹配 `qemu-system*`。严格 preflight 已证明 qemu 集合为空，因此启动后唯一新增 qemu 才可归本轮所有。
4. 绑定不到唯一 qemu、adb serial 非 `device`、boot≠1 或 measurement gate 非 0，都返回 2；返回前必须终止并回收本轮启动的进程，确认本次 qemu PID 已消失，并在有界恢复窗口内重跑严格 preflight。不得在刚制造 load 后立刻撒手。
5. 正常测完、失败、不可判和信号退出都只终止本轮绑定的 qemu PID（以及安全回收本轮 launcher 句柄）；禁止 `pkill`/`killall`，禁止杀预存或未知 PID。

## 二、精确交付物

实现席只允许修改或新增：

1. `tools/perfbase/run-input-ab.sh`：修正实际启动、全路径 comm 归一、唯一 PID/serial 绑定、阶段顺序、失败清理与严格 preflight 恢复等待。沿用现有 `EMULATOR_LAUNCHER`、`EMULATOR_AVD`、`EMULATOR_SERIAL`、`EMULATOR_READY_TIMEOUT` 或做最小兼容调整；不得 `eval` 任意参数。
2. `tools/perfbase/envcheck.sh`：默认只读；若 runner 已正确绑定后 `--measurement` 仍因同一全路径 comm 识别为 count=0，允许只同步“comm 取 basename 后匹配”这一处量具修正。不得改阶段语义、阈值或其它检查。
3. `tools/perfbase/test-run-input-ab-emulator-ownership.sh`：POSIX sh 聚焦测试。临时件只写 `.team/nodes/emu-own/tmp/`；用假 launcher、假 `ps`、假 adb、假 envcheck/measurement spy 和假采样依赖，绝不启动真实 qemu/adb/tmux/生产 daemon。
4. `.team/nodes/emu-own/IMPL.md`：记录 r11 红事实、修前聚焦红、修后绿、操作顺序、绑定 PID/serial、各退出码、清理/reap/恢复证据与未验证项。不得写“性能优化成功”。

聚焦测试必须真实执行 `run-input-ab.sh` 的 emulator 所有权路径，至少覆盖：

| 场景 | 夹具操作数 | 期望 |
| --- | --- | --- |
| 全路径 comm 阳性 | preflight qemu=0；launcher 后唯一行 `<pid> /fake/sdk/qemu-system-aarch64`；serial=`emulator-5554`, state=`device`, boot=1 | 绑定该真实 PID，按序调用 measurement，runner 0 |
| r11 count=0 | launcher 已被 runner 启动但就绪窗口内 qemu 集合仍为 0 | exit 2；零 APK install、零采样；本轮进程被回收 |
| adb 不可用 | 唯一 qemu 已绑定，但 serial offline/缺失 | exit 2；本次 qemu 被清理，零 APK install |
| measurement 拒绝 | PID/serial 已绑定，但假 measurement gate 返回 2 | exit 2；本次 qemu 被清理 |
| 信号退出 | 绑定后向 runner 发 TERM | exit 143 或任务书明确的信号码；trap 只清本次 PID |
| 失败后宿主恢复 | 失败时假 load=27.43；清理完成后假严格 gate 先 2 后变为 0/load=7.74 | runner 等到 gate 恢复 0 才结束；若有界超时则仍 2 且日志明确 |

spy 必须证明调用顺序逐字为 `preflight → launcher → qemu_bound → adb_bound → measurement`，并证明 measurement 收到的 PID 是全路径 comm 行中的真实 qemu PID、serial 是 `emulator-5554`。通过时逐字输出：

```text
EMU_OWN_EVIDENCE fullpath_qemu_bound=true bound_pid_passed=true serial_passed=true order_preflight_launch_bind_adb_measurement=true zero_count_exit=2 zero_count_no_install=true zero_count_no_orphan=true zero_count_recovered=true no_adb_exit=2 no_adb_no_orphan=true measurement_reject_exit=2 success_cleanup=true failure_cleanup=true signal_cleanup=true only_owned_pid_killed=true
```

## 三、硬约束与机械验收

1. 不得改 `MAX_LOAD=12`、死 socket 10、生产 daemon CPU 5%，不得取消 preflight 或让已有 qemu 放行；本格不是再次修改两阶段政策。
2. PID 绑定必须来自 runner 实际启动之后的进程事实。launcher `$!` 只有在其 comm 本身归一后是 `qemu-system*` 时才能等于 qemu PID；launcher fork/exec 后 PID 不同则绑定实际唯一 qemu PID。
3. 量具必须记录两边操作数：launcher_pid、qemu 候选 PID+归一后的 comm、候选数/期望 1、owned_pid、serial/state/boot、各阶段 rc、cleanup target、kill/reap 结果、恢复 gate rc 与等待上限。禁止读取或记录 argv、凭据。
4. 所有等待必须有界。绑定/adb 超时返回 2；清理至少确认 owned PID `kill -0` 不存在并回收本轮 launcher。清理后严格 gate 在恢复窗口未回到 0，仍返回 2并报告，不得假绿，也不得留下后台 waiter。
5. 只杀本次 owned PID；禁止 glob PID、`pkill`、`killall`、按进程名全杀或触碰其它 emulator。出现两个 qemu 时归属不可唯一，必须返回 2，不能任选一个。
6. 测试只用仓内假量具，不接触真实模拟器/adb/tmux/用户会话/生产 `:9900`，不读 provider profile、`tailnet-test.env`、Shadowrocket plist、`tailscale_keys.bin` 或生产明文日志。
7. 不改 App/server/解析器/历史 JSON，不改 A/B≤1.10、样本数、三夹具四段、稳定 tag/md5 或 PerfTrace；不增加后台轮询。
8. 先红后绿：先只加 `test-run-input-ab-emulator-ownership.sh`。旧实现上“全路径 comm 阳性”必须能运行并因 ownership count=0 而红；缺测试造成的 acceptance exit 1只是交付红，不代替功能先验红。红原文写入 `IMPL.md` 后才改 runner。
9. 测试禁止缓存：shell 聚焦测试每次直接执行；若确需增加 Go 测试必须 `go test -count=1`。必需命令：

```sh
sh .team/ledgers/acceptance/emu-own.sh
sh .team/ledgers/acceptance/envcheck-emu.sh
bash tools/perfbase/run-input-ab.sh --self-test
python3 tools/archwiki/build_wiki.py --check --strict-t3
```

`.team/ledgers/acceptance/emu-own.sh` 期望 0，`unjudgeable_exit_codes=[2]`。最终独立判者选择破坏齿：临时撤掉 comm basename 归一或把 measurement PID 换回 launcher PID，必须改坏红、还原绿；同一坏树的 `zero_count_exit=2` 和 preflight 阳性对照仍给各自应有结果，排除恒红/恒绿。

## 四、四态与合法出口

- **通过 / exit 0**：聚焦测试真实运行所有场景；全路径 qemu 被唯一绑定，PID/serial 正确传入 measurement；count=0/无 adb/measurement 拒绝都 exit 2且零安装零样本；成功、失败、信号路径只清本次 PID；失败后严格 gate 恢复证据齐全。
- **失败 / exit 1**：量具有效但聚焦测试缺失/空/语法错误，仍出现 r11 count=0，全路径 comm 绑错 PID，调用顺序错误，失败后有本轮孤儿，发生 APK install/采样，或误杀非本次 PID。
- **不可判 / exit 2**：bash/POSIX sh/假量具不可用、仓内夹具目录不可写，测试无法证明真实 runner 路径被执行；实际测量中唯一 PID/serial 绑不上、清理/reap 不能确认或恢复 gate 超时也属于不可判。不可判不得染成失败或通过。
- **不适用**：仅由账本在本格从未派发时表达；已派发但没跑起来是不可判。

若只改允许路径仍无法机械绑定 launcher 产生的真实 qemu，或安全收尾必须扩大到未知 PID，停止扩大范围，在 `IMPL.md` 写清已试、阻点和需要 leader 裁定的启动接口；如实报不可判。required artifacts 齐后，正常收工只调用标准 `report_result` 一次；不得 merge、push 或打 tag。
