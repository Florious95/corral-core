## 3. fresh verify 精确契约

### 3.1 同批 APPARATUS 和 pm 证明

production 不接受调用方 root/contract/manifest/fixture 替换。固定 contract 本身的 bytes SHA-256 由 shell wrapper 锁定；contract 再锁定：

- `APPARATUS.json` bytes SHA-256、schema/mode/created epoch、bundle_id 和 manifest SHA-256；
- 本批 successor10 owned-emulator producer bytes SHA-256。该固定 producer 只在 exact `adb install -r` rc0 且同 serial 的 `shell pm path dev.agentmirror.app` rc0 并返回 `package:` 后才写 APPARATUS；
- real `BUNDLE-MANIFEST.json` 摘要与 bundle/APK identity；
- permanent successor7 impl-bypass fixture 的 Git 稳定路径和摘要。

validator 必须独立重算上述 bytes SHA-256，重验 APPARATUS 为 0600 regular/non-symlink，并要求 `adb_install_exit=0`、三阶段 envcheck=0、fresh owned AVD/PID 已绑定、runner/serial/owned-qemu cleanup 全 true、`forced_kill=false`、`foreign_qemu_touched=false`。manifest 的 bundle_id/APK SHA 必须与 APPARATUS 一致。这是已归档的同批 install/pm/cleanup 证明；verify 不得在 cleanup 后重查 current adb。

permanent fixture 固定文件缺失/不可读为 exit 2，bytes 被篡改为 exit 1。production 还必须运行 `baseline-bundle-successor7-impl-bypass.sh`，用真实 projection 入口重做 green/forged/missing 三臂。旧 temporary successor6 fixture/gate 不得出现在 required 链；它存在或缺失都不得改变结论。

### 3.2 fresh 五件套与机器 schema

fresh verify 席必须原子重写 `.team/nodes/baseline-bundle-verify/` 下五个文件，全部 regular/non-symlink、mode 0600、非空：

- `VERDICT.md`
- `INSTALL.md`
- `RETRIEVE.md`
- `MUTATION.md`
- `VERIFY.json`

`VERIFY.json` 键集必须精确为：

`schema, verdict, verify_batch_id, verified_epoch, apparatus_evidence_sha256, apparatus_bundle_id, apparatus_manifest_sha256, apparatus_install_exit, apparatus_pm_identity_verified, runner_pid_cleanup, serial_cleanup, owned_qemu_cleanup, forced_kill, permanent_fixture_sha256, permanent_bypass_probe_exit, legacy_temporary_gate_used, current_adb_required, evidence_sha256`

精确值要求：`schema=agentmirror.successor11.verify.v1`；`verdict=pass|fail|unjudgeable`；`verify_batch_id` 为本 case 新生成的 64 位小写十六进制身份；`verified_epoch` 不早于 APPARATUS epoch、不超过当前时钟 5 秒且在 contract freshness 窗内；三个 APPARATUS 摘要/身份完全匹配；install=0、`apparatus_pm_identity_verified=true`、三项 cleanup=true、`forced_kill=false`；permanent fixture 摘要匹配且 probe exit=0；`legacy_temporary_gate_used=false`、`current_adb_required=false`。未知键或增加 live-adb 字段均拒绝，不让 live 状态为结论加分。

`evidence_sha256` 键集必须精确映射四个 Markdown 文件到它们的 bytes SHA-256。每个 Markdown 必须各自恰好一次写入以下机器行，值与 `VERIFY.json`/contract 一致：

`successor11_verify_schema, successor11_verify_artifact, successor11_verify_batch_id, apparatus_evidence_sha256, apparatus_bundle_id, apparatus_manifest_sha256, permanent_fixture_sha256`

`VERDICT.md` 末行必须精确为 `verdict: <VERIFY.json verdict>`。每个 Markdown mtime 不得早于 `verified_epoch-5`。因此，旧 `VERDICT.md` 从 `unjudgeable` 只改末行为 pass、不重写其余四件，必须 exit 1；不得把旧语义空洞地涂绿。

### 3.3 四态

- exit 0：contract 和同批 APPARATUS/producer/manifest/permanent fixture 全部摘要匹配，已归档 install/pm/cleanup 事实全绿，permanent 真实三臂为 0/1/2，fresh 五件套全部 0600 且交叉摘要闭合，fresh verdict=pass。
- exit 1：有效事实反证、摘要/身份/固定路径被伪造、任一 fresh 文件非 regular/non-symlink/0600，schema/键集/交叉 hash 矛盾，旧 unjudgeable 只改末行，或 fresh verdict=fail。
- exit 2：固定资产、permanent fixture、fresh 证据或 Python/量具缺失/不可读，fresh 证据超时，或 fresh verdict=unjudgeable。不可判不得折成失败/通过。
- not applicable：successor11 final case 未派发；不运行 production gate，不制造或改写 retained 证据。

## 4. 永久 fake 回归与破坏齿

fake 回归只能在 `.team/nodes/spec-sol/baseline-bundle-successor11/tmp/` 构造纯文件 repo；test mode 只接受 unset/空或精确 `1`，且必须同时持有 exact harness identity。production 出现任一 `SUCCESSOR11_TEST_*` 必须 fail closed。必须覆盖：

1. APPARATUS pass + PATH 中无 adb 的阳性对照为 0；
2. PATH 注入 fake live adb 仍为 0，而 permanent 伪造后即使有 fake adb 仍为 1，证明 live adb 不加分；
3. legacy temporary fixture 缺失为 0，伪造出一份 legacy 文件也不改变 0；
4. permanent fixture 缺失为 2、bytes 伪造为 1；
5. `VERIFY.json` 0644 为 1，缺失为 2；
6. successor10 旧 schema + 旧四文件只把 `VERDICT.md` 末行改 pass 为 1；
7. 非精确 test mode 和 production test override 均为 1；
8. fake `adb/emulator/qemu-system/kill/pkill` spy 全程零调用，production wrapper 结构只挂 permanent successor7 gate，不得再出现 successor6 verify gate。

回归不得运行 production wrapper、真实 SDK/device/process 命令或读取 APK。若以后增加 Go/Gradle 测试，必须分别使用 `-count=1`/`--rerun-tasks`。
