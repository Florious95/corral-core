# 任务书 · t.modeseed · 订阅时播种鼠标模式（修「有时候能点、有时候不能」）

## 一、用户实撞（2026-08-23，最高优先级）

用户装了含输入透传四步的包，真机反馈：

- ✅ 性能没回退（蜂窝 + TS）
- ✅ 点工具调用**能**展开——链路是通的
- ❌ **但是有概率**：「我有时候进 Claude Code，它能够有手指操作的传输，但是有时候却又没有。
  **但是 Grok 的 build 始终都没有。**」

## 二、leader 的归因（⛔ 你要自己核实每一条前提，别照单全收）

**核过的两条事实**：

1. 订阅快照就是 `capture-pane -e -p`（`server/internal/bridge/bridge.go:62`）。
   `-e` 保留的是**颜色/字符属性**，**⛔ 不含 DEC 私有模式**（`\e[?1002h` 那一类）。
2. **订阅时没有任何代码给 `MouseModeTracker` 播种模式**——
   grep `app/core-conn/` 与 `app/app/.../session/` 全空。

**推论**：app 是在**它自己启动时**吐模式序列的。我们订阅是在那之后，
⇒ 那些字节**已经不在流里也不在快照里** ⇒ 我们的 tracker 每次订阅都从 `tracking=0` 开始，
`MouseModeTracker.canEncode()` 返回 false，**一个字节都不发**。

**这同时解释了两个观察**：
- **Claude Code「有时候行」**：它在某些时机（重绘 / SIGWINCH / 重进输入循环）会**重发**模式序列，
  我们碰巧接到就生效。
- **Grok build 始终不行**：它启动时设一次，之后再不重发。

⚠️ **leader 先前还猜过「1002 能用、1003 不能用」，那多半是巧合**——
`MouseModeTracker.apply` 里 1003 会落到 `tracking=1002`，`canEncode()` 照样为 true。
⛔ 不要顺着那条错的线索走。**但如果你核出降级另有问题，照实报。**

## 三、修法方向（tmux 自己知道那些模式）

tmux 暴露 per-pane 的 format 变量：
`mouse_standard_flag`（1000）/ `mouse_button_flag`（1002）/ `mouse_all_flag`（1003）/
`mouse_sgr_flag`（1006）。
leader 就是用它们读出用户那几个 pane 的真实状态的。

⇒ **订阅时让服务端把这几个标志带上，客户端据此播种 `MouseModeTracker`。**

**这一格允许改服务端与协议**（这与用户「留给桌面端」的要求不冲突——
**加字段是增量的，桌面端同样受益**）。但：

1. **向后兼容是硬性的**：老客户端不认识新字段时，线格式与行为**必须与改前一致**
   （参照第 2 步的做法：`encodeDefaults=false`，缺省省略键）。**要有测试断言这条。**
2. **模式会变**：app 运行中可能开关模式。播种只解决「订阅时的初始态」，
   **之后仍靠解析输出流跟踪**。⛔ 不许用播种覆盖掉后续解析到的状态。
3. ⛔ **不许改滚轮/输入的既有通路**（用户点名留给桌面端）。

## 四、复现先红

- **R1**：构造「订阅时 pane 已开 1002+1006、但后续流里没有模式序列」的场景，
  断言**改前 `canEncode()` 为 false、改后为 true**。改前必须红。
- **R2**（1003 场景）：同上但 pane 开的是 1003+1006，断言改后也能编码
  （落到 tracking=1002）。改前红。
- **R3**（兼容）：不带新字段时，`subscribe` 的线格式与行为**逐字段等于改前**。改前应绿。
- **R4**（不覆盖）：播种之后，若流里解析到 `\e[?1002l`（关），
  断言 tracker **跟着关**（⛔ 播种不许把它锁住）。
