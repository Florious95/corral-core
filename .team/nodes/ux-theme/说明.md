## 查清（不猜）

### 1. `termview/` 现在的颜色从哪儿来

改前：`TermSurfaceView` companion **写死**深色默认

- `DEFAULT_BG = 0xFF0D1626`（深蓝黑）
- `DEFAULT_FG = 0xFFE8E8E8`（近白字）
- `themeBgArgb()` / `themeFgArgb()` 直接返回这两个常量，**不读系统 uiMode，也不读 Compose 主题**

ANSI 16 色与 xterm 256 查表也在同一个 companion 里。对照图里紫/蓝/粉/青底标签两边色相一致，正是这条通道——坏的只是 Default 底/字。

`Theme.kt` 的 `brandBackground` 注释写着「终端画布默认底色由 TermSurfaceView.DEFAULT_BG 以同一字面量承载，但不经本 token 引用」——两套色板从一开始就没接线。

### 2. 「用户自己发的消息块」怎么被识别

**不是 App 另标的区域。** Claude Code 在 PTY 里发 SGR `48;5;254`（xterm 灰阶 `8+10×(254−232)=228` → rgb(228,228,228)）。`TermBgCjkAlignTest.realRecapStyleBytesKeepGridAlignedAndLegible` 已经用真实 recap 字节钉过这条。

渲染层只把 `TerminalColor.Indexed(254)` 画成灰。默认底一换：

| 主题 | 整体底 | 254 灰块 | 相对关系 |
|---|---|---|---|
| 浅 | `#F8F9FD` luma≈249 | `#E4E4E4` luma=228 | 白底开灰块 |
| 深 | `#0D1626` luma≈20 | 同上 | 深底开浅块 |

主次关系随默认底反转，**不必改 ANSI 色相、不必在 App 侧打「用户消息」标签。**

### 3. `isSystemInDarkTheme()` 与自绘 View 怎么联动

`TermSurfaceView` 不是 Compose。通路：

1. `SessionScreen` 读 `isSystemInDarkTheme()`，写入 `nightOverride`
2. `TermSurfaceView.themeBgArgb()` 走 `TermPalette.of(isNight())`
3. `isNight()`：有 override 用 override，否则读 `Configuration.UI_MODE_NIGHT_MASK`
4. Activity **没有** `configChanges=uiMode`，系统切深浅会重建；`update` lambda 再灌一次 `nightOverride`
5. `onDraw` 把 `TermPalette.token(dark)` 写进 `contentDescription`（`term-theme-light|dark source=app-theme`），UI 树能断言**数据来源**，写死浅色骗「现在是浅底」会在来源 + 切换两条上红

色值集中在 `TermPalette`（默认底/字、ANSI 16、xterm 256、用户消息块索引 254）。绘制代码不再散落字面量。

## 探针（ui-check.sh）

`.team/nodes/ux-theme/ui-check.sh`：`adb reverse` → 拉 App → 进会话 → `cmd uimode night no|yes` → 采终端 View 像素 + `uiassert.py`。trap 关输入法、把 night 拨回 no。不起 daemon、不碰用户 tmux、不扫 argv。

判据（操作数都打在日志里）：

① 浅色：canvas luma>180，且存在 luma∈[190,242] 的灰块比 canvas **更深**（拒把正文深字当灰块）
② 深色：canvas luma<80，同一灰带比 canvas **更浅**
③ 切换后 canvas 真的变了（luma 差 ≥40）
④ UI 树 `term-theme-* source=app-theme`（数据来源）
