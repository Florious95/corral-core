# 市场定位与同类产品调研

- 对象：本仓库产品（README 定名 AgentMirror，暂名「远程Agent安卓」）
- 调研日：2026-08-20
- 方法：联网检索 + `gh api` / `gh search repos`（只读，未 clone）
- 产物范围：只写本文件。未改 `app/`，未跑 Gradle。
- 写法：每条可复核事实带链接或 `gh` 命令。正文里「我看到的」和「我推断的」分开。

一句话先说结论（判断，不是事实）：

> 这条赛道已经挤。几乎同形的「手机控本机 coding agent」不是空白市场。我们能站住的位置只有一个：**不换运行时、不包装 CLI，把用户已经在 tmux（含私有 socket）里跑着的整支 Agent 舰队，用扫码配对的自托管 sidecar 投到手机上。** 官方入口会吃掉「单 Claude 接着聊」；Moshi/Termius 会吃掉「我会 SSH」；Happy/CC Pocket/Litter 会吃掉「我愿意换启动方式」。剩下的人，是已经有大量存量 tmux 会话、不愿迁移的人。

## 0. 被调研对象（先认准）

本产品不是新的 agent。主机跑 `agentmirrord`（默认监听 9900），sidecar **attach 已有 tmux**（含非默认 socket），Android App 用配对码走 LAN / 内置 Tailscale 远程操控真实 Agent CLI。另有同协议 Web 客户端。许可：仓库根 `LICENSE` 为 Apache-2.0。

来源：

- 仓根 `README.md`
- `requirement-wiki/raw/001-产品命题-tmux镜像范式.md`
- 仓根 `LICENSE`

README 自己写的竞品坐标（产品宣称，不是市场核验）：

> herdr 的多 agent 感知 + moshi 的真实终端保真 + kittylitter 的扫码即连，但以「不动用户的 tmux」为第一原则。

### 1.3 和我们几乎同形的：Heeler 到底做到哪

**我看到的（README + `gh api`）：**

1. 定位原文：「agent console」，不是通用终端。首页按 Host 列出 agent，Blocked 优先。
2. 终端：libghostty（Metal）+ 本机 Composer（先在手机写完再 `agent.prompt` RPC 一次送出）。TUI 快捷键走 PTY。
3. 传输：SSH 到用户机器。RPC 走 OpenSSH `direct-streamlocal` → `herdr.sock`；交互终端 `exec herdr agent attach <pane> --takeover`。
4. 前置：**herdr ≥ 0.7.5 + 本机 OpenSSH Remote Login + stream-local forwarding**。扫码来自 `herdr plugin install ZingerLittleBee/Heeler/plugin`。
5. 推送：Blocked/Done 的 APNs，文档称 E2E，relay 只见 token/IP/密文。Live Activity / Dynamic Island。
6. 明确写 **Not affiliated with the herdr project**。iPhone only，iOS 18+。
7. 仓库 2026-07-18 创建，调研日已 795 commits、TestFlight、刚打 v0.1.0。star 只有 105——**产品完整度远高于社区声量**。

**我推断的：**

- 对「已经在 tmux 里跑了几十个 agent」的人，Heeler **不是即插即用**。必须把运行时换成 herdr（或至少 agent 活在 herdr pane 里）。这正是本产品 README 说的「herdr 范式」。
- 终端保真（ghostty）和「谁 Blocked 了」排序，目前比本产品公开描述更完整。
- iOS 侧「herdr 用户的官方级体验」这个坑，Heeler 已经在填。我们做 iOS 若还是 herdr 伴侣，会正撞；若做 tmux sidecar，才是另一条线。

### 1.4 官方入口（最大威胁）

**Claude Code Remote Control（本机会话的官方镜子）**

我看到的：

- 本机 Claude 继续跑，手机/浏览器只是窗口。与「Claude Code on the web」（云上跑）官方自己划了界。
- 连接：终端里的 URL、QR 进 Claude App、claude.ai/code 列表。
- 安全模型（Help Net Security 转述官方）：本机不开入站端口，出站 HTTPS，流量经 Anthropic API；约 10 分钟断网要重启；**每个 Claude 实例一条 remote session**；**终端必须保持打开**。
- 2026-03 另有「从手机 launch 本机会话」的发布（Boris Cherny 帖，检索到；未打开 Claude 二进制核版本号）。

**Codex / Cursor**

- Codex 手机入口接的是 ChatGPT App 里的 Codex，官方文案是云/远程环境，不是「attach 你电脑 tmux 里的 Codex CLI」。
- Cursor Web/Mobile 是 cloud/background agent + PR，不是本机 TUI。

**官方入口吃掉什么：** 只用 Claude、一次盯一个会话、接受流量过 Anthropic、电脑上那条 `claude` 可以一直开着的人。

**官方入口暂时不吃什么（当前文档能核的边界）：** 非 Claude 的 CLI；同一主机上几十个已有 tmux 会话；team-agent 私有 socket；不想把会话流经厂商 API；电脑合盖只留 daemon/tmux。

### 1.5 开源「Claude Code 手机客户端」

活着且有量的是 **Happy（23k star）** 和 **CC Pocket（1k star）**，加上跨 agent 的 **Litter（2.5k）**。它们共同结构是：

- 主机上多一个 **wrapper / bridge**；
- 手机是 **聊天/审批 UI**（Happy、CC Pocket）或 **agent 客户端**（Litter），不是「扫描你已经在跑的 tmux」；
- 被控对象以 Claude/Codex 为主（Litter 稍宽）。

Happy 的关键句（README）：`run happy instead of claude`，切手机时 **restarts the session in remote mode**。

CC Pocket README 写明：新装 Bridge 的 Claude **不支持** `/login` 订阅，要 `ANTHROPIC_API_KEY`。

其余 GitHub 名带 `claude-code-mobile` 的仓，star 个位数到几十，多数停更。不把它们当有效供给。

Reddit 上有人提 **Catnip**（iOS + GitHub 环境）。`gh search repos "catnip iOS Claude Code"` 与 `"catnip claude-code phone"` 均为空。**不进表。**

### 1.6 纯 SSH/终端：真正的替代品

对「主机已开着、我会 SSH」的人，这条路径今天就能用，不需要本产品：

`手机 SSH App → ssh 到主机 → tmux attach`

活着的供给：

- **跨平台商业：** Termius（2026-08-10 仍更新）。
- **iOS 开源专业向：** Blink。
- **Android 开源：** ConnectBot；新兴 **Moke**（明确拿 Claude Code TUI 当卖点）。
- **iOS 本地壳：** a-Shell（任务点名；它不是远程层，但能 ssh 出去）。
- **agent 特化 SSH：** **Moshi**（iOS+Android，tmux/herdr/Zellij 手势、CJK、可选 hook）。这是 SSH 类里最接近我们场景的。

JuiceSSH：曾是 Android 默认选项，调研日应按 **已退出 Play 主货架** 处理。

Moshi 官网自己问「Why Moshi instead of Claude Code Remote Control?」：Remote Control 只管 Claude 对话；Moshi 给你整台机器 + 多 CLI + 真终端。这和我们的分界类似，但 Moshi 的实现是 **SSH 客户端**，不是 tmux sidecar。

### 1.7 主机侧多 agent 面板

这些解决「桌上怎么管一堆 agent」，默认 **不是手机远程层**：

| 名字 | 和手机的关系 |
|---|---|
| herdr | 运行时本身；手机要另配 Heeler 或 Moshi/SSH |
| Conductor | Mac 工作区；站点提到 mobile，未核 |
| Nimbalyst | 桌面 + 自称 companion |
| vibe-kanban | 本机 Web；手机浏览器理论上能开，不是为手机做的 |
| claude-squad | 本机 tmux TUI |
| VibeTunnel | 把**新包的**终端送到浏览器，手机能用浏览器；iOS 原生未成熟 |

它们和本产品的分界：我们 **不拥有** agent 的生命周期，只镜像用户已经选好的复用器（tmux）。

## 2. 定位

### 2.1 一句话

**卖的是：已有 Agent CLI 舰队的手机/Web 投屏层（tmux sidecar），不是新的 agent，也不是新的复用器。**

### 2.2 和每一类的分界

| 类 | 分界 |
|---|---|
| Heeler / herdr | 它们要 agent 住在 herdr 里。我们 attach **已经在 tmux 里** 的进程，包括私有 socket。 |
| Moshi / Termius / Blink / ConnectBot | 它们卖连接与终端。我们卖 **发现 + 聚合 + 配对**，用户不必会 SSH、不必知道 session 名、不必自己 attach 非默认 socket。 |
| Happy / CC Pocket / Litter | 它们 **启动或包装** 一条 Claude/Codex。我们 **不重新开**，扫描存量。 |
| VibeTunnel | 它要求 `vt` 包一层再映到浏览器。我们扫 tmux。 |
| 官方 Remote Control / Codex App / Cursor Agents | 官方卖 **自家模型的官方会话**（本机 Claude 一条，或云端 Codex/Cursor）。我们卖 **用户自己的多 CLI、多会话、不过对方 API**。 |
| Conductor / Crystal-Nimbalyst / vibe-kanban / claude-squad | 桌上编排。我们是 **人离开桌子之后** 的显示与输入。 |

### 2.3 最尖锐的一问：为什么不直接 Termius SSH 再 tmux？

对会 SSH 的人，**80% 的「看一眼、回一句」Termius（或 Moshi）已经够用。** 不承认这句，定位是假的。

多出来、且能被本产品设计核到的，只有这些（不是「更好用」）：

1. **私有 tmux socket。** 本产品需求写明：大量 agent 不在默认 server 上。SSH 进去敲 `tmux attach` 默认会 **整支舰队隐形**。sidecar 遍历 socket 目录是功能，不是皮肤。
2. **零迁移、零包装。** 不用 `happy claude`，不用把 pane 搬进 herdr，不用 `vt`，不用开 Remote Control。daemon 起来，已经在跑的都在列表里。
3. **舰队导航而不是一个 PTY。** Termius 给你一条 shell；本产品给你按 cwd 聚合的会话列表、收藏、点进去才是终端。用户的痛是「几十个」，不是「不会 SSH」。
4. **单一 App 里的可达性。** README 明确拒绝「终端 App + Tailscale App + SSH 配置」三件套。配对码 + 内置 LAN/tsnet，对不会配 `~/.ssh/config` 的人是启用条件。
5. **会话不经厂商中继。** 对比 Claude Remote Control：官方流量走 Anthropic API。本产品是点对点（LAN 或 tailnet）镜像终端。

如果用户（a）agent 都在默认 tmux、（b）已经熟练 Termius/Moshi、（c）只盯一两个会话——**不该劝他换 App。** 那是 SSH 的客户，不是我们的。

## 3. 优势（只保留能核的）

格式：因为 X，所以 Y。核不成的候选已删。

1. **因为** sidecar 扫描已有 tmux（含非默认 socket），不要求 agent 改启动方式（README / 需求 001），**所以** 已经有存量舰队的人可以当天用，不必把会话搬进 herdr / Happy / `vt`。
2. **因为** 被控对象是用户自己的 CLI 进程而不是厂商云 agent（README；对比 Cursor Agents / Codex Cloud / Claude Code on the web 官方文档），**所以** 本机文件、MCP、私有代码、非 Claude 的 grok/codex/其它 CLI 仍在原处。
3. **因为** 镜像层是终端流而不是「官方聊天 UI」（本仓 `termview` 自绘 SGR/真彩/CJK/alt-screen 是产品事实；官方 Remote Control 用的是 claude.ai/code 窗口），**所以** 走 alt-screen 的 TUI agent 在手机上仍是那块屏，而不是被折叠成聊天气泡。  
   *限制：Heeler（libghostty）和 Moshi/Termius 同样是真终端。这条只对「聊天壳客户端 / 官方 Web UI」成立，不对 SSH 专业终端成立。*
4. **因为** 列表按工程/会话聚合，而不是一个 SSH 窗口（需求 002、README「舰队视角」），**所以** 「多工程 × 每工程一队」可以先扫状态再点进去，不必在手机上记 tmux prefix。
5. **因为** Apache-2.0（根 LICENSE），**所以** 二次分发、闭源衍生、商用嵌入的法律摩擦小于 Heeler（AGPL-3.0）、claude-squad（AGPL-3.0）、Litter（GPLv3）。Happy/CC Pocket/VibeTunnel/herdr 也是 MIT/Apache，**许可不是对它们的优势。**
6. **因为** 配对后走 LAN 或 App 内 tsnet，会话不经 Anthropic/OpenAI/Cursor 中继（对比 Remote Control 官方安全说明、Happy 默认有同步 Server），**所以** 「终端内容不过对方服务器」是可陈述的差异。  
   *限制：选 Tailscale 时，包仍经 Tailscale 网络；这不是「零第三方」，只是「无会话内容 SaaS」。*
7. **因为** 有 Android 原生客户端（本仓 `app/`），**所以** 不依赖 iOS 上的 Heeler/Blink，也不依赖「先装 Termius 再配 key」。  
   *限制：Moshi、Happy、CC Pocket、Litter、Termius、ConnectBot 在 Android 上也有。Android 本身不是独占。*

删掉的候选：

- 「体验更好」——无法证伪。
- 「推送/Live Activity」——Heeler/Moshi/Happy 有公开推送；本产品本调研未核有对等 APNs/FCM 能力，**不声称优势**。
- 「iOS」——没有。
- 「商店分发/星数/品牌」——本产品尚未作为公开竞品出现在 GitHub 搜索里。

## 4. 劣势与真实威胁

### 4.1 官方入口如果做好了，这层还剩什么？

**判断：单 Claude、单会话路径上，官方会把我们压成「挑剔者工具」。**

Remote Control 已经是「本机 Claude + 手机窗口」，和我们最像的官方形态。它会继续补：从手机拉起会话、多会话列表、更快的接通。每补一块，只使用 Claude 的人更没有理由装第三方。

还可能剩下的，全部依赖官方 **故意不做** 或 **做不像** 的：

- 非 Claude CLI（Codex CLI、Grok、其它）同一舰队；
- attach 已有 tmux 而不是「再开一条官方 remote」；
- 私有 socket；
- 终端像素级 TUI 而不是 claude.ai 聊天壳；
- 流量不过 Anthropic。

若 Anthropic 下一步做成「扫描你机器上所有 Claude tmux pane」，我们在 Claude 子集上的价值会接近零。**没有证据他们会或不会做 tmux 扫描。** 见第 6 节。

Codex/Cursor 官方手机入口是云 agent，和本机 tmux **不是同一商品**。它们抢的是「离开电脑还能让模型干活」的预算，会缩小「值得为了看本机会话而装 App」的人数，但不会实现上替代 sidecar。

### 4.2 SSH App + tmux 已经 80%，多出来的 20% 值不值得装？

**判断：对会 SSH 的个人开发者，经常不值得。对「私有 socket + 几十个会话 + 不想配 SSH」的人，值得。中间地带已经被 Moshi 切走。**

更狠一点：2026 年的替代品已经不是「原始 Termius」。**Moshi 在 Android 和 iOS 上都在卖「tmux/herdr + agent 手势 + CJK + Tailscale 文档」。** 我们相对 Termius 的 20%，对 Moshi 可能只剩：

- 扫码配对、不用 SSH 密钥；
- 自动枚举非默认 tmux server；
- Apache-2.0 可审计的专用协议。

如果这三件做不硬，**装一个专用 App 的理由不够。** 用户会继续用 Moshi。

### 4.3 只有 Android，iOS 已有 Heeler，意味着什么？

三件分开的事实：

1. Heeler **不是**「iOS 版的我们」。它绑 herdr，我们绑 tmux。iOS 用户若不肯迁 herdr，Heeler 救不了他；他会去 Moshi/Blink/Happy。
2. iOS 上「手机控本机 agent」**已经有货**：Moshi、Happy、Litter、Heeler、官方 Claude App、Termius、Blink。不存在「iOS 空白等我们去填」。
3. 我们只有 Android，意味着：双机用户（桌上 Mac、口袋 iPhone）会先碰到 iOS 供给；Android 用户才是我们进得去的店。Android 上同样已经有 Moshi / Happy / CC Pocket / Litter / Termius / ConnectBot。

**意味着：平台缺口是增长上限，不是护城河。** 不做 iOS 就放弃了一半手机；做 iOS 就要和已经产品化的 Moshi/Heeler/Happy 正面打，而我们没有商店声誉。

### 4.4 主机常开 + 网络可达，劝退多少人？

**没有调查数据，不能编百分比。** 能核的是：凡是「控本机」的产品都吃同一前提（官方 Remote Control 还要求那条终端不关）。劝退发生在 **品类选择**，不是我们单独的笨。

会直接走云的人：Claude Code on the web、Codex Cloud、Cursor Cloud Agents。他们要的是「笔记本合盖任务还在跑（在别人的机器上）」。这批人 **不是** sidecar 的转化对象。

仍留在本机的人：代码不能出境、MCP 只在本机、已经用 tmux 把任务挂在家里的盒子上。这批人 **接受** 常开主机。我们和 Moshi/Heeler/Happy 抢的是他们，不是云用户。

额外摩擦我们比 Moshi 更重的一点：**必须跑 `agentmirrord`。** Moshi 可以零主机组件（纯 SSH）。多一个常驻进程，会劝退「能 SSH 就不想再装 daemon」的人。这是为了私有 socket 扫描付出的税。

### 4.5 其它硬伤（同样不许写软话）

- **没有公开 star、没有商店页、没有英文界面**（README：当期锁中文）。作为「市场上的产品」几乎不可被搜到。
- **没有** Heeler 级的 Blocked 排序 + APNs Live Activity（本调研未见到对等实现被当作已交付能力）。
- Happy 有 2 万+ star 和双商店；这是分发事实，不是体验评价。

## 5. 结论与建议

### 5.1 该往哪打

只打这一拳：**非侵入的 tmux 舰队投屏。**

具体就是把下面三句做到没法被 Moshi/官方/Happy 随手抄走：

1. **私有 socket 与多 tmux server 一次扫全。** 这是需求里已经写明、SSH 默认路径做不到的。做不硬就没有品。
2. **存量零迁移。** 任何「请用我们的命令启动 agent」都是在把自己变成 Happy。不要做。
3. **配对即连的 Android（+ 已有 Web）。** 对象是「不会/`不愿`配 SSH、但主机上已经有队」的人，尤其是 team-agent 这类私有 socket 用户。

打法上承认客户极窄：不是「所有用 Claude 的人」，是「本机已经有一支 tmux 舰队的人」。窄，才可能活。

### 5.2 不该打（有理由，不是清单）

- **不该打云端 agent / 「离开电脑任务在云上跑」。** Cursor/Codex/Claude-on-web 用整家公司做。我们既没有沙箱也没有模型。碰了就变成三流 Copilot。
- **不该打 wrapper CLI（Happy 路线）。** 和「不动 tmux」直接矛盾。
- **不该把自己做成 herdr。** 复用器是 3 万 star 的独立品类；我们若要求迁移，就丢掉唯一差异。
- **不该用「比 Termius 更强的 SSH 终端」当主叙事。** Moshi 已经在打，且双平台、有商店评分。我们赢不了终端 App 军备。
- **不该现在把 iOS 当主战场。** iOS 上 Heeler（herdr）、Moshi（SSH+tmux）、Happy/Litter（包装/拉起）都在。没有 sidecar 协议的 iOS 端之前，做 iOS 只是减配复刻。后置可以；当主线不行。
- **不该把「官方 Claude 聊天壳更好」当竞品作业。** 官方会赢聊天。我们只守 TUI 像素和多 CLI。

### 5.3 和 README 旧坐标的校正

README 写 herdr + moshi + kittylitter。调研后：

- herdr 仍然是运行时对照，判断成立。
- moshi 已从「iOS SSH」变成 **Android 也在架的 agent 终端**，比 001 写作时更危险。
- kittylitter/Litter 是真东西（GPL、双平台、扫码/发现），但主路径是 **start agent**，不是 attach tmux。扫码即连可对标，生命周期模型不可对标。
