# t.clip · 终端左侧遮挡（078 §1）

## 两个数（先量再改）

| 操作数 | 坏基线（现装包 / 对照图右半） | 修后（本席 installDebug） |
|---|---|---|
| **容器 contentLeft** | `0`（`ViewFactoryHolder` bounds `[0,216][1260,2356]`，画布贴屏幕左缘） | 仍是 `0`（View 没被推出屏幕；**不是布局把第 0 列推出去**） |
| **首列字形起绘 / 墨迹 x** | 橙 `●` `glyphX=0`（贴 clip 边） | `glyphX=21`（8dp 左边距，密度 3 → 24px，AA 后首墨 21） |

补充（橙 `●` 色块，坏基线才量得到）：

| | 高 | 可见宽 | 宽/高 | 左缘 |
|---|---|---|---|---|
| 坏基线 | 47 | 36 | **0.766** | x=0 |
| 完整圆应接近 | ≈47 | ≈47 | ≈1.0 | >0 |

可见宽 < 高且贴 x=0 ⇒ 圆被切成 D。左溢约 `47-36=11px`，与 `drawCentered` 在 `advance>cellW` 时 `(cellW-advance)/2 < 0` 同号。

## 判别：CLIP，不是 LAYOUT_PUSH

- **LAYOUT_PUSHED**：第 0 列格子左缘 `< contentLeft`（网格本身被推出内容区）。
- **CLIPPED**：格子在内容区内，字形起绘 x `< 0`，Canvas 裁掉左半。

现场：格子原点 = 0 = contentLeft（网格钉在 view 左缘，**没被推出**）；`●` 走 `SYSTEM_FALLBACK` + `drawCentered`，`x + (cellPx-actual)/2` 为负，**画在 clip 边左侧被裁**。

`TermSurfaceView.drawCentered` 旧注释自己写了「大于则轻微左出」——col0 的左出就是这次的半个橙点。
右侧已有 `RIGHT_MARGIN_DP=4`，左侧没有对称 inset。

对照图：`.team/issues/shots/07-左侧遮挡与主题不一致.png` 红框。同场复拍：`.team/nodes/ux-clip/01-before-clip.png`。

## 改法

1. `TermLeftEdge`：`LEFT_MARGIN_DP=8`（密度 3 → 24px，盖住实测 ~13px 左溢）、`cellOriginX`、`centeredGlyphX`（钳到 ≥0）、`classify`。
2. `TermSurfaceView`：所有格原点从 `contentLeft` 起；`usableWidth` 扣左+右；居中路径走 `centeredGlyphX`。
3. `DiagLog.record(term-left-edge, contentLeft=… col0Origin=…)` —— 两个操作数都落日志。
4. 单测 `TermLeftEdgeTest`（名字含 `TermLeftEdge`）：onDraw 格子原点 == contentLeft > 0；旧居中公式为负 / 新公式 ≥0；CLIP vs LAYOUT 三分。

未动主题/默认色（078 §2 归 t.theme）。未动 073/075/076。
