# 064 悬浮窗抓屏：可行性结论

- 契约：`requirement-base/entries/064-会话内悬浮窗展示节点总览实时流.md`
- 量具：tmux **3.6a**；隔离 server `/tmp/ov-advisor/sock`（`unset TMUX`，`list-sessions` 自检为 `user`，inode ≠ 用户 `/private/tmp/tmux-501/default`）
- 默认选项（本机实测，不是文档猜想）：`window-size latest`，`aggressive-resize off`，`default-size 80x24`，`status-interval 15`

**总判：可行，且能做到零尺寸影响。** 路径不是 `capture-pane`，是「专用 scratch 会话 + 专用客户端 PTY + 周期性 `refresh-client`」。不 attach 任何用户会话。做不到零影响才该 blocking——本次实测做得到，不升级。

禁止降级成自绘。悬浮窗流与二级列表流分开；零订阅者零客户端。

---

## ① choose-tree 跑在 pane 里时，capture-pane 能否抓到它画的内容？

**不能。** 即便 pane 已是 `pane_in_mode=1 mode=tree-mode`，且有客户端正在看这个 pane，`capture-pane -p` 仍是空白（30 行空行，nonspace=0）。

choose-tree 画在**客户端 tty** 上，不进 pane 卷轴。`Ctrl-B w` 覆盖层与 `choose-tree` 把 pane 置入 tree-mode，对 capture-pane 是同一类：抓 pane 抓不到。

**能抓到的是专用客户端的 PTY。** `TERM=xterm-256color` 下 `tmux -S $SOCK attach -t scratch`，PTY 里出现原生树线与标题：

```
(0) - user: 2 windows
(1) ├─> - 0: u0-: "IDLE-TITLE-AAA"
(2) │   └─> 0: sleep*: "IDLE-TITLE-AAA"
```

命令：

```
tmux -S $SOCK choose-tree -t scratch:0.0
tmux -S $SOCK list-panes -t scratch:0 -F 'in_mode=#{pane_in_mode} mode=#{pane_mode}'
# → in_mode=1 mode=tree-mode
tmux -S $SOCK capture-pane -p -t scratch:0.0 | wc -c
# → 仅换行，无树
# 对照：读 attach 在 scratch 上的客户端 PTY → 有 ├─ / 会话名 / 标题
```

实现：为 scratch 单开客户端，抓它的 tty 字节，不要走 `capture-pane`。

## ② 是否随 pane 标题变化自动重绘？

**不会自动重绘。** 动画不能指望标题变化自己驱动。

实测（客户端已在 tree-mode，只改 `user:0` 的 `select-pane -T`，不按键）：

| 动作 | PTY 入站 |
| --- | --- |
| 连续改标题 `⠋/⠙/⠹/⠸ WORK-TITLE-N`，每次等 0.8s | 3/4 次 0 字节；一次有数据属偶发，**不能当不变量** |
| 改标题后空等 5s | **0 字节**，未见新标题 |
| 3s 内无操作 | **0 字节**（无心跳重绘） |
| `refresh-client -t <client>` | 立刻重绘，新标题出现（`ZZZ-AFTER-REFRESH`） |

`status-interval` 实测为 15，与转圈无关。

**实现必须自己 `refresh-client`。** 转圈 = 标题在变 + 我们按节拍刷新客户端，不是 tmux 主动推帧。

## ③ 专用会话的客户端对其它会话尺寸是否零影响？

**对其它会话：零影响。对 scratch 自己：客户端行列必须与该窗口已有行列一致，否则 scratch 会被改（用户窗仍不动）。**

`window-size` 默认 **`latest`（3.6a 实测）**，按**窗口**算，不是全 server 一把尺子。

| 操作 | scratch | user:u0 | user:u1 |
| --- | --- | --- | --- |
| 无客户端，初值 `-x/-y` | 100×30 或 80×24 | 80×24 | 80×24 |
| 40×12 客户端 attach **scratch** | 变为 40×12 | **80×24** | **80×24** |
| 30×10 客户端 attach **user** | 不变 | 视焦点窗 | **u1 → 30×10**（危害） |
| 80×24 客户端 attach 已是 80×24 的 scratch | **80×24** | **80×24** | **80×24** |
| `window-size smallest` + 小客户端只挂 scratch | user 仍 80×24 | 80×24 | 80×24 |
| 客户端离开 | user 仍不动；scratch 停在 last size | | |

命令摘要：

```
tmux -S $SOCK show-options -g window-size    # window-size latest
# TIOCSWINSZ 40x12 + attach -t scratch
tmux -S $SOCK list-windows -a -F '#{session_name} #{window_name} #{window_width}x#{window_height}'
# scratch 变，user 不变
# attach -t user + 30x10 → user 窗被压小 —— 所以禁止挂用户会话
```

铁律：

1. 只 `attach -t scratch`，永不 attach 用户会话。
2. 客户端 winsize = scratch 窗口当前 `#{window_width}x#{window_height}`（先 `resize-window` 钉死再 attach）。
3. 建议 scratch 窗 `window-size manual`，与用户窗隔离。

此路径满足「打开/关闭悬浮窗，用户所有真实窗口行列一个都不变」。本次**不发 blocking**。

## ④ 抓屏频率 / 动画 / CPU

转圈来自标题里的盲文点阵（约 8～10 帧一圈），加上 ②，必须主动刷新。

实测：`refresh-client` 循环约 15 次/秒、持续 2s，隔离 server `ps -o comm=,%cpu=`（**无 argv**）从 `tmux 0.0` 到 `tmux 0.9`；PTY 约 67KB/2s。3s 空闲 0 字节、0 CPU。

| 频率 | 观感 | 代价 |
| --- | --- | --- |
| 2 Hz | 转圈明显顿 | 极低 |
| **8～10 Hz（建议 10 Hz，100ms）** | 盲文一圈约 1s，能看出在转 | 按 15 Hz≈0.9% 外推，个位数 CPU |
| 15 Hz+ | 更顺，收益小 | 字节量线性涨 |

**建议：有订阅时 10 Hz `refresh-client` + 读 PTY；帧哈希未变则不推（省无线）；零订阅者拆掉客户端，一次 tmux 客户端都不留。**

依据：用户要「动态转圈」；10 Hz 盖住常见 spinner；CPU 在本机 15 Hz 仍 <1%；关掉必须回零。

## 实现要点（给 t.srv，不自绘）

1. 隔离或与用户**同一 server、不同 session** 的 `scratch` 窗（choose-tree 列整个 server，内容不缺）。
2. 有订阅才 `attach -t scratch`（独立 PTY，winsize 对齐），`choose-tree`，每 100ms `refresh-client`，从 PTY 取一帧。
3. 推独立帧（建议 `overlay_subscribe` / `overlay_unsubscribe` / `overlay_frame`），与 `level2_*` 分订。
4. `overlay_frame` 必须非空；若干秒内至少两帧内容不同（标题在变或 refresh 带出动画）。
5. 只读：不往用户 pane `send-keys`。
6. `size-invariance.sh` 是尺寸门：开路径前后逐窗 `#{window_width}x#{window_height}` 必须全等。
