# 062 三态规则方案

- 契约：`requirement-base/entries/062-状态三态规则与二级菜单缓存优先.md`
- 读者：`t.srv`（探测器 + 六条 TestL2*）/ `t.app`（缓存优先，本方案只钉判定，不代写 UI）
- 探针：同目录 `probe-tristate.sh`（现在必须红：空闲标题会被判成 unknown）

## 0. 根因（不是缺 Grok 符号）

061 的 `classifyPaneTitle`（`server/internal/api/level2.go`）只认两枚工作/空闲符号，**其余一律 unknown**，包括「第一个字符是普通字」：

```
◐ U+25D0 → working
✳ U+2733 → idle
空标题 / 其它首字符 → unknown    ← 病根
```

真机：Grok 空闲是 `<上次任务摘要> - grok`，无前导符号 → 全员未知。Claude Code 空闲若暂时没打出 `✳`、标题以字开头，同样被染成未知。工作中那一支（真有 `◐`）是对的。

062 补上缺失的那一态：**没有任何前导符号 ⇒ 空闲**。未知只留给「有一个我不认识的符号」。

## 1. 三态（取代 061 二分）

| 标题前导 | status | 说明 |
| --- | --- | --- |
| 某探测器认作工作，或共享层看到已知工作符号 | `working` | 进行中 |
| **没有任何前导符号**（空标题，或首个非空白字符是字母/数字/字） | `idle` | **新增，修复核心** |
| 有前导符号，且无探测器认领 | `unknown` | 日志必须有 `codepoint=U+XXXX` + 完整原始 `title` |

未知必须稀有。把「没看到符号」记成未知 = 把正常态染成异常态。

**禁止**用摘要正文判活。Grok 空闲标题会留下上次任务摘要。

## 2. 模块形状（用户 2026-08-18：一 CLI 一文件）

```
server/internal/api/
  l2status.go              共享层：注册表 + 三态兜底。禁止出现 grok/claude 等 CLI 字面量
  l2status_test.go         TestL2NoGlyphIsIdle / TestL2UnknownGlyphOnlyWhenGlyphPresent
  l2detect_claudecode.go   只认识 Claude Code 符号
  l2detect_claudecode_test.go  TestL2ClaudeCodeDetectorWorking / TestL2ClaudeCodeDetectorIdle
  l2detect_grok.go         只认识 Grok 符号与标记
  l2detect_grok_test.go    TestL2GrokDetectorWorking / TestL2GrokDetectorIdle
```

接新 CLI = **新增一个探测器文件 + 一个测试文件**。不许改共享层，不许改别的探测器。

`level2.go` 的 `classifyPaneTitle` 改成调用共享层；删掉文件里那两枚写死的 `◐/✳` 常量（否则 Claude 符号又耦合进共享扫描循环）。

### 共享层（不认识任何具体 CLI）

```
classify(title):
  for d in detectors:
    if st, claimed := d.Match(title); claimed: return st
  r = 第一个非空白 rune（全空白/空串 ⇒ idle，known=true）
  若 r 不是「前导符号」⇒ idle          // 字母/数字/Lo 等字文
  否则 unknown，并 log codepoint+title  // 有符号但无人认领
```

「前导符号」= 不是 Letter、不是 Number（用 `unicode.IsLetter` / `IsNumber`，**不要**在共享层写死盲文区段或 `◐`）。盲文是 Symbol，共享层会当成「有符号」；Grok 探测器先认领才变成 working。拆掉 Grok 探测器后，盲文应变回 unknown，而不是 idle。

机械门（t.srv 应自带）：`l2status.go` / `l2status_test.go` 里 `grep -qi 'grok\|claude'` 必须空。

### Claude Code 探测器

| 输入 | 判定 |
| --- | --- |
| 首个非空白 ∈ `◐◓◑◒`（U+25D0 / 25D3 / 25D1 / 25D2） | 认领 `working` |
| 首个非空白 = `✳` U+2733 | 认领 `idle` |
| 其它 | 不认领 |

### Grok 探测器

| 输入 | 判定 |
| --- | --- |
| 首个非空白 ∈ U+2800–U+28FF | 认领 `working` |
| 标题含 `" - Thinking - "` 或 `" - Waiting for response"` | 认领 `working`（即使没有盲文前导） |
| **无前导符号** 且以 `" - grok"` 结尾 | 认领 `idle` |
| 其它 | 不认领 |

实测样例（契约 062 §三，探针用同样形状）：

- 工作：`⠼ - Waiting for response… - 修滚动摘要`（`⠼` = U+283C）
- 空闲：`修滚动摘要 - grok`

## 3. 具名测试（账本，必须真跑 PASS）

| 测试 | 断言世界 |
| --- | --- |
| `TestL2GrokDetectorWorking` | 上表工作样例 → 探测器认领 `working` |
| `TestL2GrokDetectorIdle` | 上表空闲样例 → 认领 `idle`，**不是** unknown；摘要里即使有「Thinking」字样的任务名也不许据此改判（摘要 ≠ 标记） |
| `TestL2ClaudeCodeDetectorWorking` | `◐…` / 同族 → `working` |
| `TestL2ClaudeCodeDetectorIdle` | `✳…` → `idle` |
| `TestL2NoGlyphIsIdle` | 共享层：`修滚动的 bug`、`hello`、空串 → `idle`，且共享源码无 CLI 字面量 |
| `TestL2UnknownGlyphOnlyWhenGlyphPresent` | `※…` 或 `?…`（有符号、无人认领）→ `unknown`，日志含 `U+XXXX` + 完整 title |

061 已有的 `TestL2UnknownGlyphStaysUnknown`（`?l2-unknown-glyph-probe`）应继续绿：`?` 是前导符号。若有测试把**空标题**当成 unknown，按 062 改成 idle。

## 4. 探针（本目录 `probe-tristate.sh`）

真起隔离 daemon + 隔离 tmux（`AGENTMIRROR_E2E_DISCOVERY_SOCKET_DIRS`，不听 9900，不扫用户 tmux），订阅 `level2_frame`，用真实 pane 标题驱动三条：

1. Grok 空闲标题 → `status=idle`（当前实现会给出 `unknown` ⇒ **整探针红**）
2. Grok 工作标题 → `status=working`
3. `※` + 唯一 marker → `status=unknown`，且 daemon 日志同时有该码点与完整标题

文件存在 / 符号存在不算绿。

## 5. 二级缓存优先（062 §四，交给 t.app）

进入二级立即画上一次列表，后台再订；新帧原地替换。只有该工作区从未缓存才允许空态。可机械口径：进入到首帧有内容之间，不得出现空列表帧。本探针不覆盖这一条。
