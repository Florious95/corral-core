## 计时边界（真机可复现）

`TermSurfaceView` 继承 `android.view.View`，**不是** SurfaceView。

| 字段 | 含义 |
|---|---|
| `dt_lock_us` | 恒 `-1`。没有 `lockCanvas`。 |
| `dt_post_us` | 恒 `-1`。没有 `unlockCanvasAndPost`。 |
| `surface=view` | 哨兵：这条路径不是 Surface 提交。 |
| `dt_us` | `onDraw` 方法入口→出口（含 `super.onDraw`）。**不含** 返回之后的 HWUI 合成 / GPU。 |
| `dt_super_us` | `super.onDraw` |
| `dt_chrome_us` | `publishThemeChrome` |
| `dt_clear_us` | 整画布一次 `drawRect` 铺默认底 |
| `dt_lines_us` | 逐行 `drawLine`（铺格 + drawText + 几何） |
| `dt_body_us` | chrome + clear + lines（我们自己的 CPU） |

p95 环只收 `textDraw>0` 的稳态帧，丢掉前 10 帧 warmup；空屏走 `source=onDrawEmpty`，不进 p95。10s 窗口 `[term-draw]` 上限仍是 **12**（1Hz 摘要）。n≥120 才是稳态。

## 结论

1. 计时边界正确：`View.onDraw` 方法体，没有 lock/post。
2. 62ms 是模拟器冷首帧。稳态 3–8ms，已在半帧（8000µs）内。
3. **跳过默认底不是普遍收益**：d480 驱动复跑 −56%；**d440 驱动复跑 +2.3%，无改善。** 本席自跑的升降都不当结论。
4. r8：d480/d440 的 `outside_us`（10–35ms）都 **大于** `dt_us_p95`（5.4–7.3ms）⇒ 瓶颈在 `onDraw` 返回之后。
5. **不再加绘制优化。** 假瓶颈。

## 风险

- 真机尚未导出：用户看 `[term-draw]` 的 `n` / `dt_us_p95` / `dt_lines_us_p95`，以及 gfxinfo 导出旁证。
- 被测屏是空格铺满的会话。彩色 TUI 的 `dt_lines` 会更高，字段仍适用。
- 083 §0：模拟器 gfxinfo 绝对值无渲染分辨力；本轮用它只证明「比 onDraw 墙钟大」，不当「有多卡」。
- 085 / 083 未动。无遮掩手段。
