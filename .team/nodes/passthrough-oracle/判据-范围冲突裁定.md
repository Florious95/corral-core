# 判据-范围冲突裁定：t.pt-impl 直通输入的 write 范围

- 顾问：r.advisor
- 关联任务：t.pt-oracle（判据）/ t.pt-impl（实现）
- 触发：dev-keybar 施工中发现「每键直通」wire 级实现需要越出 write 范围
- 日期：2026-08-15
- 状态：已实证，待 leader 裁定扩权

## 问题

判据 S1-S4 是结构检查（bridge TypeKeys 原语 / keys backspace 映射 / VM 发送只提交 /
屏不累积），在 t.pt-impl write 范围（bridge/ + protocol/ + session/ + test/）内可全绿。
但「每键文本直通 + 删除键直通 + 发送只提交」要 **wire 级真通**，需要动范围外文件。

## 通道实证（r.advisor 逐一核实，非猜）

1. **「不加 Enter 注入」wire 通道已存在**：协议 `Input.Keys []Key`（`server/internal/protocol/frames.go:185`）
   → handleInput Keys 分支（`server/internal/api/ws_handler.go:227-246`）调 `br.SendKeys` **不加回车**
   （bridge.SendKeys，bridge.go:271）。这是 R-1 快捷键条（017）留下的行为先例。
2. **闭集只有 7 键**：`server/internal/protocol/keys.go` 与 App `conn/Keys.kt` 都是
   esc/ctrl_c/tab/up/down/left/right。**没有任意文本字符键、没有 backspace** →
   每键文本、删除键无法用现有 Keys 通道表达。
3. **Text 路径必 +Enter**：handleInput 里 `i.Text != ""` 一定走
   `Inject` / `InjectWithAttachment`（bridge.go，send-keys -l + Enter）。协议层**没有**
   「text 不加回车」的开关字段。
4. **App 侧无逐字符通道**：`ConnectionManager` 只有 `sendInput(text, …)`（整条注入）与
   `sendInputKeys(闭集)`，没有 per-keystroke 发帧方法。

## 结论

dev-keybar 的判断**正确**：wire 级「每键直通 + 删除键直通」必然要动范围外文件。
这是**任务定义与 write 范围的冲突**，需 leader 扩权，不是他漏看了既有通道。

## 建议扩权最小集（已报 leader）

- `server/internal/api/ws_handler.go` —— handleInput 加「仅键入不回车」分支
- `app/app/src/main/java/dev/agentmirror/app/conn/Keys.kt` —— InputKey 加 backspace
- `app/app/src/main/java/dev/agentmirror/app/conn/ConnectionManager.kt` —— 新增逐键发帧方法
- `server/internal/protocol/frames.go` **已在 write 范围内**，协议字段改动无需扩权

## 对判据的影响

判据 S1-S4 是结构检查，不依赖 api/ 与 conn/ 的具体实现。无论 leader 裁定扩权（A）
还是降级为手测（B），判据本身不变；扩权后 dev-keybar 的实现仍以 S1-S4 为验收。
