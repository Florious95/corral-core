## 字段怎么加的、base64 用哪个 API

`bytes` 用 `ByteArray? = null` + 全局 `encodeDefaults = false`（`CodecErrors.kt:31-33`），缺省省略该键，不会出现 `"bytes":null`。

**不用 kotlinx 默认 ByteArray 编码器**：它会把字节编成 JSON 数字数组（改后第一轮 R1 原文：`Element class kotlinx.serialization.json.JsonArray is not a JsonPrimitive`）。服务端 `[]byte` 的 JSON 是标准 base64 字符串。

线格式 API：`java.util.Base64.getEncoder()` / `getDecoder()`（RFC 4648 StdEncoding，带 padding，非 URL-safe、不插换行），对齐 Go `encoding/json`。R1 用含 `0x03`/`0x1b`/`0xfb` 的真实字节：编码 → `getDecoder()` → `contentEquals` 原数组；并断言 wire 字符串等于 `getEncoder()` 且不等于 `getUrlEncoder()`。

## 上限怎么处理的

客户端硬闸 `ProtocolVersion.MAX_INPUT_BYTES`（1 MiB）：`InputFrame.validate` 超限拒编码；`sendRawBytes` 超限或空载荷直接 `false`，不拼超大帧。服务端仍有自己的 `too_large`；本格不改 ack 节奏。
