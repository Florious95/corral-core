# 任务书 04 · 异源评审席（三个评审格共用）

你与实现席**异源**（他们 grok，你 Opus 5）且**零上下文**。你的价值在于**不采信自报**。
产出方自证不算数——凡是「他说跑绿了」，你自己重跑一遍再说。

## 通用交付物：`.team/nodes/pb-rv-<面>/裁定.md`

判据 `tools/perfbase/judge-verdict.sh` 会核这份文件的**形式**（不重做你的事实判断）：

- 必须有**恰好一行** `status=pass` 或 `status=rework` 或 `status=inconclusive`（顶格，独占一行）。
- `status=pass` 时正文⛔ 不许出现「没核到 / 未核 / 查不清 / 跑不起来 / 没跑到 / blocked /
  inconclusive / 不可判」——嘴上 pass 身体 blocked 是形式绿最常见的形态，判据会当场拦下。
  真判不出就写 `status=inconclusive`，**那是合法终态，不是没干活**。
- 必须有「证据」节，且引用至少一处 `文件.kt:行号` 或命令输出原文（`$ ...` / `rc=` / `exit code`）。
  ⛔ 纯印象裁定不收。
- `status=rework` 必须**逐条**写：问题 / 证据 / 期望。含糊的 rework 会让实现席空转一轮。

## t.rv.instr：判仪表（面 = `instr`，落 `.team/nodes/pb-rv-instr/裁定.md`）

三条主线，各自要有独立证据：

1. **关时真的零成本**——去证明它**有**成本：调用点在开关关掉时是否仍构造参数对象 /
   拼字符串 / 装箱 / 建 lambda；`first_draw` 的 glyph 统计是否在 onDraw 里做了 O(rows×cols) 遍历；
   `layout_settled` 是否起了常驻定时器或常驻协程（静默经济红线：空闲 CPU 趋近 0）；
   `DiagLog.record` 持锁从绘制线程调用会不会阻塞；打开链路上有没有新增同步 IO。
2. **链路完整性与可算性**——判据是那句：**光看导出的日志就能算出每段耗时，并判断出
   「该做而没做」还是「做了但做错了」**。去找反例：从收藏页进 / 断线重连后进 / 旋转后重进
   会不会漏事件；快速连点两个会话 `open_id` 会不会串；「打开后立刻打字」时 `layout_settled`
   会不会永不触发或提前触发；哪些事件只带判决没带操作数。
3. **单测是不是形式绿**——`perfTrace_关闭时零行` 有没有真把开关关掉；
   `..产出八事件..` 是不是绕过真实链路直接手调了八次 `PerfTrace.ev`（那等于没验接线）；
   断言是不是只做 substring 包含而没核字段值与单调性；有没有被 `@Ignore` 或被排除出 task。
   **自己重跑** `./gradlew :app:testDebugUnitTest :terminal:test` 并把退出码写进证据。
   服务端同理跑 `go build ./... && go test ./...`。

## t.rv.base：判基线（面 = `base`，落 `.team/nodes/pb-rv-base/裁定.md`）

基线是「此后一切工作的地板」，假地板比没地板更坏。查：

- 三夹具是否各 ≥10 次**冷点开**（每次真的 force-stop 重启了 app，还是连点了 10 次）；
- 数是不是**真从 PerfTrace 日志**来的——⛔ 用户明令不许识图/取帧，去 `.team/perf/raw/`
  核原始 logcat 段落对得上统计值；raw 缺失或对不上 ⇒ rework；
- **有没有剔除极端值**（用户明令不许剔除，只许列进 outliers）；p95 的算法对不对；
- 环境自证是否齐（隔离 socket 自检输出、夹具 pane 的 comm、daemon 端口与 state dir）——
  **⛔ 一旦发现动了用户真实 tmux 或点了真实舰队会话，直接 rework 并在裁定书头一行标红**。
