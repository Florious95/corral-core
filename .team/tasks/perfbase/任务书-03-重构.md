**APP 的全部东西从 corral-core 剥离出去**；引用方式构建出的 APP 性能**不低于任务二基线**。

## t.core：仓内模块切分（本格只做这一步）

在 `app/` 里拆出三个 **纯 JVM/KMP** Gradle 模块，`app` 模块只剩壳：

| 模块 | 装什么 |
|---|---|
| `:core-protocol` | 帧编解码 / 协议类型（对应 server `internal/protocol` 的客户端侧） |
| `:core-terminal` | 终端模型：TerminalEmulator、快照与增量应用、滚回、Style/Cell/Grid |
| `:core-conn` | 连接状态机：auth / 订阅 / 重连策略 |

- ⛔ 三个核模块**不许**上 `com.android.*` 插件、⛔ 源码不许 `import android.` / `import androidx.`
  （判据 `tools/perfbase/judge-core-split.sh` 逐条查）。
- 现有 `:terminal` 模块已经是纯 Kotlin/JVM：**优先把它并进 `:core-terminal` 或直接改名复用**，
  ⛔ 不许另起炉灶再抄一份（本仓最常见的垃圾就是隔几个文件重写一份）。
- **一次只挪一个模块**，每挪完跑一次全量单测。出现红立刻回退该步（回炉纪律：回退作分析）。
- 迁移**只搬不改**：⛔ 不许顺手重构被搬的代码、不许改包名以外的逻辑。改了逻辑就分不清
  性能回退是切分引起的还是改逻辑引起的。
- PerfTrace 的打点跨模块了怎么办：核模块里需要打点的位置，用**接口回调/函数引用**由 app 壳注入，
  ⛔ 核模块不许 import `android.util.Log`。八个事件名与格式不许变（任务二的量具依赖它）。

## t.repo：引用式构建暂存件（⛔ 席位不许推远端）

在 `.team/staging/corral-app/` 造出**本地暂存的独立工程**：

- app 壳（Activity / Compose UI / TermSurfaceView 绘制层 / 资源 / manifest）整体搬过去；
- 用 **Gradle composite build**（`includeBuild` 指回本仓 `app/`）引三个核模块——先用①，够用不升级到 maven；
- `.team/staging/corral-app/迁移清单.md`：**逐条**列「搬了哪个文件/目录 → 去了哪里 → 为什么」，
  以及**还留在 core 里的 Android 残留**（如果有，明写，⛔ 不许说「已全部剥离」而实际没有）；
- 判据 `tools/perfbase/judge-repo.sh` 要求 `./gradlew :app:assembleDebug` 在暂存工程里绿并产出 APK。
- ⛔ 不许 `git push`、不许动 `tools/mirror-pr*.sh`、不许碰远端仓库。推送与建 PR 是 leader 的动作
  （CLAUDE.md「一事一PR一闭环」）。图标等 UI 资产迁移遵守 093 §2：**只用 Provider 原生厂家官方图标**。
