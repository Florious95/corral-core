# 073 · 会话身份跨 socket 冲突：多个 leader 同名 `claude_code`，收藏一个全中、只关联一个

- 日期：2026-08-19
- 来源：用户实测
- **修正**：067 §2「收藏的身份只能用 tmux 结构字段（session_name / window_index / window_name）」——
  **这条是我（leader）写的，它漏了 socket，本条是它的直接后果。**

## 1. 现象（用户原话）

> leader 的会话名字一直是 claude code，导致多个工作目录 leader 都是这个名字，
> 一个 leader 点击收藏，全部 leader 都点击收藏，收藏列表只有一个，且点进去，
> 是左上角工作空间的会话

三个症状，**同一个根**：

1. 多个工作区的 leader 会话**显示为同一个名字** `claude_code`
2. 收藏其中一个 ⇒ **全部同名会话都变成已收藏**
3. 收藏列表里**只有一条**，点进去落到**第一个工作区**的那个会话（错的那个）

## 2. 根因（两层，必须都修）

### 2.1 身份键漏了 socket —— 契约缺陷，我的责任

067 §2 规定收藏身份用 `session_name / window_index / window_name`。
**这三者在不同 tmux server（不同工作区）之间会完全重复**：
每个工作区的 leader 都是同一套值 ⇒ **键冲突**。

⇒ 症状 2（一个收藏全中）与症状 3（只有一条、跳错）都是键冲突的必然结果，不是两个 bug。

🔴 **修正**：身份键**必须含 socket**（服务端造 `ref` 用的就是 `Socket + \x1f + PaneID`，见 `session.go:23`）。
**收藏键与 `ref` 必须同源**——⛔ 不许收藏自己拼一套键，那正是两套身份漂移的起点。

**判据 A-fav-uniq**：两个不同工作区各有一个 `window_name=claude_code` 的会话，
收藏其中一个 ⇒ **另一个必须仍是未收藏**；收藏列表**两条**（各收藏一次后）；
点每一条**分别落到各自的会话**。
🔴 此条须先在当前实现上**验红**（现在必红）。

### 2.2 显示名不可区分

所有 leader 会话都显示 `claude_code`，用户在列表里**无法分辨哪个是哪个工作区**。

**要求**：同一个列表内**不得出现无法区分的重名**。
名字可能是中文（用户明确提到），⇒ ⛔ 不得做 ASCII 假设、不得截断到不可辨认。

**判据 A-name-distinct**：一级/二级/收藏三处列表中，任意两行的展示名 + 副标题组合**必须可区分**。
⛔ 判据不能只断言「名字非空」。

## 3. 边界（先查清再改，不要猜）

「正确的名字」从哪来，**尚未确定**，交给任务去查：候选是 `window_name` / `session_name` /
`pane_title` / 工作区名限定。⛔ **不得用标题字符串当身份键**（062/067 的既有铁律不变）——
标题只能用于**显示**，身份仍走结构字段 + socket。

## 4. 不得倒退

- 收藏闭环（点星→实心→收藏栏出现→点它进会话）
- 一二级白名单过滤（068）、三态状态（062）、底部标签栏（067 §4.1）
