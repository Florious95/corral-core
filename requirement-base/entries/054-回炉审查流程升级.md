# 054 回炉审查流程升级（基于失败 diff 反向推）

- 状态：已裁定（流程类）
- 类型：工作流 W-05
- 出处：用户 2026-08-12 原话「回退重做的时候，需要开新角色对这个 diff 进行审查，基于现象反向推」

## 升级内容

回退重做时，**不从零分析，而是基于失败 diff 反向推**：

1. 回退代码。
2. **开审查席看回退的 diff**——分析「改了什么、为什么没修好」。
3. 审查席输出具体原因（不是「可能」，是「因为 X 所以 Y」）+ **根因探针**（能命中根因的测试/检查）。
4. **回退后跑探针**：命中 → 诊断正确，继续；不命中 → 诊断错误，重新分析。
5. 出 MVP → 改代码。
6. **修完后跑探针**：不再命中 → 修复有效；仍命中 → 修复无效，没改到点上。

## 原则

失败的 diff 是信息不是垃圾。每次失败都缩小下次搜索范围。根因探针是修复的验收标准——从「命中」变为「不命中」。
