# 059 直通输入：显式取代「一次性注入」

- 状态：已裁定
- 类型：契约取代（显式取代 [[003]] 第 1 条「一次性注入」）
- 出处：用户 2026-08-15 原话，转录于 `docs/rulings/20260815-用户裁定原文-直通输入与刷新模型.md`

## 冲突是什么

[[003]] 第 1 条把「整条消息」与「发送那一刻」绑成一个原子动作，且草稿留在 App 本地输入框：

> 输入零延迟：输入框是本地的，打字/改字/输入法联想全程不走网络；
> **按发送那一刻整条消息经 send-keys 一次性注入并回车**。

用户 2026-08-15 裁定直通输入：键盘上**每敲一个键**（含虚拟键盘删除键）**实时直达**
Agent CLI 的输入框；CLI 输入框本身就是草稿，发送键是唯一提交动作。

结构上不再是「本地输入 + 发送时整条注入」，而是**「键入即直达 + 发送只提交」**——
[[003]] 第 1 条的机制前提被整体取代，不是量级调整。

## 为什么直通（用户理由，原话）

- 「**删除这个体验是天然的。**」——本地输入框模拟删除做不到 CLI 原生的编辑手感。
- 「有些东西我必须，就比如说那些命令，我必须先按斜杠……我完全可以说我一边输，
  然后按一下上面的 Tab 键，自动补全。」——**CLI 输入框才有斜杠命令 + Tab 补全**，
  App 本地输入框没有，若在本地输就必须背住全部命令。

## 裁定行为（用户原话为准）

1. **每键直达**：键盘里输入的所有信息、所有内容，直接发送到 Agent 的 CLI 的输入框里面。
   虚拟键盘按下删除键，也直接发送到 Agent 的 CLI 里面。
2. **CLI 输入框就是草稿**：按下键（无论中文英文），到达 CLI 输入框时它本身就是草稿，
   只有点发送才发送——**草稿编辑能力不消失，只是从 App 本地移到了 CLI 输入框**。
3. **发送键仍是唯一提交动作**（用户：「你只有点发送它才发送」）。
4. **显式取代 [[003]] 第 1 条**：「按发送那一刻整条消息经 send-keys 一次性注入并回车」
   不再适用。[[003]] 条目本体不回改，本取代登记于 REVISIONS.md R-009。

## 与既有条目的关系

- **[[003]] 其余三条不受影响**：发送必达 / 状态零丢失 / 需要时被唤醒照旧，被取代的只有第 1 条机制。
- **[[057]]（发图预贴例外）保留，边界口径更新**：
  - 057 当初以「注入拆成两步」为由开例外，前提是文字仍走「发送时才注入」。
    直通模型下文字本就逐键在 CLI 输入框，**图片路径预贴照旧成立**——预贴的仍是**图片路径本身**，
    用户文字照常逐键直通，发送键统一提交。
  - 057 第 1 条「纯文字消息仍是原来的单次注入 + 回车」随 [[003]] 第 1 条一起失效。
  - 057 其余边界**原样保留**：预贴只贴图片路径、不掺文字；不清理 CLI 输入框
    （`[Image #N]` 占位符滞留但用户看得见）；附件可累加；带图与纯文字手感同量级。
- **[[042]] 不冲突**：042 管 App 本地输入框不回填路径；直通模型下草稿载体迁到 CLI 输入框，
  图片路径按 057 预贴进 CLI 输入框。
