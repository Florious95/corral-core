## §1 右上角「查看」二级菜单串会话

**用户原话**：「这个列表在收藏里点开会话会窜……」
**用户随后的关键修正（以它为准）**：「准确的说是**最后一个加入收藏的**，查看页面展示的内容」

⇒ 不是「第一次点开的被缓存住」，而是「**不管从哪个会话点，拿到的都是收藏簿里最后写入的那条**」。
这两种说法的修法完全不同：
- 「第一次的被钉住」⇒ 浮层缓存没随会话切换失效。
- 「**永远是最后一个收藏的**」⇒ 浮层**没把「当前会话」当输入**，读了某个被 `addFavorite` 覆盖的共享/单例值。

**截图自证**（`.team/issues/shots/01-查看菜单串会话.jpg`）：
背景终端是「多agent协作」工作区（`Ctx: … | 多agent协作 | main`），
浮层列的 7 行副标题却**全是 `/Volumes…Agent安卓`` —— 错配在同一张图里就抓到了。

**判据 `A-vw-src`**：造两个工作区各一个会话，先收藏 A 再收藏 B（B 是最后一个）；
**从 A 的会话里点「查看」，浮层内容必须是 A 的**。🔴 先在当前实现上验红（现在必出 B）。
🔴 判据要能区分 **「浮层没刷新」** vs **「浮层读错了源」** —— 两者在界面上同形。

### 3a 🔴 claude code 的会话显示名恒为 `claude_code`，**要单独处理**
用户原话：「对 claude code 的会话名称存在问题，总为 claude code，**逻辑不一样，需要单独处理**」
⇒ 不能沿用其它 CLI 那套取名规则。

**🔴🔴 2026-08-19 用户直接给出了答案，073 §2 那个「尚未确定」到此为止。**

用户提供的 `tmux list-windows` 对照（`.team/issues/shots/05-tmux窗口名与pane标题对照.png`）：

```

- team-grok-l2: 4 windows

  └─> + 19: ux-v1-fav*:   "Write team-agent hands.txt self-proof fi… - grok"
```

格式是 `序号: window_name: "pane_title"` ⇒ **左边 = `window_name`，右边 = `pane_title`**。

**用户原话**：「Claude Code 的会话名称和 Grok 会话名称检测的机制不一样。可以发现 Grok 的会话名称检测是对的，
但是 Claude Code 它的会话名称的检测是**右边的，不是左边的**。左边可以看到它是 claude_code，
使得这个现象就印证，**你们总是拿左边的**，所以说 Claude Code 的会话名称不对。」

⇒ **规则定下来（每家 CLI 单独一条，正合 068「每个 CLI 独立探测器」的架构）**：

| CLI | 显示名取自 | 为什么 |
|---|---|---|
| grok 等 | **`window_name`**（左边） | 它就是席位名，天然各不相同：`advisor` / `ux-v1-layout` / `ux-v1-view` / `ux-v1-fav` |
| **claude code** | **`pane_title`**（右边），**剥掉前导状态符号** | 它的 `window_name` 恒为 `claude_code`，零区分度；真名在标题里：`"✳ 远控 leader"` → **`远控 leader`** |

🔴 剥前导符号复用 062 已有的三态判定那套符号表（`✳` U+2733 / `◐◑◒◓` 一族），
⛔ 不要另写一份符号表——单一真相，两份必漂。
🔴 名字**可能是中文**（`远控 leader` 就是），⛔ 不得做 ASCII 假设、不得截断到不可辨认。
🔴 **显示名只用于显示，身份仍走结构字段 + socket**（062/068/073 铁律不变）——
   062/068 禁的是「拿标题做**过滤/判活/身份**」，这里是**显示名**，不冲突。
⚠️ **grok 的 `pane_title` 是会变的任务摘要**（截图里就是），所以**不能**反过来给 grok 也用标题——
   这正是「逻辑不一样，需要单独处理」的含义。
