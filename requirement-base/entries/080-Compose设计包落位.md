## 1. leader 的技术抉择（用户授权「你自己去抉择」，逐条记明理由）

### 1.1 ✅ 保留设计的**青系**强调色，⛔ 不改成中性灰
用户曾说浅色终端「我发的信息是**灰底**」，而设计给的是浅青绿 `0xFFE6F5F2`
（配套光标 `0E7F72`、选中 `12A594` 也是青系）。
**裁定：照设计。** 依据是用户随后那句「这个样式我是完全看了，并且把关了的，能够还原就行了」——
他看过成品后仍然认可，说明「灰底」是当时对**主次关系**的描述（白底上开一块），不是对**色相**的指定。
🔴 主次关系必须成立：`userBlockBackground` ≠ `background` 且在浅色下更深。

### 1.2 🔴 三态按本工程，**不按设计的两态**
设计 `Models.kt` 是 `enum class SessionStatus { Busy, Idle }`，注释写「UI 只认这两个，映射由你那边做」。
**这句话在本工程是陷阱**：062 铁律是三态，且「⛔ `unknown` 绝不能当 `idle` —— 那是把『不知道』染成『确定空闲』」。
照它映射会把未知压成 Idle，把防了很久的坑重新挖开。
⇒ **扩成 `{ Busy, Idle, Unknown }`**，`StatusChip` 与 `RunningDot` 都要认第三态。

### 1.3 状态灯的三态映射（**用户直接指定**）
> 用户原话：「标题左边的那个绿点，按照它工作与否设置成绿灯亮还是灰灯。**未知的那就是红灯**。」

| 状态 | 灯 | 文案 |
|---|---|---|
| 进行中 Busy | **绿灯亮**（保留设计的脉冲动画） | 进行中 |
| 空闲 Idle | **灰灯**（不脉冲） | 空闲 |
| **未知 Unknown** | **红灯** | 未知 |

适用两处：列表行的 `StatusChip`、会话页顶栏的 `RunningDot`（现签名是 `running: Boolean`，要改成三态）。

### 1.4 终端左右内边距以**设计**为准，覆盖 `t.clip` 的取值
| 来源 | paddingLeft | paddingRight |
|---|---|---|
| `t.clip` 席位实测后自定 | `LEFT_MARGIN_DP = 8` | `RIGHT_MARGIN_DP = 4` |
| **设计 `TerminalSpec.kt`（采纳）** | **`14.dp`** | **`14.dp`** |

`t.clip` 的**根因诊断是对的、要保留**（判别为 CLIPPED 而非 LAYOUT_PUSHED：
格子原点 = contentLeft = 0，`drawCentered` 在 `advance > cellW` 时 x 为负 ⇒ 画到 clip 边左侧被裁），
**只把数值换成设计的 14dp**，且左右对称。
⚠️ 设计注释独立命中了同一机理：「字形绘制原点必须是 x = paddingLeft（**不是 0，也不是 -0.5f**）」。

### 1.5 落位方式：**并存 → 逐屏切换**，⛔ 不做一次性大替换
新代码整包进 `dev.agentmirror.app.ui.*` 子包，**与现有屏并存**；
再一屏一屏把现有 Composable 改成调用新组件，**业务逻辑一行不动**（新组件是纯展示的，正好只换壳）。
理由：一次性替换出问题时分不清是哪一屏引入的，且无法逐格出包让用户验。
