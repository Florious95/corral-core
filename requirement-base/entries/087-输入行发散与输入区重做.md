# 087 · 输入行发散与输入区重做（E1–E5）

- 日期：2026-08-21
- 来源：用户实测「打 `/` 加三个字符按 Tab，CLI 补全了，手机输入框还是原来那三个字符」「按两次 Esc 回退上一次输入，文本到了 CLI 输入框，手机这边什么都没有」「**导致我无法删除它**」
- 前置：[084 输入框差分同步]，本条**补它的洞**

## 1. 根因：084 漏了「远端会改写输入行」这一路

084 定的是差分同步：手机维护 `已同步文本`，每次变化算 `公共前缀` 发最小按键，
并**约定「同步后光标永远在行尾」**。这个约定成立的前提是——
**手机本地缓冲是 CLI 输入行的唯一作者**。

这个前提是错的。CLI 自己会改写输入行，至少三条路：

| 触发 | CLI 那边发生了什么 | 手机这边 |
|---|---|---|
| `Tab` 补全 | 输入行被替换成补全后的全文 | `已同步文本` 仍是补全前的三个字符 |
| `Esc` `Esc` 恢复上一次输入 | 输入行被填入一整段历史文本 | 本地缓冲为空 |
| `↑`/`↓` 历史、`Ctrl-R` 等 | 同上 | 同上 |

⇒ `已同步文本` 变成**过期信念**，而 084 的差分算法完全信任它：
- 前缀按过期信念算 ⇒ 后续按键发错；
- 用户按退格 ⇒ 手机删的是空的本地缓冲，`len(已同步)-prefix == 0` ⇒ **一个按键都不发** ⇒
  **CLI 那边的文本删不掉**。

🔴 **这是功能失效，不是显示不同步。** 用户会卡在一个删不掉的输入行上。

## 2. 失败条件（怎么算没满足）

- **F-087-1**：CLI 输入行被远端改写后（Tab 补全 / Esc Esc / ↑ 历史），手机输入框内容与 CLI 输入行**不一致**。
- **F-087-2**：上述状态下，用户在手机上执行删除，**CLI 侧输入行长度不变**。
- **F-087-3**：为修 F-087-1/2 而破坏 084 §5 的四条判据中的任意一条（尤其 `A-df-append` 的「退格数==0、字符序列与逐键直通完全一致」）。

## 3. 待定的方案岔路（⛔ 思路席位先答，实现席位不得自行选定）

手机这个框到底是什么，两种互斥答案，**选错则 E2–E4 全部返工**：

1. **本地缓冲 + 回读**：保持 084 的本地完整编辑，另外把 CLI 的输入行**读回来**校正 `已同步文本`。
   难点：alt-screen 应用（Claude Code / Grok）的输入行是渲染出来的区域，
   「哪几行是输入行」需要判定，⛔ 不许写死行号。
2. **镜像 + 按键捕获**：手机框不再持有独立缓冲，一切编辑（含删除、光标移动）都转成按键转发，
   框内显示的是远端输入行的镜像。E2 的「膨胀」变成「让镜像显示更多行」。

思路席位必须回答：**成熟 Agent 终端 APP 实际是怎么消解这个矛盾的**，
并给出选定方案在 F-087-1/2/3 上各自的代价。⛔ 不许只描述方案不给代价。

## 4. E2–E5：输入区重做（受 §3 结论约束）

- **E2**：输入框现在只有单行，改东西非常不便 ⇒ **点击后膨胀**展开为多行。
- **E3**：按键条（Esc/Tab/方向键/Ctrl-C）要能与打字**并存**——一边打字一边按，不互相打断。
- **E4**：**附件与发送收进输入框内部**。
- **E5**：观感对标成熟 Agent APP 的输入区。

## 5. 验收判据

- `A-087-tab`：手机打 `/` + 若干字符 → 发 `Tab` → **CLI 侧输入行文本 == 手机侧输入框文本**。
- `A-087-esc`：连发两次 `Esc` 触发历史恢复 → **CLI 侧输入行文本 == 手机侧输入框文本**。
- `A-087-del`：在 `A-087-esc` 达成的状态下执行删除到空 → **CLI 侧输入行长度归零**。
  🔴 断言的是 CLI 侧真的空了，⛔ 不许只断言手机侧空了。
- `A-087-nore`：084 §5 四条判据（`A-df-append`/`A-df-edit`/`A-df-ime`/`A-df-latency`）**全部仍绿**。
- `A-087-ui`：user gate——点击膨胀多行、按键条与打字并存、附件与发送在框内，
  由用户看真机截图拍板。⛔ 单测绿不算修好。
