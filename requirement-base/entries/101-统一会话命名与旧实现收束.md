- 日期：2026-09-13
- 来源：用户本轮关于 tmux 左右名称的四张截图、统一取名规则，以及后续指令「需求提交PR。把现有的实现收束。同时给出统一的算法。」
- 状态：**核心需求已明确；本 PR 提交需求、统一算法及实现收束要求，不是运行时代码已交付。** 分隔细节、噪声表及缺省行为是本 PR 明示的工程细则，不冒称用户逐项指定。
- 算法唯一现行入口：[统一会话命名算法 v1](../../requirement-wiki/wiki/techniques/unified-session-naming.md)。本条保存需求出处、替代范围和交付边界，不复制第二份算法。

## 1. 用户要求

用户指出，按 Agent/Provider 分别适配名字，会不断出现「修好 Codex、Cursor 又错」的问题，要求：

> 不再为每一个Provider设置单独的算法。

候选来自图中左侧 tmux 窗口名和右侧标题。左侧先排除 `tmux`、`node`、`[tmux]`、`node!` 等无信息名字；右侧通过 `-`、`|` 分出多个候选。工程名最低，其他候选左侧优先、右侧其次。

**本需求改的是 Corral 的会话显示名，不是 Provider 内部保存的原生会话名，也不是把计算结果写回 tmux。** 因此不再以注入 `/rename`、调用 Provider 私有改名接口或修改启动参数作为本需求的实现路径。

四张图的可复核期望（工作目录以合成路径 `/work/多agent协作` 表示）：

| 图 | 左侧窗口名 | 右侧标题 | 最终显示名 |
| --- | --- | --- | --- |
| 1 | `[tmux]` | `解决中转站的问题` | `解决中转站的问题` |
| 2 | `zsh` | `π - 多agent开发leader - 多agent协作` | `多agent开发leader` |
| 3 | `node!` | `多 agent leader \| 多agent协作` | `多 agent leader` |

图中的窗口序号、树形箭头、活动标记不属于名字输入。真实实现直接读取 tmux 结构化字段，不截图、不 OCR、不解析整行 choose-tree 文本。

本条只修订命名。**不撤销 Provider 识别、活动状态检测、健康状态、白名单、收藏键、跨 socket 身份或已落地的刷新性能要求。**

| 位置 | 当前分散点 | 收束后的要求 |
| --- | --- | --- |
| corral-serve `internal/api/listing.go::displayName` | Codex、Pi、default 分别取原生元数据、标题或窗口名 | 仅委托一个 Provider 无关的纯函数，例如 `internal/sessionname.Resolve`；函数不接收 Provider 或状态观察结果 |
| 同文件 `sessionFromPane` / `toSession`、listing、list_delta、Level2 | 同一对象可能经过不同入口显示 | 全部从同一个投影写 `Session.name`；不在序列化、Level2 或增量比较处再命名 |

| nodeprobe/协议里的 `session_name`、`Name` 等字段 | 原生名称或旧报告名称可能继续被 UI 用作覆盖来源 | 原生元数据可按既有协议兼容传递，但不得覆盖最终 `name`。逐一审计报告、工具和 UI 的名称消费者；不修改活动/健康检测来凑命名结果 |

| corral-app `FavoriteBook.kt` / `FavoriteRecord.kt` / 列表映射 | 收藏行丢失服务端名字后可能重新选窗口名 | 在线行消费同一 live name；离线只显示该 ref 最近保存的已解析 name 并标离线，不重新取名、不改收藏身份 |
| 会话顶栏、查看菜单、导航状态、Web/桌面消费者 | 点击时复制的旧字符串或另一条标题路径可能长期不更新 | 按 ref 订阅当前 name；名称变化后同一快照下各界面一致，不要求退出重进；终端镜像内的原始字符不替换 |

## 4. 收束完成的验收条件

下列项目是**运行时实现 PR 的待执行验收项**，本需求 PR 不把它们标为已通过。

- [ ] 四张图及算法页的边界样例精确匹配；有意义的左侧名胜出，左侧工程名不能压过右侧任务名。
- [ ] 同一组 tmux 输入仅更换 Provider 为 Codex、Cursor、Pi、Claude、Grok、unknown 或未来值，名字不变；缺少 Provider 判定不阻塞命名。
- [ ] `node`、`node!`、`[tmux]`、shell 默认名被过滤；`node-proxy`、`smoke-luna`、中文、空格及有意义的标点不被误伤；既有 Claude 场景不回归为 `claude_code`。
- [ ] listing、list_delta、真实 WebSocket Level2、查看菜单、收藏和顶栏都消费同一 name；验证中必须经过真实转换入口，而不是只单测帮助函数。
- [ ] 同一 ref 的 window_name/pane_title 更新后，列表、在线收藏与已打开顶栏及时更新；无变化不额外推送，不用独立名字轮询修补。
- [ ] ref、CWD 分组、原始窗口字段、Title、Provider、活动状态、健康状态、尺寸不因取名改变；同名不同 ref 的会话不得合并。
- [ ] 普通/私有 socket、同 cwd 多会话、未知 Provider、缺省元数据、重新连接、离线收藏均有用例；失败快照与成功但字段为空必须区分。
- [ ] 命名自身零额外进程、零终端正文读取、零 Provider 文件读取、零写入；只处理当前已采集的数据，不重新全机扫描。
- [ ] 已移除的 Provider 特例、命名缓存、专用兜底和未使用依赖有逐项清理回执；不是只在最外层盖一个新的显示字符串。
- [ ] 原有测试中确实被本需求推翻的名称期望，须注明旧规则→新规则；身份、状态、刷新及 UI 内容断言保留，不通过删断言或改 CI 范围制造全绿。

## 5. 本 PR 与实现交付的边界

本 PR 将用户需求入库，显式替代旧命名规则，并给出单一算法和清理清单；**不会使已安装的服务端或 App 自动获得修复**。随后运行时实现必须列出具体仓库/commit、删改入口、实际执行的测试及未验证项目，配套核对服务端与客户端版本；不能以本需求文档已合入、局部原型通过或仅截图正确代替链路验收。

不在本需求 PR 中修改 CI、发布产物、Provider 会话、tmux 配置、任务状态账本或任何真实对话。无合并、部署、发布授权。
