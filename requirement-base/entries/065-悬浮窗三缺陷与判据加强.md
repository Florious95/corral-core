# 065 悬浮窗三缺陷：socket 错、ANSI 未渲染、画面追加不替换

- 日期：2026-08-19
- 来源：用户真机实测 + 截图
- **补充并加强** `064`。064 的形态与「尺寸零影响」不变（那条已实证通过）。

## 一、三个缺陷

### 缺陷 1：内容来自错误的 socket，且把 scratch 会话自己也列了进去

用户原话：
> 我在不同的会话里面，点击右上角的查看，它都是这样的画面，都是这一个 socket 下的 CLI。

截图证据：列表里出现 `am-overlay: 1 windows (attached)`、`tree*`、`sleep*`、`ov-spin` ——
**`am-overlay` 是我们自己为抓屏建的 scratch 会话**，`tree` / `sleep` / `ov-spin` 是它内部的辅助 pane。

⇒ 两个错：
- **a. 没有按当前会话所属 socket 取数**：悬浮窗必须显示**用户当前所在那个会话所属 socket** 下的节点。
  客户端订阅时要带上目标 socket，服务端按它取数，不能用「第一个发现的」或写死的那个。
- **b. 自我映照**：抓屏用的 scratch 会话（`am-overlay` 及其辅助 pane）**必须从输出中排除**。
  它是观测装置，不是被观测对象。

### 缺陷 2：ANSI 控制序列被当作文本渲染

截图里出现字面量 `[?1049h`、`[22;0;0t`、`(B[m`、`[K`、`[30m[43m`。

⇒ App 拿到 PTY 裸字节后**没有过终端模拟器**。

🔴 **本项目已经有一条终端渲染路径**（三级终端流）。悬浮窗应当**复用它**，
不要另写一份渲染。理由：另写一份必然与三级的行为漂移，而漂移是静默的。
（若实现席认为不能复用，说明理由并发 `class="blocking"` 交 leader 裁定。）

### 缺陷 3：画面不断向下重复，不替换

⇒ 缺陷 2 的必然后果：`[?1049h`（切备用屏）与 `[H[2J`（清屏归位）没被解释，
于是每次 `refresh-client` 重发的整帧被**追加**而不是**替换**。

修好缺陷 2 后这条应当自动消失，但**必须单独有判据守住**，不能靠推理。

## 二、🔴 判据为什么没拦住：我的探针验错了东西

064 的跨端探针断言的是「**两帧非空且内容不同**」。

**一堆乱码完全满足这个条件。** 它验的是「有东西在动」，不是「画面是对的」。
这是本项目的头号复发形状（验东西在那儿，没验东西起作用）换了个马甲。

⇒ 加强后的探针必须断言**渲染结果本身**，至少三条：

| 判据 | 断言 |
|---|---|
| **无裸控制序列** | 渲染后的帧文本中**不得出现** `ESC[`、`[?1049`、`[K`、`(B[m` 这类字面量 |
| **socket 正确且无自我映照** | 帧中必须出现**目标 socket 下真实存在的会话名**；**不得出现** scratch 会话名（`am-overlay`）及其辅助 pane 名 |
| **替换而非追加** | 连续若干次刷新后，帧的行数**保持有界**（≤ 终端行数），且不出现同一棵树重复多份 |

三条都要**先在当前这版实现上验红**——现在这版正是坏的，是最好的红样本，别浪费。

## 三、不变的部分

- 悬浮窗是 App 内覆盖层，**用户所有真实会话的窗口行列数一个都不能变**（064 已实证，回归判据保留）。
- 打开才订阅，关掉即停。
- 抓屏保真（原生树线 + 转圈动画），不自绘。
