# 072 · 「查看」改为可点二级菜单；徽章错位/灰框/星星位置三修

- 日期：2026-08-19
- 来源：用户实测四条
- **推翻**：064/065/066 关于「悬浮窗必须是 choose-tree 抓屏、原生一致、带转圈动效」的形态要求

## 1. 【形态变更】右上角「查看」改成二级菜单式的可点列表

用户原话：「右上角查看展示不完全，现在把右上角查看改为二级菜单，且可以点击一个会话跳转」。

**新形态**：点右上角「查看」⇒ 弹出的悬浮窗内容 = **和二级菜单一样的会话列表**
（会话名 / 路径 / 状态徽章），**点其中一行直接跳到那个会话**（等价于从二级菜单进入）。
点列表以外区域关闭。

⛔ **不再做 choose-tree 抓屏**。随之作废的东西一并列出，避免有人回头去"修"它们：

- 064/065「原生一致抓屏、带转圈动效」——作废
- 070 §6.2 的横向截断 / 预览区糊入 / 大片空白三条——**随抓屏一起消失**，不必再修
- 070 §7 的 `A-ov-fresh`（scratch 会话跨重启复用）——**若不再起 scratch 客户端则自然消失**；
  仍要确认服务端**真的不再 attach 任何 tmux 客户端**（061 的零 attach 不变）

🔴 **服务端侧**：这条让 overlay 从「抓屏流」退化成「二级菜单数据的另一个消费者」。
⇒ 优先复用**已有的 level2 数据通路**，⛔ 不要为它再造一份取数逻辑
（一二级已经统一走同一个 provider 识别函数，见 068 §7；这里同理）。

## 2. 「进行中」徽章错位

现象：`进行中` 徽章与同行的星星、文字**基线不齐**，比 `空闲` 徽章偏移
（用户截图：developer-d72 的 `空闲` 与 developer-d75 的 `进行中` 高低不一）。
根因方向：两种徽章文字宽度不同导致的布局抖动，或未统一垂直居中约束。

**判据 A-ui-align**：同一列表内 `进行中` / `空闲` / 星星三者**垂直中心线一致**，
且徽章右边缘对齐。⛔ 判据不能只断言「徽章存在」。

## 3. 点收藏出现灰色正方形框

现象：点星星时出现一个**灰色正方形**（Material 默认 bounded ripple 落在方形边界上）。
**要求**：点击反馈必须是**圆形**（或无边界 ripple），⛔ 不得出现方形色块。

**判据 A-ui-ripple**：星星的点击指示为圆形/无界，实现里不得使用默认 bounded indication。

## 4. 星星移到会话条目**前面**

**推翻 067 §2 的「状态标左边」**：星星改到**每行最前面**（会话名之前）。

用户原话：「那就把收藏改到会话条目前面」。
理由（用户实测得出）：星星和状态挤在右侧时，两者的对齐问题互相放大，且点击热区互相干扰。

## 5. 不得倒退的既有行为

- 收藏闭环：点星→实心→收藏栏出现→点它直接进会话（已验通，⛔ 别改坏）
- 一级/二级白名单过滤（068）、三态状态（062）
- 底部标签栏（067 §4.1 已改判为底部三栏）
