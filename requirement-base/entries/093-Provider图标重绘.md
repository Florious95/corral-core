# 093 Provider 图标重绘（状态双态）

来源：用户 2026-08-21 追加反馈（附参考截图 assets/093-参考图标风格.jpg）。

- 用户原话：「当前的实现，图标很丑，换成图中的，且空闲和运行中的图标相似但不一样」；
  追问后明确：「我说的是 provider 的图标」。
- 要求：
  1. 会话列表/收藏列表第一列的 **Provider 卡通图标**（088 §3 那套）重绘，
     风格对齐参考图：小机器人/小怪物 glyph，圆润、可爱、线条简洁。
  2. **每个 Provider 有自己的 glyph**（识别度保留），但整族同一风格语言。
  3. **同一 Provider 两态**：运行中 vs 空闲，图标**相似但不一样**——
     参考图的做法是同一 glyph 的 实底彩色（运行）vs 灰色/描边（空闲）变体，可照此。
  4. 088 的审美标准继续适用：互洽、不突兀、「看了还想看」；不透明底问题不许再犯。

## §2 用户二次纠正（2026-08-22，⛔ 本条推翻上文「重绘」方向）

用户已两次表达、被我两次做错：**图标只用各 Provider 原生厂家图标**（Claude/Codex/Copilot/Grok/
Cursor/Pi 的官方图标），⛔ 不许自绘卡通/机器人 glyph——自绘的「特别特别丑」。
- 早前「互洽、不透明底」的要求针对的是**容器处理**（统一底板/圆角/边距让原生图标不突兀），
  不是授权重画图标本身。
- 运行/空闲双态仍可做：对原生图标做 彩色/灰度 或 亮度 两态，不改图标本形。
