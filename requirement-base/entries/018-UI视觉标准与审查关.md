# 018 UI 视觉标准与审查关

- 状态：已裁定
- 出处：用户三次真机回炉批评（2026-08-09）："已经跟你说了用户体验要达到什么样的标准，结果就这么简陋的 UI"；"派活的时候完全没有 UI 样式所要达到的标准…你是不是从来没有考虑过对这个 UI 进行审查？"
- 性质：leader 编排失职的结构性修正——此前所有 UI 任务只有功能验收，无视觉标准、无审查关（016 教训的 UI 版本重犯：功能绿≠体验合格）。

## 一、视觉标准（所有 UI 任务的验收依据，缺一即不合格）

1. **现代设计语言**：Material 3（动态色可后置），统一 Theme（色板/字阶/圆角/间距 token 化），深浅色双套完整；禁止裸默认样式直出。
2. **系统集成**：全页面 safe-area（statusBars/navigationBars/ime insets）；状态栏图标颜色与背景适配；键盘弹出不遮挡输入。
3. **信息层级**：每页有明确的主/次/辅层级（字号、字重、透明度分级）；列表行主信息一眼可辨；长文本截断有设计（路径中段省略、名称尾部省略），禁止无脑换行撑爆。
4. **密度与呼吸**：行高/间距按 Material 密度规范；触控目标 ≥48dp；禁止大片空白或元素悬空错位。
5. **状态可视**：加载/空态/错误态每页专门设计（不是白屏或裸文本）；状态徽章色彩语义一致（工作中/阻塞/完成/空闲/未知五态可辨且色弱可辨）。
6. **反馈与动效**：点击态（ripple）、页面转场、列表增删过渡；连接状态变化平滑呈现，禁止闪跳。
7. **终端页专项**：字形完整（无豆腐块）、等宽对齐、滚动 60fps 体感、顶栏紧凑不喧宾夺主。

## 二、审查关（流程红线，进所有 UI 任务模板）

- UI 任务交件**必附模拟器截图**（涉及页面全态：正常/空/错误/深色）落 `e2e/artifacts/ui-review/`；
- leader 验收**必须逐图目检**对照本条标准，逐条给结论写进证据 JSON（`ui_review` 字段）；测试绿但目检不过 = 不合格打回；
- 真机清单每步附 UI 体验判定（简陋/合格/优秀），"简陋"即立案。
