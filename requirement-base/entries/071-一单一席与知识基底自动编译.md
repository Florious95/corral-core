## 1. 两条纪律

### 1.1 一单一席

**每一格用一个新席位，不复用。** 席位名 `<账本短名>-<任务短名>`。

理由（本工程实证）：席位复用会把上一格的上下文带进下一格。
2026-08-19 已经吃过一次亏——`fav-dev-app` 连做 `t.fav`/`t.cols`/`t.port`/`t.fix` 四格，
它在后面几格里沿用了前面格子形成的判断，**而前面那格本身是错的**
（`t.fav` 单测绿但点星星根本不生效），错误就这么被继承下去。

### 1.2 知识基底自动编译

**模块影响闭包随单下发**，不靠席位自己猜架构。
`tools/basegen_ledger.py <账本> <任务id>` → `.team/nodes/<任务>/BASE.md`，含：

- 任务信封（账本原文机械抽取）
- **正向依赖** = 你消费的契约（只读）
- **反向依赖 = 波及面 = 你的回归自查范围** ← 这一条是重点，缺它就会「改对了地方、漏了兄弟调用方」
- 闭包内架构卡全文内联

⛔ 不复制第二份闭包实现：`basegen_ledger.py` 复用 `basegen.py` 的算法，
只替换「信封来源」（taskbook.yaml → ledger.v2）。两份实现会静默漂移（同 063 单一语料）。

## 2. 一条命令

```bash
python3 tools/prep_ledger.py .team/ledgers/<账本>.json
ledger-run --preflight --json .team/ledgers/<账本>.json    # 必须 rejected:false
nohup sh -c 'ledger-run --drive --json <账本> > <日志> 2>&1' >/dev/null 2>&1 &
```

`prep_ledger.py` 幂等，做四件：编基底 → 建专属席位 → **行为自证** → 写回账本。

## 3. 行为自证不可省

新席位必须**真写出一个文件**才算可用。
`clone-agent` 会**静默把分身降级成只读**（能说话、不能写盘，无警告无报错），
所以「席位活着 / 它回话了」**不是**可用性证据。
`prep_ledger.py` 里这一步失败即退出，不允许带着一个没有手的席位开跑。

## 4. teardown 推迟到整张账本终态之后

⛔ **不要在单格终态后销毁它的席位**：框架 preflight 会校验**已终态任务**的收件席位，
中途销毁会锁死整张账本（框架已知未修，2026-08-19 交付信里他们自己列出）。
⇒ 账本跑完再统一清理，并一并删 `.team/dynamic-role-files/<名>.md`（残留会挡下次建席）。
