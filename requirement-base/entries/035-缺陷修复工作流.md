# 035 缺陷修复工作流

- 状态：已裁定（流程类）
- 类型：工作流 W-01
- 出处：用户 2026-08-12 裁定「你在派活的时候，就应该同步的派测试去做…让开发自己去走测试开发循环，直到红测消失」

## 流程

1. **撞库**：librarian 检索需求基，确认缺陷涉及的需求约束。
2. **basegen 编闭包**：算影响范围，编译知识基底。
3. **同步派两席**：
   - 测试席：先写红测（Web 端 Playwright / Chrome DevTool MCP），断言当前行为是错的 → 红灯。
   - 开发席：拿到基底开始改代码。
4. **开发改完 → 跑红测**：红测变绿 = 修复确认。
5. **Web 端绿 → 上模拟器**：安卓端自动化测试验证。
6. **模拟器绿 → 打包交用户手测**：最终验收。
