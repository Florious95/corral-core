**用户原话**：「现在已经改对了，但是点进会话的话，它的标题还是旧的。」

076 §3a 的显示名规则（claude code 取 `pane_title` 剥前导符号）只落到了**列表**：
收藏页与二级菜单已显示 `leader` / `远控 leader` / `team-leader-2`，
但**点进会话后，顶栏仍是 `claude_code`**。

**leader 用 UI 树当场复现（`.team/issues/shots/06-会话页标题仍是claude_code.png` 同一现场）**：
```
$ python3 tools/uiassert.py dump
‹ 返回

```

⇒ **同一个会话，在列表里叫 `远控 leader`，进去以后叫 `claude_code`** —— 两条取名路径没统一。

🔴 **判据 `A-tt-title`**：进入任一 claude code 会话后，
`uiassert.py absent claude_code` 必须 **rc=0**，且 `uiassert.py has <该会话在列表里的显示名>` 必须 **rc=0**。
🔴 先在当前实现上验红（现在 `absent` 必红，leader 已实测确认）。
🔴 显示名**只用于显示**，身份仍走结构字段 + socket（062/067/073 不变）。
⛔ 不许在会话页另写一份取名逻辑 —— **必须复用 076 §3a 落地的那一个函数**，否则又是两套漂移。

## §2 🔴 判据形态升级：改用 UI 树断言，不再靠多模态读图

**用户原话**：「现在这个 APP 模拟器基本上能够 1:1 还原我在我手机上看到的样子。
**你们要考虑一个以 MCP 为基础去测试的办法，而不是要频繁实图**、频繁去识别图片、使用多模态去识别图片。」

安卓侧没有现成 MCP，但 **`adb exec-out uiautomator dump`** 就是等价物：
它吐出整棵 UI 树的结构化 XML，`text` 属性就是屏幕上的字。

**工具**：`tools/uiassert.py`（已落地并正反测过）
```
uiassert.py dump                      # 打印当前屏幕全部可见文本
uiassert.py has    "远控 leader" …     # 全部出现 → 0
uiassert.py absent "claude_code" …     # 全部不出现 → 0
uiassert.py distinct 3 --among A B C   # 两两不同且都在屏上 → 0
uiassert.py save /path/ui.xml          # 存 XML 快照当证据
```

**为什么这是升级，而不只是省事**：
旧判据是「三张截图 md5 互不相同」——它**连图里画的是什么都没看**。
2026-08-19 实发：`t.layout` 交了一张半透明过渡态截图（底部标签栏都没渲染出来），
md5 判据照样绿，缺陷要靠人再看一眼才发现。
UI 树断言**直接断言内容**，这才叫「判据断言世界变了」。

**新规矩**：
- ✅ **机械判据一律用 `uiassert.py`**，断言具体的字符串在/不在。
- ✅ 每个现场存一份 `ui.xml` 快照（`uiassert.py save`）作可复核证据。
- 🖼 **截图仍要留**，但降级为**给人看的旁证**，⛔ 不再作为唯一机械判据。
  数量从 ≥3 张降到 ≥1 张关键现场即可，省下的是 leader 反复读图的开销。
- ⛔ 取不到 UI 树时必须**响亮失败**（`uiassert.py` 已内置）——
  尺子坏了和被测正常在输出上同形，这条不能省。
