# 100 连接保活与半开自愈（用户实测二连击：旧 app L2 卡重连、新装 app 无限重连）

来源：2026-08-22 用户两次实测 + Opus 审计确认项（F-090-1 残留：WebSocket 无任何保活，
半开连接下回前台永远不重连）。leader 复现对照：同 APK 模拟器连 ship daemon 一次成功 ⇒
手机侧是旧连接半开后重连状态机卡死，不是新版本连不上。

## 要求
1. 应用层保活：ws ping/pong（或协议心跳帧）周期发送；N 次未回 ⇒ 判死，强制关 socket 重拨。
2. 「重连中」状态机必须真的在拨：横幅显示重连中时，必须存在活跃的 dial 尝试与退避计划；
   ⛔ 不允许「显示重连中但无 dial」的状态存在（先验红就钉这个状态）。
3. 回前台必查活：onResume 主动 probe（收不到 pong 即重拨）——090 那条回归的根治位。
4. 服务端若需配合 pong 回应，一并做（协议里已有？实现席核对）。
