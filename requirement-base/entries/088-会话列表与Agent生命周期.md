# 088 · 会话列表与 Agent 生命周期（E7–E16）

- 日期：2026-08-21
- 来源：用户 2026-08-20/21 连续给出的优化点 + 两张真机截图

## 1. 列表交互

- **E7**：「查看」会话列表在 Agent 数量多时**展示不全，且没有可下拉/可滚动的提示**。
  失败条件：列表内容超出一屏时，用户无法从界面上看出「下面还有」。
- **E8**：列表打开时从屏幕侧边滑动，**退出了会话**，而不是**关闭这个列表**。
  失败条件：sheet 处于展开态时，系统返回手势未被 sheet 消费。
- **E9 排序**：⛔ 不再按首字母。排序键＝**(收藏 降序, 运行中 降序, 名称 升序)**，
  即「收藏且运行 → 收藏且空闲 → 未收藏且运行 → 未收藏且空闲」，每档内按首字母。
- **E16 状态标签**：「进行中」（3 字）与「空闲」（2 字）不等宽 ⇒ **「进行中」改为「运行」**，
  且两个标签**等宽**。🔴 等宽必须是布局保证，⛔ 不许依赖「碰巧都是两个字」——
  将来加「已断开」会再次歪掉。

## 2. 首列与长按

- **E10**：第一列的星标是**低频操作却占了最易误触的位置** ⇒ 首列改为 **Provider 图标**，
  一眼认出是哪个 CLI。**收藏页（E15）首列同样是 Provider 图标。**
- **E11**：收藏改为**长按会话**弹出（长按复制那种交互），⛔ 不再是首列点按。
- **E15**：收藏页长按 = **取消收藏**；收藏页⛔ **没有「关闭」按钮**。

### 图标的硬指标（⛔ 不是形容词）

1. **不透明底必须去掉**——原生资产直接摆上会出现方块底，这是用户点名的问题。
2. **与界面互洽**：统一光学尺寸、统一内边距、统一圆角容器；**深浅两主题各出一版对比图**。
3. **观感**：可爱、耐看、不突兀 ⇒ 走 **user gate**，用户看截图拍板。
4. **许可**：优先用各家官方发布的图标资产并做上述归一化；
   **凡许可不允许再分发的，在同一套视觉语言下自绘**，⛔ 不把不能发的资产塞进本仓。

## 3. 关闭（E12）

**「关闭」是一个原子动作**，三件事同时成立或同时不发生：

1. 关掉该 CLI 进程；
2. 关掉它在 **tmux** 下的条目（pane/window）；
3. 若它是收藏项，**一并取消收藏**。

失败条件：出现任何半截状态——关了会话却遗留 CLI、或 CLI 没了却还挂在收藏页上。

- **二次确认必须有**（不可逆销毁，未保存内容会丢）。
- **作用域（用户 2026-08-21 裁定 (b)）**：保护只在收藏页生效。
  **会话页长按已收藏项，照给「关闭」**；收藏页⛔ 不给。

## 4. 新建 Agent（E13）

工作区页右上角加 **「+」**：选择 Provider、勾选是否开启 Bypass 权限。
本质是**新开一个 tmux pane/window，在其中执行该 Provider 的启动命令**。

### Bypass 参数（🔴 本机 `--help` 实测，⛔ 不是推测）

| Provider | Bypass 参数 |
|---|---|
| Claude Code | `--dangerously-skip-permissions` |
| Codex | `--dangerously-bypass-approvals-and-sandbox` |
| Copilot | `--yolo`（等价 `--allow-all`） |
| Cursor | `--force`（`--yolo` 是其别名） |
| Grok | `--always-approve` |
| Pi | **无** bypass 参数（`--approve/-a` 是「信任项目本地文件」，不是免审批） |

⚠️ **Grok 必须显式传 `--always-approve`。** 用户本机截图显示 `always-approve`，
那是**用户本地 config 已开**；产品⛔ 不许依赖用户的本地 config，
否则换一台机器就会开始弹审批。

## 5. Provider 启动命令可配置（E14）

设置里可改**每个 Provider 的完整启动命令**。
用例（用户原话）：自建的 `claude-local` 直接走本地第三方模型，启动命令与官方不同。
⇒ 启动命令是**配置**，⛔ 不是硬编码常量。Bypass 参数同理，应可随命令一起配置。

## 6. 验收判据

- `A-088-sort`：构造含四档的会话集合，断言输出顺序 == (收藏↓, 运行中↓, 名称↑)。
- `A-088-label`：断言「运行」与「空闲」两个标签**测量宽度相等**；⛔ 不许只断言文案改了。
- `A-088-close`：关闭后断言三件事同时成立——进程不在、tmux 条目不在、收藏项不在。
  🔴 任一为假即红；⛔ 不许只断言 UI 上消失了。
- `A-088-close-scope`：收藏页长按菜单**不含**「关闭」；会话页长按已收藏项**含**「关闭」。
- `A-088-new`：对六个 Provider 各断言生成的 argv == §4 表格（勾选 Bypass 时）与不含该参数（未勾选时）。
- `A-088-cmd`：改过启动命令后新建，断言实际执行的是改后的命令。
- `A-088-back`：sheet 展开态下触发返回手势，断言 sheet 关闭且**会话页仍在栈顶**。
- `A-088-ui`：user gate——图标观感、下拉可见性、深浅两主题各一版截图，由用户拍板。

## 7. 契约裁定：`create_session` 的 argv 由服务端原样执行（2026-08-21 leader 裁定）

`pr2-judge-proto` 在审 `t.newpane` 时升报：`protocol/frames.go` 注释写着
「**Server executes Argv as-is**」，`handleCreateSession` 把客户端送来的 `Argv` 原样交给
`tmux new-window -- …`，**服务端不做白名单校验**；六个 Provider 的白名单只存在于客户端。
`validate.go` 只查「非空」。评审席未将其算作否决，但要求 leader 裁定，⛔ 不许默认漂着。

### 裁定：**维持现状（选项 ①）**，并把理由与边界写死在这里

**理由一：不制造新的权限等级。**
现有 `input` 帧本来就允许往任意已有 pane 注入任意按键 ⇒ **认证后执行任意命令的能力已经存在**。
本帧没有抬高权限，只是换了个入口。**信任边界在配对/认证那一层，不在这一帧。**

**理由二：服务端白名单与 E14 需求直接冲突。**
E14 是用户点名要的：「我自己建了一个 Claude Code，但是直接使用本地的第三方模型，
它的命令我自己设置了 `claude-local`，那我很显然可以在这个 Provider 设置里面改它的启动命令」。
⇒ 服务端若校验 `argv[0]` 属于六个已知 Provider，**用户自建的 `claude-local` 会被拒**。
选项②在功能上是错的，不只是成本问题。

### ⚠️ 但下面三条是这条裁定的**前提**，任何一条不成立就必须重裁

1. **⛔ 绝不经 shell**：argv 必须原样作为参数数组交给 `tmux new-window -- …`，
   ⛔ 不许拼成字符串走 `sh -c`。（现状已满足；这是防命令注入的唯一屏障。）
2. **必须留审计痕迹**：服务端执行前必须把**实际 argv** 记进日志（诊断日志纪律：记操作数）。
   出事时要能回答「到底执行了什么」。
3. **配对/认证是唯一信任边界**：⇒ 配对流程的强度就是本条的强度。
   任何削弱配对（如 091 E21「配对页能被侧滑到达」）的缺陷，**同时削弱本条**。
