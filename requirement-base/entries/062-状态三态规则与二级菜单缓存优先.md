# 062 状态判定改为三态规则；二级菜单进入先画缓存

- 日期：2026-08-18
- 裁定人：用户（真机反馈 + 截图）
- **补充** `061`。061 的形态、时效、推送模型不变；本条改判定规则并加一条渲染要求。

## 一、根因：只定义了「工作符号」，没定义「没有符号」

真机现象（用户报）：
- 所有 Grok 席位一律显示 **未知**
- Claude Code 也「每次进二级菜单都是未知，点进去发现它在工作，回来才显示工作中」

⇒ 病根不是「缺 Grok 的符号」，而是 **`没有前导符号` 落进了 `未知`**。
「工作中」这一支是对的（用户实测：真在工作时确实显示工作中）。

## 二、🔴 三态规则（本条取代 061 里「认不出即未知」的二分写法）

| 标题前导 | 判定 | 说明 |
|---|---|---|
| **已知工作符号** | **进行中** | 见下表 |
| **没有任何符号**（首字符是普通字文/数字/字母） | **空闲** | ← 061 缺这一条，是全部误判的来源 |
| **有一个符号，但不在表里** | **未知** + 记 Unicode 码点与完整原始标题 | 供人把它加进表 |

🔴 **「未知」必须稀有。** 它只表示「有个我不认识的符号」，
不表示「我没看到符号」。把后者也记成未知，等于把正常态染成异常态，
用户看到的每一行都是未知，那个标记就失去了信息量。

## 三、已实测的符号表（真数据，不是从截图猜的）

| CLI | 工作态 | 空闲态 | 证据 |
|---|---|---|---|
| Claude Code | `◐` U+25D0（及同族 `◓◑◒`） | `✳` U+2733 | 用户截图 + 本机 tmux 标题 |
| **Grok CLI** | **盲文点阵 U+2800–U+28FF**（实测到 `⠼` U+283C），且标题含 `" - Thinking - "` 或 `" - Waiting for response"` | **无前导符号，以 `" - grok"` 结尾** | 本机实测采样：<br>工作 `⠼ - Waiting for response… - <任务摘要> `<br>空闲 `<任务摘要> - grok` |

⚠️ Grok 的空闲标题**保留上一次任务的摘要**，所以「标题不是 `grok` 两个字」不能当成在工作。
判据只看**前导符号**与**文本标记**，不看摘要内容。

## 四、二级菜单进入时先画缓存，不要先空白

用户原话：
> 每到第二级菜单的时候，它都是完全的空白。先空白再刷新，等刷新完成才出现列表。
> 之前的体验是展示旧的，然后这个时候刷新新的。**我希望展示旧的这一点能够保留。**

- 进入二级菜单**立即渲染上一次的列表**（本地缓存），同时后台建立订阅；
- 新数据到达后**原地替换**，不清空重画；
- 缓存为空（首次进入该工作区）才允许显示空态。

⇒ 这是一条可机械验证的要求：**进入到首帧有内容之间，不得出现空列表帧**。

## 五、🔴 模块解耦：每个 Agent CLI 一个独立探测器，各带各的判据

用户裁定（2026-08-18）：**每一个 Agent 都应该有单独的判据和函数。要做好模块解耦。**

### 形状

```
共享层（不认识任何具体 CLI）
  └─ 三态兜底：有已知工作符号 ⇒ 进行中 / 无前导符号 ⇒ 空闲 / 有陌生符号 ⇒ 未知+记码点
探测器注册表
  ├─ claudecode 探测器   ◐ U+25D0 同族 = 工作；✳ U+2733 = 空闲
  └─ grok 探测器         盲文 U+2800–U+28FF = 工作；" - Thinking - " / " - Waiting for response" = 工作；
                         无前导符号且以 " - grok" 结尾 = 空闲（标题保留上次摘要，不据摘要判活）
```

### 硬约束

- **接一个新 CLI = 新增一个探测器文件 + 一个测试文件**，不许改共享层、不许改别的探测器。
- **共享层里不得出现任何具体 CLI 的字面量**（不得出现 `grok` / `claude` 这类串）。
  这条要写成机械判据去查，不靠自觉。
- **每个探测器有自己的具名测试**，工作态与空闲态各至少一条。

### 为什么这条值钱

符号识别层是本项目**四轮翻车**的位置，且它注定被反复修改（每接一个新 CLI 就要动它）。
耦合在一起时，**加 Grok 会碰坏 Claude Code 的判定，而这种回归是静默的**——
判据仍然全绿，只有用户在真机上看到一片「未知」。
解耦之后，改动的爆炸半径被限制在一个文件里，且那个文件有自己的判据守着。
