# 091 · 配对页的皮与门（E20 旧 UI / E21 侧滑能跑进来）

- 日期：2026-08-21
- 来源：用户口述两条
- 状态：**已入池，⛔ 本轮第一波未派单**（用户 2026-08-21 令：「你当前不用直接写任务书，写账本。之前的完成之后你可以再做」）

## 1. E20 · 配对页还是旧 UI、旧主题

「重新配对 / 配对」那一页**没有跟着新主题重构**，仍是旧皮。

- **失败条件 F-091-1**：切换主题后，配对页的底色/前景/控件配色**不跟随**，或与其它页明显不同源。
- 判据方向：与 APP 其它页走**同一套主题令牌**；深浅两主题各出一版截图，走 user gate。
  🔴 ⛔ 不许只把几个写死的色值换成另几个写死的色值 —— 那还是旧皮，只是换了颜色。

## 2. E21 · 配对页在不该出现的时候出现（侧滑能跑进来）

用户原话：「**它有可能在一些地方的侧滑，然后跑到这一页**……
这个配对的这一页，**只能在设置点击进入才能够进入，或者说第一次开 APP 的时候才能够进入**。
其他的是任何情况下都不要出现这个异常的页面。」

### 准入规则（这是硬规则，⛔ 不是「尽量」）
配对页**只有两条合法入口**：

1. 设置里主动点击「重新配对」；
2. **首次启动**（尚未配对过）。

- **失败条件 F-091-2**：除上述两条以外的**任何**路径到达配对页，
  尤其是**从任意页面做边缘侧滑（系统返回手势）落到配对页**。

### 根因方向（⛔ 是线索不是结论）
配对页很可能作为**导航起点**留在返回栈里，于是返回手势一路弹栈就弹回它。
⇒ 修法应是**配对完成后把它从返回栈移除**（而不是给每个页面各加一个拦截）。
🔴 与 **E8**（会话列表展开时侧滑退出了会话而不是关列表）**可能同源**——
都是返回手势的处理。**并格前先验证是不是同一个根因，⛔ 不许因为形状像就合并**
（形状像 ≠ 同源，已有实撞教训）。

### 判据
- `A-091-gate`：穷举可达页面，对每一页触发返回手势，断言**没有任何一页能落到配对页**。
  🔴 这条要断言「世界变了」：先验红时必须真的能从某页滑到配对页，把那条路径写进说明。
- `A-091-entry`：断言两条合法入口**仍然可用**（设置点击、首启未配对）。
  ⛔ 防的是「为了堵住侧滑把入口一起堵死」。
- `A-091-theme`：配对页与其它页共用同一套主题令牌；深浅两主题截图走 user gate。
