# 082 · 收藏页把在线会话判成「不在线」

- 日期：2026-08-19
- 来源：用户实测 `.team/issues/shots/09-收藏页不刷新误判不在线.png`

## 1. 现象

**用户原话**：「收藏页的话，它没有刷新的功能，导致有些节点它是不在线的。
但实际上你在会话页点进去看的时候，发现它是在线的。」

截图三行：
| 显示名 | 工作区 | 状态标 |
|---|---|---|
| `claude_code` | 讨论team-agent | **不在线**（置灰） |
| `claude_code` | 远程Agent安卓 | **不在线**（置灰） |
| `team-leader-2` | 多agent协作 | 空闲（正常） |

## 2. 🔴 根因方向：不是「缺个刷新」，是**跨工作区的 live 数据只有一份**

`FavoriteBook.kt:92` 写得很清楚：**「用 live 的 ref 对账。未命中 → isOnline=false（不在线 / gray），仍输出该行。」**

⇒ 收藏行在不在线 = **它的 ref 在不在当前那份 live 列表里**。
而 live 列表来自二级菜单的扫描缓存，**只覆盖用户最近进过的那一个工作区**。

**截图完美印证**：唯一显示「空闲」的 `team-leader-2` 属于「多agent协作」——
用户最近就在这个工作区；另两个 claude_code 所属工作区的 live 数据**压根没被扫过**，
于是「没扫到」被当成了「不在线」。

🔴 **这和 076 §1（查看菜单读单例）是同一个病根**：
**跨工作区的数据没有被"分工作区地"持有与刷新**，全局只有一份最近值。
076 §1 修的是「查看」那条读取路径；本条是收藏页这条**还没修**。

⚠️ 因此「加个下拉刷新」**不足以修好它**：刷新只会刷当前那一个工作区，
另外两个工作区的会话仍然扫不到。**必须按收藏项各自的工作区去取数。**

## 3. 连带现象（leader 核出，用户未提，但同源）

截图里**不在线的两行显示名仍是 `claude_code`**，而在线那行已经是 `team-leader-2`。

原因：`FavoriteRecord` 的注释写着「身份只有 ref；**其余字段仅供失联时展示**」——
失联行只能拿落盘快照里的旧 `identityLabel`（= 旧规则的 `window_name`）。

⇒ **修好在线判定，076 §3a 的显示名会跟着自动好**；不修的话，
即使设计版落位完成，这两行**仍然显示 `claude_code`**。
🔴 这条要写进判据，否则会出现「显示名那格明明验过了，用户还是看到 claude_code」的自相矛盾。

## 4. 判据

**`A-fv-online`**：造三个工作区各一个在线会话并全部收藏，
**不进入任何二级菜单**直接打开收藏页 ⇒ **三行都必须是在线状态**（非「不在线」）。
🔴 先在当前实现上验红（现在只有最近进过的那个工作区那行是在线）。
🔴 判据要能区分 **「没刷新」** vs **「只刷了一个工作区」**：
量 **收藏项覆盖的工作区数** 与 **实际取过数的工作区数**，两个数都要记。
⛔ 只断言「有一行在线」不算——那在坏实现下也成立。

**`A-fv-name-offline`**：上述三行的显示名必须都按 076 §3a 的规则（claude code 取 pane_title 剥符），
⛔ 不得出现 `claude_code`。

## 5. 不得倒退
- 061 静默经济：⛔ 不许改成周期性轮询所有工作区。取数应由**进入收藏页**这一次事件触发（069 的形态）。
- 073 身份键含 socket；076 §1 查看菜单按当前会话 ref 取数；076 §3 星在行首 + 状态标同源。
