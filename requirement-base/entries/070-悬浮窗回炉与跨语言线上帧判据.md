## 1. 现象

新包（`agentmirror-whitelist-fav-overlay-d1e624cde.apk`）+ 新 daemon（10:20 换，白名单 5 条已载）：
点会话内右上角「查看」⇒ 悬浮窗弹出但**内容全白**，底部同时出现红字
`协议错误：bad_frame（malformed frame）`。

## 2. 定位（读码，非推测部分）

- `ws_conn.go:406-412` `classifyCodecError`：**`ErrInvalidField` 也映射成 `bad_frame`「malformed frame」**，
  与真正的 JSON 解码失败共用同一个错误码。
- `validate.go:319` `OverlaySubscribe.Validate()`：**唯一的校验是 `socket` 非空**。

⇒ `socket` 为空 ⇒ `ErrInvalidField` ⇒ `bad_frame` ⇒ 订阅未建立 ⇒ **窗口没有任何帧可画 ⇒ 全白**。
**空白与红字是同一个因，不是两个缺陷。**

⚠️ 「socket 为什么是空的」尚未坐实（`sessionSocketFromRef` 取 ref 中 U+001F 之前的前缀）。
这一步交给根因探针，不猜。

## 3. 真正的缺口：没有跨语言线上帧判据

已有测试的形状全是**同语言闭环**：

- App 侧：App 的对象 → App 的序列化 → App 的断言
- 服务端侧：服务端的对象 → 服务端的解码器 → 服务端的断言
- 探针（066 附则）：抓到的帧夹具 → **App 的模拟器** → 渲染断言

**没有任何一条把「App 真正发出去的字节」喂给「服务端真正的解码器」。**
⇒ 跨语言的线上帧不一致，在两边各自的单测里**永远是绿的**。
这就是 t.port / t.probe2 / t.ver 全绿而真机一点就红的原因——判据验的是渲染，不是那条线。

## 4. 判据

- **A-wire-roundtrip（核心，缺它这类缺陷必然复发）**：
  对**每一个 C→S 帧类型**，用 **App 的序列化器**产出字节，落盘成 `app/wire-fixtures/*.json`；
  Go 侧读同一批文件，用**服务端真正的解码器 + Validate** 逐个解，必须全部成功。
  🔴 须先在当前实现上**验红**（`overlay_subscribe` 的 socket 为空那条必须红）。
- **A-wire-badframe-distinct**：`ErrInvalidField` 不得与真正的解码失败共用 `bad_frame`。
  字段非法要有自己的错误码与**可读的字段名**，否则客户端拿到「malformed frame」无从下手。
- **A-ov-diag**：悬浮窗路径必须有诊断记录（诊断日志纪律）。
  用户导出的日志里 overlay 相关记录数**必须 > 0**，且要记**参与判断的操作数**
  （订阅发出的 socket 原值、收到的帧序号与字节数、拒绝原因），不是只记「失败了」。
  🔴 实发：这次用户导出日志，`[viewport]`/`[grid]` 刷屏，**overlay 零记录**，
  拿着一个为诊断而生的日志诊断不了这个。
- **A-ov-nonempty**：socket 为空时 App **不得发出该帧**，就地报可读错误。

## 5. 纪律（本次教训）

**同语言闭环的判据，证明不了跨语言的接缝。** 凡是「两个实现要在一条线上对话」的地方，
判据必须**跨过那条线**：一侧产字节，另一侧解字节。在各自那侧多写十个测试也补不上这一条。

## 6. 模拟器实测（2026-08-19 11:28，leader 亲测，禁令已由用户解除）

环境：AVD `agentmirror_geo_1260x2800`（与用户手机同几何）+ 用户手上那个 APK
`agentmirror-whitelist-fav-overlay-d1e624cde.apk` + 10:20 换的 daemon，
经 `adb reverse tcp:9900` 直连本机 daemon。证据截图见
`.team/nodes/ov3-probe/emulator-evidence/`。

### 6.1 复现不出 bad_frame —— 这条要单独记

模拟器上点「查看」，悬浮窗**正常出内容**：无 `bad_frame`、无裸控制序列、中文树画得出来。
⇒ **用户手机上的 bad_frame 在模拟器上不复现。**

差异只有一处：用户手机走 tailnet 且**带着旧版本留下的本地缓存**，模拟器是全新配对。
⇒ **推测（未坐实）**：手机上的会话 `ref` 来自旧版服务端的缓存列表，其结构与新版取 socket 的方式不一致
⇒ `sessionSocketFromRef` 取出空串 ⇒ `overlay_subscribe` socket 为空 ⇒ `bad_frame`。
⚠️ 这条**没有证据**，只是唯一能同时解释「手机红、模拟器绿」的差异。
不管它成不成立，§4 的 A-wire-* 与「socket 为空不得发帧」都要做——那是防线，不是猜测。

### 6.2 模拟器上当场看见的两个真缺陷（这才是排版问题的本体）

1. **横向截断**：每行右边被切掉（`保留V5代码保证审查…` / `Level2 回炉：归档回退与全…`），
   面板没有按自身宽度做任何适配。
2. **下半部分错乱 + 大片空白**：choose-tree 的**预览区**内容糊进面板中部
   （框线碎片 + `Ctx: 340936 (34%) | Opus 5 (`），面板下半整块空白。

⇒ 判据补充：
- **A-ov-fit**：悬浮窗内容**不得横向截断**；宽度不够时按可读方式处理（缩宽/换行/横向可滚），
  ⛔ 不得直接切掉。
- **A-ov-treeonly**：只画**会话树**，⛔ 不得混入 choose-tree 的预览区内容。
- **A-ov-nogap**：面板不得出现大片空白（内容高度与面板高度要相称）。
