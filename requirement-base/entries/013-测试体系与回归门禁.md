# 013 测试体系与回归门禁

- 状态：已裁定
- 出处：用户提问 + leader 裁定，2026-08-09

## 五层测试体系

1. **定向单测**：秒级，跑在席位内环（开发时即跑），红测先行（先写断言再实现）。
2. **跨语言契约测试**：黄金夹具 `testdata/` 两端（Go 服务端 / Android 客户端）共用，
   拦截协议漂移。
3. **tmux 集成测试**：隔离 socket 上跑真实 tmux，不 mock。
4. **协议级 E2E**：无模拟器，Go harness 走全链路，验证 [[003]] 四标准的链路可达性。
5. **老化实验**：20 轮杀-恢复循环，验证无状态免疫（[[004]]）；flaky 靠复跑统计，
   不靠单次通过判定。

## 回归门禁

- **全量门** `tools/gate/run.sh` 一键并行 + 机器可读报告，支撑 [[010]] 生产级验收。
- **标尺 = 0 新回归而非全绿**：既有失败可接受，但不得新增回归；基线变动显式登记。
  与 [[008]] 生产级定位一致：质量底线用门禁兜住，不靠"全绿"做姿态。

## 测试数棘轮

用例数**只增不减**，减少即红——防删测试作弊。

## 失败四归因

product / harness / baseline / flaky 四类归因。**判错归因比失败本身危害更大**——
归因错误会掩盖真问题或误杀正确改动。

## 席位与门禁分工

席位只跑定向单测（内环），全量归门禁（外环）。
