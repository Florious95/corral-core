# 079 · 会话页触摸点击 → 转发鼠标事件（**未来目标，本轮不做**）

- 日期：2026-08-19
- 状态：🟡 **已记录，暂不施工**（用户 2026-08-19：「先把这一点记录下来吧。是之后的目标。」）
- 来源：用户提问「我在 Agent CLI 的会话页面，是否可以通过触摸去点击？比如一个工具调用，我点一下就可以把它的内容展开。」

## 1. 结论：可行，且**只有一条路**是对的

**做法**：触摸坐标 → 终端行列 → 编码成 **SGR 鼠标序列** → 走现有输入通道发给 tmux。
APP **完全不需要理解**「这一段是工具调用」，语义由 CLI 自己处理。

## 2. 前置条件已具备（leader 2026-08-19 只读实测）

```
$ tmux -S <sock> list-panes -a -F '#{window_name} mouse_any_flag=… mouse_sgr_flag=… alt=…'
claude_code    mouse_any_flag=1  mouse_sgr_flag=1  alt=1
ux2-v1-title   mouse_any_flag=1  mouse_sgr_flag=1  alt=1
advisor        mouse_any_flag=1  mouse_sgr_flag=1  alt=1
```

- `mouse_any_flag=1` ⇒ **CLI 已经在收鼠标事件**。
- `mouse_sgr_flag=1` ⇒ 用的是 **SGR 编码**（现代模式，坐标精确、不受 223 列上限）。
- `mouse_button_flag=0` ⇒ **不要求拖拽/移动上报，只要点击**，实现更简单。
- Claude Code 与 Grok CLI **都是**这个状态。

## 3. 另外两条路为什么不行

### ❌ APP 侧识别文本自己展开 —— **物理上做不到**
🔴 **折叠状态下，那些内容在终端里根本不存在**：CLI 折叠时压根没往终端输出那些字符，
tmux 里没有、传给 APP 的也没有。APP 拿到的是一张**已经渲染完的字符网格**，
**要展开的东西不在这张网格里**。识别得再准也变不出数据来。

### ❌ 让 CLI 输出结构化 JSON
那是**另一个通道**，不是「镜像主机终端」这件事；
且 Claude / Grok / Codex / Copilot / Cursor 各家格式不同，白名单里五家就得写五套。

## 4. 开工前必须先验的一条（⛔ 不许跳过直接写代码）

`mouse_any_flag=1` 只说明「它在收鼠标事件」，**不等于「点工具调用就会展开」**。
⇒ **先在隔离 socket 里起一个 CLI，直接往 pane 注一条 SGR 序列打在某个折叠行上，看它展不展开。**
验绿了再立判据派单。

## 5. 真正的难点不是技术可行性，是**手势冲突**

会话页同一块区域上已经有：
- **竖直滚动**（看历史）
- **横滑切页**（076 §2 刚修完，⛔ 不得倒退）
- **长按**（选文本 / 复制）

再加点击，必须先定清楚优先级：单指轻点 = 发鼠标事件，其余手势保持原样。
🔴 **这个优先级排错，会把 076 §2 刚修好的滚动再搞坏一次。**
⇒ 施工时判据里要带上「076 §2 的滚动不倒退」这条回归断言。
