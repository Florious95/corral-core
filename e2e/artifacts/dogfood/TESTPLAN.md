### 0.2 推导方法（骨架 = 016 九步 × 018 七条 × 红线五条）

1. **主干**：016(a)「真机首触零阻断」的九步清单逐步展开为 A 组用例——这是 016(c)
   「用户首触路径必须最先最重覆盖」的直接执行面。
2. **横切**：018 视觉七标准不作独立用例，而是**每一屏截图的固定目检清单**（见 §5 目检卡），
   任何一屏违反即缺陷；另对 018 明确点名而主干路径不必然走到的态（空态/错误态/深色）
   单列 B 组用例。
3. **支线**：017 八项裁定中标注「当期必做」的项（R-1/R-2/R-3/R-5/R-6/R-7/R-8）逐项成 C 组用例
   ——017 原文「任务书承诺不可赖账」，当期项缺失即欠账缺陷。
4. **红线**：根 CLAUDE.md 工程常识红线五条成 D 组用例（面向常驻运行的工程卫生，
   scenario-coverage §10 已给判定形状）。
5. **其余条目**：001/002/003/004/005/006/008/012 中未被 A–D 组覆盖的可观察行为成 E 组用例。
6. **探索性**：直觉/边界/破坏性场景单列 X 组，**与需求推导用例分开计数**，不进覆盖矩阵。

### 0.3 判定方式三选（每用例显式声明）

- **S = 截图目检**：`adb exec-out screencap -p` 落图，本席位亲自识图判定（018 七条 + 常识）。
- **U = 结构断言**：`uiautomator dump` 取控件树，断言文本/控件/bounds 存在与位置。
- **T = tmux/主机对账**：隔离 tmux `capture-pane` 或 daemon 侧文件/进程/日志核对。

### 0.4 严重度定义（REPORT 用）

P0 阻断（首触链路走不下去/崩溃/数据错）｜P1 影响使用（能走但明显别扭、需要用户自救）｜
P2 观感（视觉/文案层面不达 018 标准）。

## 1. 执行环境（隔离铁律）

| 项 | 值 |
|---|---|
| 模拟器 | AVD `wedding_user_a_api35`（API 35），本席位自启 `-no-snapshot -no-audio` |
| APK | 自打 `cd app && ./gradlew -q :app:assembleDebug` → `app/app/build/outputs/apk/debug/app-debug.apk` |
| 隔离 tmux | `TMUX='' TMUX_TMPDIR=/tmp/dg.XXXX/tmux tmux -f /dev/null` 自建 socket |
| 隔离 daemon | 自 build `server/cmd/agentmirrord` → `/tmp/dg.XXXX/dogfood-daemon`，`-listen 0.0.0.0:19983`，独立 `AGENTMIRROR_STATE_DIR` 与 `-upload-dir` |
| App 连接地址 | `ws://10.0.2.2:19983/ws` |
| 收尾 | trap 杀 daemon + `tmux kill-server` + 删临时目录；**退出自证零监听零孤儿** |

**绝对禁触**：生产 daemon（用户手机正连着）、用户真实 tmux（默认 socket 与 team-agent 私有 socket）。
所有 `pkill` 只按自建二进制名 `dogfood-daemon` 精确 scoped kill。
