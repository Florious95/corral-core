## 3. 本版含什么

- **白屏根因修复**：`ConnectionManager` 由**单一全局 listener 槽**改为**按 ref 分发**。
  根因 18/18 零反例：订阅首帧被列表页 `WorkspaceViewModel` 吃掉，会话页 VM 一帧都拿不到。
  铁证行：`ev=first_frame_recv emitted=0 reason=has_listener listener_null=0 listener_ref=…WorkspaceViewModel`
- **PerfTrace 八事件全链仪表**：`tap → route_enter → subscribe_sent → geom_seed →
  first_frame_recv → snapshot_applied → first_draw → layout_settled`。
  Debug 级；`adb shell setprop debug.agentmirror.perftrace 0` 可关；关时调用点最外层短路。
  每事件带**参与比较的两边操作数**；守卫没走通时打 `emitted=0 reason=`（⛔ 不算完成事件）。
- **服务端** subscribe 三时间戳：`perf_subscribe / recv_ms / start_ms / done_ms / queue_ms`
- **三核模块切分**：`:core-protocol` / `:core-terminal` / `:core-conn`，零 `import android./androidx.`
- **corral-app 引用式构建暂存工程**：`.team/staging/corral-app`，composite build 可装出 APK

## 5. 怎么用这条地板

1. 每个改动包，用**完全相同的流程与环境**复测，落 `.team/perf/recheck-<日期>-<名>.json`；
2. 跑 `tools/perfbase/judge-perf-nonregress.sh`：逐夹具逐段比 p50/p95，超基线 **+10%** 即红；
3. ⛔ 不许换夹具、换次数、换取数方式来让它变绿；
4. 模拟器绿**只是回归下限**，**最终判据永远是用户真机「秒开无空白」**。两道门都要过。

## 6. 本基线未修的已知缺陷（另案）

- **tsnet 身份分裂**：`TsnetWire.stateDirForKey` 按 auth key 的 SHA-256 分状态目录，
  而 `sanitizeHostname` 恒为 `agentmirror-<机型>` ⇒ 换 key 会注册出**同名**新节点，
  旧节点占位可致 `tsnet.Up: context deadline exceeded`（表现为「一直入网中最后失败」）。
  绕过：删掉 tailnet 里旧的同名设备。修法待裁：①设备级单一 state dir（更贴合「始终是同一台设备」）
  ②或把 key 指纹并进 hostname（只让冲突可见）。
- **`GomobileTsnetBackend.start` 全程零日志**：入网失败只有一句 deadline，
  分不出「同名冲突」还是「网络不通」。修 tsnet 之前先补这段留痕（带两边操作数）。

## 7. 排查顺序的实撞教训（2026-08-22）

「重连变慢」当天被怀疑成服务端回退，实际是**手机 VPN 设成全局转发**、tailnet 流量被套一层；
改成分应用转发并排除本 app 即恢复。而服务端二进制**一夜未动**（`agentmirrord-night-4120c0884`）。
⇒ **先问网络路径，再疑代码**；「回退服务端」之前先确认它现在到底是哪个版本。
