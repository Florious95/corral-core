# 编排方法论 —— 在全自动编排之上长出来的那一套

- 立文：2026-08-21
- 来源：**不是设计出来的，是撞出来的**。下文每一条都指向一次真实事故或一次真实打回，
  出处写在条目里。⛔ 没有出处的条目不许往里加。
- 边界：**全自动编排（`ledger-orchestration` + `team-agent`）是基础设施，不归本工程改**。
  本文只讲**我们怎么用它**。框架侧的缺陷走 `.team/artifacts/ledger-trial-findings.md`。

---

## 0. 一句话总纲

> **判据是唯一的真相来源；席位、基底、PR、并线，全都是为了让判据说的话可信。**

推论：凡是让判据变得「不那么可信」的动作，都是本方法论要禁止的——
包括我自己写出一个恒真判据、包括让一个必然会红的东西冒充先验红、
包括让判据在两条路径里只验过一条。

---

## 1. 知识基底：席位不许凭空猜架构

### 1.1 基底是**算出来的**，不是写出来的

```
taskbook/账本的 write_paths
   → tools/basegen_ledger.py 现算模块影响闭包
   → .team/nodes/<格>/BASE.md
   → 内联进派单正文
```

**正向依赖 = 你消费的契约；反向依赖 = 你的回归自查范围。**
闭包来自 `docs/wiki/README.md`，而那份维基是 **`tools/archwiki/build_wiki.py` 从代码注释现算**的。

### 1.2 于是「写合规注释」不是洁癖，是**下一个席位能不能干活**的前提

注释不合规 ⇒ archwiki 少节点少边 ⇒ 下一格拿到的基底是残的 ⇒ 它凭空猜架构。
⇒ **每个实现格的机械判据里必须含 archwiki 检查**，⛔ 不能只在最后统一跑一次。

### 1.3 派单正文 = 席位的唯一任务书

🔴 **席位只读两样：派单正文 + 它自己的任务书。**
写进 skill / CLAUDE.md / 本文的规则，**席位一个字都看不到**。
⇒ 凡是要求席位遵守的，**必须逐份抄进派单正文**。这是绕法不是原生支持，别指望它自己生效。

### 1.4 ⛔ 别把「方案全文」当任务书甩给席位

**实撞（2026-08-21，t.e8）**：我把 `方案.md` 给了席位，而它的 §1 列着**全部 7 个 PR 的施工顺序**。
席位照着一路往下做，在一个 worktree 里连建四条分支切来切去，
E8 的交付被提交到了 `pr/e7-scroll-hint` 上，封版判据判红。
⇒ 给方案可以，但**必须同时写死「⛔ 本格只做这一条，方案里其它 PR 不归你」**。

## 2. 席位：分族、异源、轮转、额度

### 2.1 一族知识基底一个席位

**用户令（2026-08-21）**：「第一个 PR 和第二个 PR 没什么关系，知识基底都不一样，
就不能让他继续审查，你就要重置他的角色。」

落法**不是**靠 leader 记得在正确时刻重置（无人值守时 leader 不一定在场），
而是**一族一席**——换族＝换席＝新上下文，**结构性生效**：

```
pr2-judge-listui   纯 App 列表 UI
pr2-judge-proto    协议 + 服务端 + 设置
pr2-judge-input    输入区（session/）
```

同族多格共用一席 ⇒ **必须共用同一个 `worktree_id`** 强制串行，否则引擎认为可并行，
会在同一秒对同一个 pane 连投两次（实撞：`send_unverified_exhausted`）。

### 2.2 评审必须异源，且 provider 由 leader 定

实现走 grok，评审走 Claude 订阅（**2026-08-21 起评审席固定 Opus 5，⛔ 禁 Fable 5，⛔ 禁 Deepseek**）。
异源不是形式：**同源评审看不出自己那套思维定式里的洞**。

### 2.3 🔴 角色文件里有两个字段**只在启动时生效**

`dangerously_skip_permissions`、`model`。
**改文件不够，`reset-agent` 也不够**，必须 `remove-agent --force` + `add-agent` 重建，
并**读 pane 自证**（底部应显示 `Opus 5` / `bypass permissions on`）。

**实撞**：`pr1-judge` 我写了 `dangerously_skip_permissions: false`（想着「只读席不需要绕权限」），
结果它每跑一条 `git show` 都停下等按 Yes，**永远卡在第一个提示上**。

### 2.4 ⛔ 席位不许写 `/tmp` 或任何项目外路径

各家 provider 对「项目外路径」的默认策略不同，**靠加权限治不了根**。
临时文件写 `.team/nodes/<格>/tmp/`。好处有二：整类确认提示消失；临时产物留在仓里可回看。
（后来 `t.close` 席位把先验红原始输出落进 `tmp/prior-red-*.txt`，评审席才能独立复核——这是意外收获。）

### 2.5 额度是硬墙，要提前看

**实撞**：三个实现席全是 grok，跑到一半 `Weekly limit left: 0%`，链 B 三格一行没动。
⇒ **开工前看一眼各席的额度行**；撞墙不是故障，⛔ 不走恢复流程（重起只会再重派给开不了工的席位）。

## 3. PR 链：把「已完成」和「已接受」分开

### 3.1 为什么 commit 不够

| | commit | PR |
|---|---|---|
| 回退单元 | ✅ | ✅ |
| **「已完成」与「已接受」分离** | ❌ 提交即在线上 | ✅ |
| 评审单元 | ❌ | ✅ |
| **门（不过就进不了线）** | ❌ | ✅ |

### 3.2 四个动作，四个不同的人/时机

```
提 PR  →  测 PR        →  审 PR         →  land
席位      驱动器跑判据      异源评审席        判据自动并线（脚本再验一次 verdict）
```

- **⛔ land 不由产出方顺手完成。**
- `land-pr.sh` **自己再验一次 `VERDICT: supports`** 才动手——**判据执行顺序不保证**，
  不能假定 `A-*-rv-pass` 一定先跑过。⇒ **评审判 refutes 就不会并线，裁定是真的门。**

### 3.3 封版（seal）：引擎不让席位 commit，就由 leader 代提交

**实撞**：派单信封里有引擎自己加的硬约束「不跑 git commit / push」，
于是席位的改动只以**未提交工作区**存在，分支上一个 commit 都没有 ⇒
**没有 PR 可提、没有 diff 可审、也没有东西可以 land**。评审席自己发现的。

⇒ `tools/gate/seal-pr.sh` 作为每个实现格的判据，在**评审席被派单之前**把 sha 固定下来。
理由只有一条：**评审必须审「最终会并线的那一份」**，未提交的工作区不保证这个性质。

⚠️ **这是绕法，代价三条，一条都别忘**：
1. 判据里做了有副作用的事（提交），**不是纯判据**；
2. 封版是**无差别提交**（`git add -A`），带进过构建垃圾；
3. **链内共享 worktree + 封版** ⇒ 曾把 E1 的提交封进 E2 的分支，
   导致 E2 的 PR 背着一份**被否决的交付**，评审席按「超范围」判红，后续还撞出真合并冲突。

### 3.4 ⛔ 不在 GitHub 网页点 Merge

远端是 `filter-repo` 过滤后的镜像仓，网页合并会造出本地没有的 commit，
下次镜像会被**祖先闸**拦死（那道闸是对的，别绕它）。

### 3.5 分支污染的正确修法：让上游先落 main，⛔ 不手工合并产品代码

手工解冲突是最容易**悄悄改变语义**的地方。派回给实现席 rebase，并写死
「解冲突时上游部分一律取 main 的版本，⛔ 不许借机改上游语义」+ **要求自证** diff 里不再含上游文件。

## 4. 判据方法论（本文最要紧的一节）

### 4.1 三铁律

1. 判据要断言「**世界变了**」；
2. **写完先验红**——改之前跑一遍必须红，**原始输出必须贴进说明**；
3. 要能**区分两个同形世界**。

### 4.2 🔴 「必然会红的东西」不能冒充先验红

**两次打回都栽在这里**（`t.resync` / `t.compose`）：
说明里贴的先验红是 `A-*-doc` 的 `hit=[]`、`A-*-seal` 的 `seal_exit=1`——
**文件还没写、分支还没提交，它们当然红**，与缺陷本身毫无关系，**区分不了功能判据是否恒真**。

⚠️ 而**我自己看那份说明时没看出来**：我的 `A-*-doc` 判据检查的正是「说明里有没有『先验红』这三个字」，
**判据被字面满足了，语义没有**。

**正确姿势**（评审席给的）：写一条**只用既有 API** 的最小红测，这样它在改前的代码上也能编译。
例：`onPassthroughInput(tv("prev-command"), tv(""))` 改前发 **0** 个 BackSpace、改后发 **12** 个。

### 4.3 🔴 判据会在别人改动之后**悄悄变成恒真**

**实撞（`t.provcmd`）**：`TabScrollTest` 有两个断言分工不同——
`assertIsDisplayed` 管「够得着」，`lastFullyAboveTabs` 的 bounds 比较管「**够得着但被底栏切掉**」
（原作者故意不用 `assertIsDisplayed`，因为 Compose 对**部分可见**节点也判 displayed）。
加了第六张卡后，bounds 断言指向的那张卡滚出了上方 ⇒ **该断言恒真化**，
而真正的最后一项**没有任何断言看着它**——**失败文案还写着「最后一项仍被切断」，量的却是中间那张卡**。

⇒ 改测试时，**换目标不等于补牙**。换完必须**重新先验红**，证明新断言真的会红。

### 4.4 存量红：判据要「不许新增」，⛔ 不是「必须为 0」

**实撞**：main 上本来就有 33 条坏味道、若干条 archwiki T3 违规。
把「必须全绿」设成每格判据 ⇒ 席位为**不是自己造成的红**卡死，还会被逼去改无关代码。

⇒ 增量棘轮：`tools/gate/smell-ratchet.py`、`tools/gate/wiki-ratchet.py`，
**逐条点名新增了哪几条**（含文件行号），⛔ 不许 `--freeze` 洗基线。
**T1 类硬约束（环依赖 / 包 doc）仍必须全绿，不走棘轮。**

### 4.5 🔴 一个制造伪阳性的判据，比没有判据更糟

**实撞**：棘轮最初按 `文件:行号` 做键，**上面加一行 import 就把所有存量判成新增**，
席位被逼着加 `@Suppress("ModifierParameter")` 去压制真实告警。
**它扭曲的是激励，不只是噪音。**⇒ 键改为 `(工具:规则:文件)` 计数比对，去掉行号。

### 4.6 🔴 验判据本身，也要**两条路径都走**

`land-pr.sh` 连红三次，全是脚本自身的问题，成因同一个——**我只验了一条路径就当它可信**：

| 次 | 缺陷 | 阳性对照为什么没抓到 |
|---|---|---|
| 1 | `$BR` 紧跟全角括号被 bash 吞进变量名 | 只喂了 `refutes`，**根本没走到并线代码** |
| 2 | 仓根未跟踪同名副本挡住 merge | 没造出「仓根有副本」这个条件 |
| 3 | 幂等检查顺序写反，**已并过的分支重跑反而判红** | 没验「重跑一条已成功的判据」 |

⇒ **判据必须可重跑**（这也是 `ledger-orchestration` 的硬要求），
且**拒绝路径与通过路径都要各验一次**。

### 4.7 判据里写绝对路径要当心引擎改写

引擎会把裸 argv 里的绝对路径改写进 worktree。绕法：**路径塞进 python 字符串**。
另：产物可能落在仓根，也可能落在本格 worktree ⇒ **判据两处都找**。
⚠️ 这是**措辞修正不是放宽**——判据断言的是「文档内容含哪些要素」，产物在哪个目录是管道不是断言。

## 5. 打针（改运行中的账本）

### 5.1 ⛔ 席位在途时不打针

**每次 `revision` 前进，驱动器会把整个前沿重派一遍。**
我为了修自己写错的判据连打十几次针，制造了大量重复投递与 `send_unverified_exhausted`——
**那一串「投递失败」大部分是我自己造的。**
⇒ 改判据**攒起来批量做**，等一轮判据跑完的空档再 bump。

### 5.2 打针要留证据，⛔ 不删

失败 attempt 会**把格挡在前沿外**，即使 `state` 已复位成 `planned`（恢复四步没写这条）。
⇒ 归档到 `.team/evidence/pr1-v1-superseded-attempts.json` 再从账本清空，**并写明为什么被作废**。
⚠️ 代价：**证据链断在账本之外**，重放账本时看不到这些红曾经发生过。

### 5.3 `write_paths` 划窄了是 leader 的错，但席位仍应报 `blocked`

**同一件事出现三次**（`t.close` / `t.provcmd` / `t.newpane`）：席位发现作用域不够，
**自行扩写并事后声明**，评审席一律按「超范围」判红。

两边都对，评审席的措辞我原样采纳：
> **声明比隐瞒好，但不构成豁免。**

⇒ leader：`write_paths` 要按**方案里真正会碰的文件**划，⛔ 窄到一格但别窄过头。
⇒ 席位：发现不够就**报 `blocked` 等一轮**，成本远小于返工一轮。

## 6. 判活与停滞

### 6.1 只认一把尺

`nodeprobe`（tmux 私有 socket）。
⛔ **不许用 `team-agent` 的 `worker_state` / `last_output_at`**——实测它把正在 `Thinking` 的席位
也一律报 `PROBABLY_IDLE`。⛔ `unknown` 绝不能当 `idle`。

### 6.2 「席位全 idle」≠ 停滞

编排的活在两层之间转移：**席位干活 → 驱动器跑判据（此时席位本来就该 idle）→ 再派下一格**。
判停滞要**两个条件同时成立**：席位全 idle **且** 有实质进度信号不再增长。

🔴 **进度信号用账本 `revision`/mtime，⛔ 不要用驱动器日志 mtime**——
实撞：账本从 rev17 推到 rev20（含两次 land 落盘）期间，**日志一行都没长**（stdout 缓冲）。
起驱动器时加 `stdbuf -oL` 可缓解，但**账本才是权威**。

### 6.3 席位卡住先**读屏**，⛔ 不按错误串的建议重投

`send_unverified_exhausted` 这一条串，一天之内对应了**四种处置相反的真因**：

| 真因 | 处置 |
|---|---|
| 卡在 provider 确认提示 | 重建席位 / 给 bypass / 不越界 |
| 两格同派一席（账本漏互斥） | 改账本加互斥 |
| **席位正忙（回合中）** | ⛔ **别动** |
| 消息入队未提交 | 等它自己冲队列 |

读屏：`tmux -S <team 私有 socket> capture-pane -p -t <pane>`。
⚠️ 「消息入队未提交」那一种**我方无法自愈**——⛔ 禁 `tmux send-keys` 是绝对禁令，
我不能替它按回车，只能重建席位并丢掉上下文。

### 6.4 告警要盯「现在真正卡在谁身上」

驱动器 park 住等人决定时，**停掉它并删 pid 文件**，否则告警立刻自触发。
**一个立刻自触发的告警等于没有告警**，而且会训练人去忽略它。

同理：**已知答案的状态不要挂告警**（撞额度那次我就没重挂）——产出的不是信息，是噪声。

## 7. leader 的自律

1. **⛔ 不亲手写产品代码**，包括手工解合并冲突（那是最容易悄悄改变语义的地方）。
2. **判据红了先问「是不是我的判据错了」**——本轮 `t.recon` 返工 6 轮里 4 轮是我的判据假红，席位一次没错。
3. **⛔ 判据红了不许改判据让它变绿**。判据本身写错可以补强/澄清，
   但**必须向用户明说是语义变更还是措辞修正**。
4. **拿到打回先读完，⛔ 不要急着判「席位偷懒」**——四次打回里，
   两次是席位的先验红不合格、**三次同时暴露了我的账本或工具有错**。
5. **对外部框架队**：唯一配合项是**换用他们发布的新基础设施**（按 **inode** 自证，⛔ 不按版本号）。
   ⛔ 不为他们做复现取证。缺陷写进清单，**投前必须验活**——
   `ok: True` 不是送达，投给死队照样返回成功。

## 8. 这套方法论买到了什么（诚实结算）

**两波共 34 格全部走完「提 PR → 测 PR → 审 PR → land」。**
**四次被异源评审席打回，没有一次是靠放宽判据过的。**

评审席抓到的、而我自己看说明时**没看出来**的：
- 两次「用必然会红的机械判据冒充功能先验红」；
- 一次「判据在这次改动之后悄悄变成恒真，失败文案量的却是另一张卡」；
- 一次「说明写『棘轮恒绿』，而它自带的证据文件第一行是『红：本次引入了新的架构维基违规』」
  ——⚠️ **说明往好里写是最危险的一类问题：它让下一个读者信错东西。**

它还主动核了我**没在派单里要求它核**的两条安全红线（服务端拒绝空 socket、只取 `comm` 不取 argv），
并把一条真正需要人裁的契约问题**升报**给我而不是自己拍板。

**代价也照实记**：四次打回里三次的直接原因是我的账本或工具有错，
返工成本全部由席位承担；`land-pr.sh` 连红三次全是我只验了一半路径。
⇒ **这套方法论目前最大的瓶颈不是席位，是 leader 的判据质量。**

## 9. 🔴 事故补记：判据只盖了半个仓（2026-08-21，两波收官后当场撞上）

两波 34 格全绿、13 条 PR 全部 land、12 份评审全 `supports` 之后，
**全量门在 main 上报出真回归**：

```
server  cases 353 → 248（棘轮下行）  真单测失败 3
  ❌ cmd/agentmirrord (package failure)
  ❌ internal/api  (package failure)
  ❌ go vet
```

**根因**：`server/internal/api/lifecycle.go:252` 的**生产代码**调用了
只定义在 `server/internal/api/tmux_test.go:157` 里的 `scrubbedEnv()` ⇒
`go build` 失败，但 `go test` 能过（测试构建包含 `_test.go`）。
**席位不是没测，是它测的那条路盖不住这个洞。**

### 我的错：判据只盖了 app 面
`t.close` / `t.newpane` 改了 `server/internal/protocol/` 与 `server/internal/api/`，
而它们的机械判据是：

### 立成规矩
1. **格的判据必须覆盖它 `write_paths` 碰到的每一面。**
   碰 `server/` ⇒ 必须有 `go build ./... && go vet ./... && go test ./...`；
   碰 `app/` ⇒ gradle 套件。⛔ 不许只跑其中一面。
2. **`write_paths` 与判据要对着写**：账本作者填完 `write_paths` 后，
   逐条问「这一面有门吗」。⛔ 这一步不做，就会出现「改了没人看的半个仓」。
3. **生产代码调用 `_test.go` 里的符号，`go test` 抓不到，只有 `go build` 抓得到。**
   ⇒ `go test` **不能替代** `go build`，两条都要跑。
