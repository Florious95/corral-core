# 教训 · 环境中间变量伪造出一次「性能回退」（2026-08-23 用户真机实撞）

> 用户裁定：「**一旦这种中间变量导致回退，就有可能极大地影响我们的测试以及回归测试，
> 就会极大地影响我们定位的成本。**」

## 一、事件

用户在真机上报：**「打开会话不是很迅速，没有之前迅速。局域网的情况下白屏时间那么长。」**
追加：**「它还在不断地重绘整个 Terminal 界面。」**

这是对 2026-08-22 金标准（真机「秒开无空白」）的直接回退。

## 二、排查过程与每一步的判据

**第 1 步：先确认两端到底变没变**（⛔ 不是先看代码逻辑）

| 检查 | 命令 | 结果 |
|---|---|---|
| 服务端源码 | `git log --oneline baseline-20260822-release..main -- server/` | **0 个提交**，diff 为空 |
| 生产二进制 | `lsof -a -p <pid> -d txt` | `agentmirrord-night-4120c0884`，**连续跑 33 小时** |
| 该二进制与基线关系 | `git merge-base --is-ancestor` | 是基线的**祖先**（比基线还旧） |
| 手机 APP | 用户原话 | **没变过** |

⇒ **两端都没变，体验却退了。**这一步直接排除了「回退服务端」这个动作——
用户本来要求「把服务端回退到基线水平」，而**服务端根本没离开过基线**，
回退是空操作，做了会白白浪费用户一轮真机测试。

> 📌 **教训 A**：用户要求回退某个组件之前，**先证明它真的变了**。
> 「回退」是一个昂贵动作（要占用户一轮实测），基于错误前提的回退是纯浪费。
> 判据是三条同时看：**源码 diff + 运行中二进制身份 + 该二进制与基线的祖先关系**。

**第 2 步：可观测性当场归零**

- daemon 的 stdout/stderr → `lsof -a -p <pid> -d 1,2` 显示**都是 `/dev/null`**
- HTTP 路由只有 `/ws` 和 `/upload`——**没有 pprof、没有 stats、没有 healthz**

⇒ 关键路径上的进程**全程不可观测**。当天能查出根因靠的是外部采样（`top`）+ 读源码，
**不是它自己的留痕**。

> 📌 **教训 B**：不可观测的生产进程是**定位成本的放大器**。
> 本工程已有「诊断日志纪律」，但那条只管**代码里记什么**；
> 这次暴露的是**运维层**：日志被丢进 `/dev/null` 等于代码里记得再好也白记。

**第 3 步：量环境，不量代码**

```
daemon 空闲 CPU 连续采样：0.0  17.0  33.6  21.6  34.3  33.7  27.4  18.2   (%)
内存 21MB（有界，正常）
```

只有 1–3 个订阅者、没人操作，CPU 稳定在 18%~34%，**周期性 0%→30%+**。
这违反本工程「工程常识红线」第 1 条：**静默经济——空闲 CPU 趋近 0、无固定频率子进程派生**。

**第 4 步：定位到中间变量**

```
/private/tmp/tmux-501/   socket 总数 161
    连不上（死的）        140
    活着                   21（含用户真实 default）
```

根因在 `server/internal/discovery/scan.go:152`：

```go
cmd := exec.CommandContext(ctx, "tmux", "-S", socketPath, "list-panes", "-a", "-F", paneFormat)
```

`DiscoverWithDirs` **对目录里每一个 socket 文件串行 fork 一个 `tmux list-panes` 子进程**；
死 socket 只有在连接失败之后才被跳过（源码注释写的是「stale socket … 正常，跳过并继续扫描（红线）」——
**跳过是对的，但代价已经付了**）。

`list-interval` 缺省 **2s** ⇒ 每 2 秒 fork 161 次，其中 140 次注定失败 ⇒ **约 80 次 fork/秒**。

三个症状全部对上：
- **CPU 周期性尖峰**（2 秒一波）
- **打开会话白屏久**（订阅要跟这个扫描抢 CPU 与进程表）
- **不断整屏重绘**（扫描结果抖动 ⇒ 反复推 list_delta / 快照）

**第 5 步：止血并当场验证**

只删掉 140 个**已确认连不上**的 socket（`tmux -S <f> list-sessions` 失败即判死），
⛔ 不改代码、⛔ 不重启 daemon、⛔ 不碰活着的 21 个。

| | 清理前 | 清理后 |
|---|---|---|
| daemon CPU 采样 | `0.0 17.0 33.6 21.6 34.3 33.7 27.4 18.2` | `0.0 0.2 2.6 0.1 7.1 2.0 0.0 2.4 0.0 2.9` |
| 均值 | **≈23%** | **≈1.7%** |

**降一个数量级。用户复测：「变好了」。**

删除清单留档：`.team/nodes/t.idlecpu/tmp/deleted-dead-sockets.txt`

## 三、这些死 socket 是谁留下的

**是我们自己的测试。** 当天跑了 e2e、按键回显量具、三轮 A/B 性能测量、多个账本 worktree，
每一个隔离 tmux 都在那个目录里留下 socket。2026-08-22 用户测金标准时数量还不多，
一天之内涨到 161。

> 📌 **教训 C（本篇核心，用户点名的那条）**：
> **测试自身留下的环境残留，会伪造出一次「性能回退」——而且两端代码都没变。**
> 后果是双重的：
> 1. **回归测试失去意义**：环境脏的时候，绿是假绿、红是假红。
>    当天前三轮 A/B 测量（120+120+120 样本、约 4 小时）就是在这个环境里做的，
>    结论全部作废。
> 2. **定位成本爆炸**：因为「代码没变」这个事实会把人推向错误方向
>    （怀疑量具、怀疑统计口径、怀疑网络），真正的变量在**没人看的地方**。

## 四、由此固化下来的规则

1. **性能测量／回归测试开跑前必须先过环境闸**：`sh tools/perfbase/envcheck.sh --gate`
   （检查死 socket 数、load1、残留模拟器、生产 daemon 空闲 CPU）。
   **不达标一律判「不可判」（exit 2），⛔ 不判通过也不判失败**——
   环境脏的时候那个数字本来就不承载信息。
2. **谁留下的谁清**：任何用了隔离 tmux／隔离 daemon／模拟器／worktree 的格，
   收工必须清干净并在说明里写清「起了什么、停了什么」。⛔ 不许攒到下次。
3. **报「性能回退」之前先量环境**，顺序固定：
   ① 两端代码到底变没变（源码 diff + 运行中二进制身份）
   → ② 环境（死 socket／load／daemon 空闲 CPU／连接数）
   → ③ 才轮到代码逻辑。
   这与 2026-08-22 那条「先问网络路径，再疑代码」是同一类，**本篇把它扩到「先问环境」**。
4. **关键路径上的进程不许无留痕**：stdout/stderr 指向 `/dev/null`、
   且不暴露任何诊断端点的生产进程，视为运维缺陷，另案修。

## 五、仍未修的（本篇只止血，⛔ 不是修复）

- **`scan.go` 的扫描本身**：只要有人再留下死 socket，问题**原样复发**。
  待修方向（未裁定）：失败的 socket 记入短期黑名单／先用 `net.Dial` 探活再决定要不要 fork／
  并行 + 更短超时。归 `ledger.idlecpu.v1`。
- **daemon 不可观测**：日志进 `/dev/null`、无 pprof／stats 端点。另立格。
- **`list-interval` 缺省 2s 是否合理**：在 pane 规模大的机器上，即使全是活 socket 也不便宜。

## 六、同日附带的量具教训（与本篇同源：都是「测出来的东西不可信」）

- **同一个 A 包在两轮之间自漂：中位 14.6%，最大 25.4%**（release、load≤12、n=20 都达标）。
  ⇒ 量具自身重复性差于要检测的 10% 效应。
- **不配对的组中位数会把慢漂移当成效应**：`big_scrollback layout_settled`
  旧口径 +13.5%，配对（`median((B_i−A_i)/A_i)` + bootstrap CI）之后只剩 **+1.1%**。
  两轮共 12 段配对后 **CI 全部盖住 0** ⇒ 那两次 FAIL 都是口径产物。
- **这台量具在 n=20 时只能分辨 26.7%~34.3% 的效应**；要压到 10% 需约 140–240 对样本。
- ⇒ **用户真机永远是最终判据**；量具给的绿或红都不能推翻它。本次正是如此：
  量具在 4 小时里给了三个互相矛盾的答案，**用户一句「白屏很久」直接指向了真问题**。
