# 性能关键路径

打开会话从点到排布定住的八个 PerfTrace 事件。边界按**代码位置**划，不按仓名：
`app/core-*` = **核**，`app/app` = **壳**。

本表只钉事件的**产品调用点**（真实存在、判据 `test -e`）。不写模块名，不把解码器、主题、列表 UI、测试塞进来——那些不在这条打开链路上，写进去会让 `judge-perf-touched.sh` 天天误报。

切分后 ConnectionManager 已在 `:core-conn`，故 `subscribe_sent` / `geom_seed` 标核；其余六条 emit 在壳。`layout_settled` 的 500ms 结算在壳的 PerfTrace，重排触发源与订阅同文件（核，已在监视表）。

| 事件 | 在核还是在壳 | 文件 | 慢了会表现成什么 |
|---|---|---|---|
| tap | 壳 | `app/app/src/main/java/dev/agentmirror/app/MainNavState.kt` | 点了会话行还停在列表，像没点上 |
| route_enter | 壳 | `app/app/src/main/java/dev/agentmirror/app/session/SessionRoute.kt` | 导航动了但会话页迟迟不出现，空壳/白页 |
| subscribe_sent | 核 | `app/core-conn/src/main/java/dev/agentmirror/app/conn/ConnectionManager.kt` | 进了会话页却一直白屏：订阅帧还没发出去 |
| geom_seed | 核 | `app/core-conn/src/main/java/dev/agentmirror/app/conn/ConnectionManager.kt` | 画面挤成一团或大片留白，随后才抖到对的行列 |
| first_frame_recv | 壳 | `app/app/src/main/java/dev/agentmirror/app/session/SessionViewModel.kt` | 订阅之后长时间仍是空白（帧没到本页） |
| snapshot_applied | 壳 | `app/app/src/main/java/dev/agentmirror/app/session/SessionViewModel.kt` | 帧到了终端仍无字，白屏持续 |
| first_draw | 壳 | `app/app/src/main/java/dev/agentmirror/app/termview/TermSurfaceView.kt` | 模型已有内容，画布还不画，用户仍看见白 |
| layout_settled | 壳 | `app/app/src/main/java/dev/agentmirror/app/perf/PerfTrace.kt` | 已经看到字但仍跳行列、闪、反复重排，排布定不下来 |

## 改动纪律

碰上表任一 `app/**/*.kt`（以及同文件上的订阅/resize：`app/core-conn/src/main/java/dev/agentmirror/app/conn/ConnectionManager.kt`）的改动：

1. 必须落 `.team/perf/recheck-*.json`（形状同基线，极端值不剔除，只从 `adb logcat -s PerfTrace` 取数）。
2. 必须过不倒退判据 `tools/perfbase/judge-perf-nonregress.sh`（逐夹具逐段 p50/p95 相对基线超 +10% 即红）。
3. 守门脚本：`tools/perfbase/judge-perf-touched.sh <基线ref>..<待判ref>`。未传范围退出 2（不可判），不许默认放行。
4. ⛔ 不许拆 PerfTrace 仪表，⛔ 不许拆 `addBinaryListener` 按 ref 分发。
5. 关开关必须最外层短路：零分配、零拼串。
6. 优化必须高于基线 tag `baseline-20260822-release`；低于即红。
7. 本文只增删**这条打开链路上的调用点**。不要为了凑数把不在链路上的文件写进来。
