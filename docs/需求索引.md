## 本仓要实现什么：029 是主线

**[`requirement-base/entries/029-左中右三页架构.md`]** —— 状态「已裁定，**只入库不施工**」。
也就是说：**这条需求早就定了，一直没人做，它就是新 UI 的骨架。**

用户 2026-08-12 原话：「改成左中右三页。左页是收藏，中页是会话，右页是设置」

- **左页 · 收藏**：跨节点收藏会话列表，点进去直接进终端

关联条目：`028` 多节点（中页顶部那个选择器就是它）、`018` UI 视觉标准（三页布局必须过审查关）、`002` 两级分组（中页的工作区列表就是 cwd 聚合视图）。

## 一条对新 App 团队特别重要的历史

`corral-core` 的 `docs/archive/scroll-rounds-8-10/README.md` 记着一张表，
标题是「连续六次**验证的不是真正的被测对象**」。到 2026-08-14 收盘时这个数字是 **8**。

最贵的一次：设计文档里写着「鼠标字节注入实测证伪」，
而那次实测打的是 `less` 和 `vim` —— 两个都没开鼠标上报，收到鼠标字节当然没反应，
**从没测过 Claude Code**。这条错误结论被写成了测试断言，
于是后面十轮全部绕开了唯一对的那条路。

**动手前先问一句：我验的这个东西，就是用户在用的那个东西吗？**

对本仓尤其适用 —— 你写的是**壳**，而用户判定好坏的是**对话体验**。
壳上的单测全绿，跟用户能不能舒服地跟 CLI 说话，是两件事。
