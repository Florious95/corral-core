## 一、 核心诉求与战略目标

将 AgentMirror 从传统的「TUI 终端字符流镜像」升维为「**全主流 Agent 结构化原生 GUI 模式**」，并实现设置双模无缝切换：

1. **极致性能与高效流式传输（高于 TUI 的性能）**：
   - 彻底摆脱 ANSI 终端控制码与全屏重排刷新的带宽及算力消耗；
   - 采用结构化增量协议（JSON/Protobuf Delta），上下滑动看历史、大上下文翻阅、工具调用展开必须做到**零丢帧、零重排抖动、秒开秒定**。
2. **媲美 Codex App / Meta Muse 的现代化顶级审美（拒绝平庸粗糙）**：
   - 视觉精美度要能够与业界顶级的 AI 原生产品（OpenAI Codex App、Meta Muse、Claude Desktop / Zed）相媲美；
   - 在已有的 Liquid Glass（液态玻璃）与 Modernism 视觉基础上，给予高级模型充分的**自由审美与排版设计空间**。
3. **支持全主流 Agent Provider（首期客户端启动，保留标准启动参数）**：
   - 涵盖 **Claude (Claude Code), Pi, Codex, Cursor Agent, Grok**；
   - **首期实现**：由客户端发起新建/启动的 Agent 自动进入 GUI 结构化模式；
   - **长远兼容与启动参数规范**：明确每一种 Agent CLI 应当通过何种命令行参数启动，才能输出结构化协议供客户端转换为原生 GUI 展示。

## 三、 全主流 Agent CLI 启动参数规范与适配契约

为了实现客户端启动 Agent，以及未来其他方式启动的 CLI 能直接接入 GUI，必须制定标准启动参数契约：

| Agent Provider | 推荐结构化启动参数 (CLI Command) | 协议模式 | 数据通道 / 机制说明 |
| :--- | :--- | :--- | :--- |
| **Pi** (`@earendil-works/pi`) | `pi --mode rpc` | Pi RPC (JSONL) | stdin/stdout 传输纯净结构化事件（`message_start`, `tool_call`, `message_delta`），无 ANSI 控制码。 |
| **Claude Code** (Anthropic) | `claude --acp` 或 `claude-code --json-rpc` | ACP (Agent Client Protocol) | 标准 JSON-RPC 协议通道，双向交互，输出原生 content blocks 与 tool calls。 |
| **Codex** (OpenAI Codex) | `codex --stdio-rpc` 或 `codex app-mode` | JSON-RPC / ACP | 结构化交互模式，关闭交互式 TUI 字符屏，直通纯文本与工具元数据。 |
| **Cursor Agent** (`agent`) | `agent --acp-mode` 或 `agent --headless-json` | Headless JSON-RPC | 标准 Headless 协议，由服务端管道对接事件并格式化。 |
| **Grok** (xAI Grok Bot) | `grok --mode rpc` 或 `grok --jsonl` | JSONL RPC | 结构化事件流输出，支持 thinking 块与工具执行流。 |

> **长远运行规范（文档沉淀）**：
> 在用户使用任何外部终端或手动启动上述 Agent 时，只要在启动命令中追加上述参数（如 `--mode rpc` / `--acp`），服务端即能通过结构化握手识别并建立原生 GUI 会话；若未追加上述参数，则一律自动平滑接入原版 TUI 终端模式。

## 四、 传输架构与性能原则（严格禁止开第二条 Socket）

### 1. 单一连接复用原则（Single Connection Invariant）
- **上一轮失败教训**：在客户端另起一条 `/gui` WebSocket 会在真实生产 9900 环境（仅开放 `/ws`）触发 404 挂死，导致报错弹窗；
- **正确架构**：
  - **100% 复用现有的 `/ws` 物理长连接**；
  - 参照成熟的 `notifications_v1` 装饰器模式，在 `/ws` 上协商扩展 `conversation_v1` 能力；
  - 自动继承已验证的企业级网络红利：15s 双向 Ping、切前台瞬间自愈、Tailscale IP (`100.75.207.88`) 与局域网多路无缝选路。

### 2. 极致性能与重排收敛
- **结构化增量协议**：
  - 服务端直接推送增量 Delta 与工具状态机变更，带宽较 ANSI 终端降低 80% 以上；
- **Compose 渲染性能**：
  - `LazyColumn` item key 必须严格绑定到稳定的 `messageId` / `blockId`；
  - 流式文本打字机效果只触发当前 item 的局部重绘，绝不引起整页重排；
  - 向上回滚查阅历史万行对话时，采用虚拟化与分页机制，保持 60/120fps 跟手丝滑。

## 五、 交互设计与功能底线（兼顾自由审美）

1. **设置（Settings）双模切换**：
   - 提供「展示模式（Display Mode）」持久化配置：`TUI` 经典终端 vs `GUI` 原生对话；
   - 切换为 TUI 时，现有经典终端与底栏 100% 保持原有表现，零侵入、零破坏；
2. **极简输入底栏与斜杠命令补全（Slash Completion `/`）**：
   - 彻底隐藏 Esc/Tab/Ctrl-C 等终端按键；
   - 用户在输入框中键入 `/` 时，输入框上方以平滑微动效升起命令补全浮层（包含内置命令如 `/compact`, `/clear`, `/help` 及快捷指令）；
   - 支持点击一键自动填入并收起浮层；
3. **可折叠工具调用卡片（ToolCallCard）**：
   - 默认折叠：呈现工具图标、名称、状态呼吸灯、执行耗时摘要；
   - 点击展开：展示参数代码块、执行命令与输出结果（支持代码复制与高亮）；
4. **异常与重试优雅度**：
   - 彻底消除生硬刺眼的报错弹窗；遇到通道中断或重连时，以优雅的非阻塞式 Inline 卡片呈现，并提供平滑的「重新连接」操作。
