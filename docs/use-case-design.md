# AgentMirror 用例设计（由需求基派生）

- 日期：2026-08-14
- 性质：**设计契约**，不是新的产品裁定。产品行为的唯一权威仍是 `requirement-base/`。
- 派生范围：`requirement-base/entries/001`–`056`（截至本文件入库时的全量条目）
- 不是什么：
  - 不替代 `docs/scenario-coverage.md`（那是 2026-08-09 的覆盖审计，账实会过期）
  - 不替代 `test/inspection_design.md`（那是机器眼 Layer 1 的指标/棘轮设计）
  - 不替代 `docs/protocol.md`（那是字节级传输契约）
- 是什么：把需求基里**用户可见行为**编成可执行的用例目录，并映射到
  [[013]] 五层 / [[032]] 独立测试工程 / [[036]] 三层流水线。
  之后补自动化、派测试席、写未验证清单，都以本目录的 UC-ID 为索引。

## 0. 设计原则（从需求基抽出，不是新发明）

1. **覆盖跟着用户首触走，不跟着可自动化程度走**（[[016]] c）。
2. **自动化必要非充分，最终验收权在真机**（[[016]] b；[[010]] 验收 = 生产级安卓 App + 主机 daemon）。
3. **镜像层与状态层严格隔离**：状态判不出降 `unknown`，绝不拖垮镜像与输入（[[008]]）。
4. **验真正的被测对象**：Claude Code 是 `alt=1 hist=0 mouse=1` 的 TUI，不是裸 shell；
   协议层绿 ≠ 用户看见的画面对。缺真机的步骤进未验证清单，禁止计入已验收（[[016]] d）。
5. **流程类条目不是用户用例**。[[009]]/[[030]]–[[038]]/[[053]]–[[055]] 约束怎么干活，
   不进入本目录的主表（见 §8）。
6. **后置 / 只入库 / 再议仍给 UC-ID**，但施工状态显式标出——有编号才能排期，没有编号就会再丢一次。
7. **017 引用纪律**（REVISIONS R-005）：017 八项是 leader 自裁，不是与 001–010 同级的用户背书。
   本目录引用 017 时逐条回溯：能追到 003/007 的保留；R-5 通知开关已被 R-004 撤销，不立项；
   R-1 特殊键条追溯不到用户原话，标「待用户确认」。

## 2. 旅程总览

用户价值主链只有一条（[[016]] 首触清单展开）：

```
扫码/手填配对 → 舰队按工程可见 → 点开会话秒开 → 输入发送回显
    → 附件注入 → 需要时被叫 → 被杀/断网后画面还在
```

| 旅程 | 覆盖的用户问题 | 需求核 |
|---|---|---|
| J1 首触与配对 | 三件套叠 App、扫完没反应、连上假地址 | 001 / 007 / 011 / 016 / 017 R-3 |
| J2 舰队导航 | 私有 socket 看不见、平铺噪音、状态全灰或全错 | 001 / 002 / 008 / 012 / 023 / 025 |
| J3 对话与输入 | 逐键灾难、发出去没回执、图传 401、返回手势乱跳 | 003 / 017 R-1·R-2·R-8 / 021 / 022 / 042 / 044 / 048 |
| J4 终端保真与自适应 | 缩放字、键盘挡内容、退出后电脑被挤窄、历史滚不动 | 005 / 006 / 019 / 020 / 026 / 040–047 / 049 / 050 |
| J5 后台与唤醒 | 杀不掉就崩、blocked 不叫、点通知回首页 | 003④ / 004 / 016 |
| J6 联网 | 必须先开外部 TS、蜂窝不可用、多主机后置 | 007 / 024 / 027 / 028 / 039 / 056 |
| J7 异常与安全 | token 上屏、路径穿越、认证前乱帧 | 003 / 008 / 017 R-4 |
| J8 后置功能 | 三页/发现/主题/tmux 树 | 027–029 / 050–052 / 017 R-6·R-7 |

## 4. 主路径用例（写到可派测试席）

下面只展开**首触主链 + 对话四标准 + 自适应成对行为**。
其余 UC 的步骤从总表 + 对应需求条目即可还原；补自动化时按本模板扩写，不另起格式。

### UC-P01 扫码即连进舰队

- **前置**：主机已有至少一个 tmux 会话（含或不含私有 socket）；`agentmirrord` 冷启并在 stdout 打印 QR；手机首装或已清配对。
- **主路径**：
  1. 用户打开 App → 进入配对页（相机权限按系统弹窗）。
  2. 授权后取景识别 QR（载荷 = `v/url/token`，可选 `candidates`/`ts_authkey`）。
  3. UI 立即可见「已识别 · 正在连接 <地址>」，token 明文不上屏。
  4. `auth` → `auth_ack.ok=true` → 进入工作区列表，而不是停在配对页沉默。
- **怎么坏**：扫完无进度无报错（历史缺陷 B）；QR 选中 198.18/169.254（历史缺陷 A）；权限拒绝卡死。
- **可见结果**：3s 量级进入非空或空态设计过的列表；失败必有人话原因 + 可重试。
- **层**：扫码识别 L3；auth 成功 L0 已有。L2 虚拟相机注入属后置（原 e2e-scan-emulator）。

### UC-P06 错 token 被拒

- **前置**：隔离 daemon，token 已知。
- **主路径**：连 WS → `auth(wrong)` → `auth_ack.ok=false` 且带 reason → 连接关闭。
- **怎么坏**：关连接但不说原因；reason 或日志回显 token。
- **可见结果**：`test/cases/auth_reject.test.js` 现有断言；App 文案不含 token 值。
- **层**：L0 必跑；L1 映射文案。

### UC-F01 + UC-F02 私有 socket 舰队按工程出现

- **前置**：主机同时存在默认 tmux server 与 team-agent 私有 socket；两 socket 下有相同与不同 cwd 的 pane。
- **主路径**：sidecar 启动（不重启任何 agent）→ listing 含全部 socket 的 pane → 按 cwd 聚合成工作区 → 工作区内条目是会话。
- **怎么坏**：只扫默认 server（产品命题失败）；按 session 名分组；同 cwd 被拆成多个「工程」。
- **可见结果**：列表键 = cwd；二级标签 = window_name（UC-F03）；首页会话数 = 聚合后计数。
- **层**：L0 应在隔离环境起**两个** socket（现有 workspace 用例只有一个隔离 server，不够）。

### UC-F04 聚合状态

- **前置**：同一 cwd 下至少 4 个会话，状态可被测试夹具写成 blocked/done/working/idle/unknown。
- **主路径**：服务端算聚合，客户端只渲染。
- **断言表**：

  | 会话集合 | 聚合 |
  |---|---|
  | idle + working | working |
  | working + done | done |
  | done + blocked | blocked |
  | idle + unknown | idle |
  | 全 unknown | unknown |

- **怎么坏**：客户端自己推一次优先级；unknown 把整组拉成 unknown；blocked 被 working 盖住。
- **层**：L0/L1。这是 012 的可计算核，不依赖真机。

### UC-F06 状态层失败不影响镜像

- **前置**：某 pane 无法识别 agent（超时 / 未知 CLI）。
- **主路径**：该条徽章 = unknown；subscribe / input / 快照仍成功。
- **怎么坏**：unknown 导致不能打开、不能输入、或整页灰死。
- **层**：L0。

### UC-S01 + UC-S02 输入零延迟、发送必达

- **前置**：已订阅一真实 pane（优先：能回显的 bash；发布前必须在 Claude Code 上 L3 复验）。
- **主路径**：
  1. 用户打字 / 改字 / 选词：零网络帧。
  2. 点发送：一条 input（整段 + 回车），本地立即进入「发送中」。
  3. `input_ack` 成功 / 失败 / 超时 / 断连 四态必达其一，不允许「发出去了没反应」。
  4. pane 出现该文本（对会自己回显的 CLI）。
- **怎么坏**：逐键转发；ack 成功但 pane 无字节（验错对象：只断言 ack）；冗余 resize 把整屏当新快照重推（[[026]]/d27）。
- **层**：L0 已有 d27/d37；L3 验中文 IME 与 Claude Code 回显。

### UC-S07 图片落盘注入

- **前置**：已配对；pane 是会打印路径或能读文件的 CLI。
- **主路径**：选图 → multipart 上传（Bearer = 运行时 token）→ 主机落盘 → 路径进入附件区（UC-S10）→ 发送时注入 CLI。
- **怎么坏**：头写了 Bearer、运行时 token 是空（[[021]]）；401/413 无文案；路径进了输入框当用户文本。
- **层**：L0 可测「带 token 的上传 + 路径回到客户端」；相册/拍照 UI 属 L3。

### UC-T01 + UC-T02 进入缩小、退出还原（成对）

- **前置**：主机 pane 原尺寸已知（例如 80×24 或桌面全尺寸）。
- **主路径**：subscribe(rows, cols=手机网格) → 主机 pane 变成该尺寸并重推快照 → unsubscribe 前 restore → 主机 pane 回到原尺寸。
- **怎么坏**：只做进入不做退出（[[020]]）；键盘弹出也 resize（[[019]]，见 UC-T03）。
- **层**：L0 已有 resize 三条。L3 目检电脑画面是否被永久挤窄。

### UC-T03 键盘上推不重排

- **前置**：已在会话页，主机 pane 尺寸 = 进入时的手机网格。
- **主路径**：弹出 IME → 视口平移，输入框在键盘上方可见 → 主机 `#{pane_width}x#{pane_height}` 不变 → 不出现整屏闪/扭曲。
- **怎么坏**：锁死不动被键盘遮挡；每发一句就 SIGWINCH。
- **层**：尺寸不变可 L0（已有 no-keyboard-churn）；遮挡与闪烁只能 L3。

### UC-T05 vs UC-T06 两种「历史」（不得混验）

| | UC-T05 主屏 scrollback | UC-T06 alt-screen 对话历史 |
|---|---|---|
| 被测对象 | `alternate_on=0` 且 `history_size>0` 的 pane | Claude Code：`alternate_on=1` `history_size=0` `mouse_any_flag=1` |
| 需求依据 | [[006]] 主路径 | [[006]] 已知边界 + [[047]] |
| 正确手段 | 本地 buffer + `capture-pane -S` 分页 | **再议**。copy-mode / 服务端自持 offset 对 hist=0 读空；鼠标上报是否可行未闭环 |
| 验错即废 | 在裸 bash 上把滚动测绿，宣称 Claude Code 能看历史 | 用 `capture-pane` 冒充 `pipe-pane` 通道 |

L0 `d36` 只覆盖 UC-T05。把 d36 绿当成 UC-T06 通过，属于「验证的不是真正的被测对象」。

### UC-R01 被杀无所谓

- **前置**：已在某会话页，画面有可识别锚点。
- **主路径**：强制停 App → 再开 → 重连 → 首屏快照 = 当前主机画面，导航仍在该会话。
- **怎么坏**：要用户重新扫码；回到列表；空白屏但指标全绿（必须先过存活判据，见 inspection_design）。
- **层**：L3。L0 只能证明「重订阅会再推快照」。

### UC-R07 需要时被唤醒

- **前置**：状态层对该 CLI 能判 blocked/done（依赖 UC-F08，不准则本 UC 假绿）。
- **主路径**：agent 进入 blocked → 通知到达 → 用户点击 → 打开的是**那一个** session ref，不是首页。
- **怎么坏**：生产恒 unknown 所以永不通知；通知有、深链无消费方。
- **层**：决策逻辑可单测；端到端 L3。通知「App 内全局开关」已撤销（R-004），本 UC 不含开关。

### UC-N01 + UC-N02 单一 App 出网

- **前置**：手机不装 Tailscale App、不依赖小火箭先拉起 TS；服务端已在 tailnet 或 App 自行入网。
- **主路径**：设置/QR 填入 auth key → App 成为 TS 节点 → 蜂窝下打开会话、发送、回显。
- **怎么坏**：必须先开外部 TS（[[024]]）；局域网测通冒充蜂窝（[[039]]/[[056]] 的正面验收条件是蜂窝+TS）。
- **层**：L3。单测禁止真连控制面，也禁止把 LAN 延迟当成 tailnet。

## 10. 修订

本文件可以改（它不是需求基条目）。改法：

- 需求基新增条目 → 在 §3 加 UC 或在 §8 声明非用例，并补 §5 一行。
- 某 UC 的施工状态变化（只入库→开工、再议→新裁定）→ 只改总表「施工」列和对应展开节，不删 ID。
- 发现验错对象 → 在该 UC「怎么坏」里记一笔，避免再犯。
