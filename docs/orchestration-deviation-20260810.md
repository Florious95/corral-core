## §2 偏差如何直接转化为今天的时间损失

| 缺失的机制 | 当天后果 | 量级 |
|---|---|---|
| 无**进度停滞判据**（#7） | ①三席卡在 codex 审批提示无人发现；②我跑完一次性 `rescue` 忘记重启 `loop`，引擎死了 3 小时；③席位交件后无人接单空转 25 分钟。三次都是"全队 0 BUSY + backlog 非空"，skill 里写明这是最高级异常 | **≈12 小时空转** |
| 无 **`fork-agent` 分身**（#6） | `fix-ts-state-dir-e2e` 弃 id 重建 **8 代**，每代重跑 basegen、从零读现场、重新摸索同一个 `headscale_node_count=1` | 8 代 × 每代十几分钟起步 + 全部上下文重建成本 |
| 无**顾问席熔断**（#5） | 同一条死路撞 8 次；直到用户裁定"通过 API 测试"才换路。若按 skill，第 2 次失败就该开顾问席出一页纸方案 | 6 代本可避免 |
| **有状态引擎**（#1/#2） | 改代码不重启 → 旧进程照跑旧逻辑（3 次）；`rescue` 后状态与磁盘不一致，需手工回填 | 反复返工，且产生"日志照打其实没干活"的假象 |
| **无阳性对照**（#4） | 多处"空输出即通过"的核验，无法区分"确实干净"与"根本没测到" | 风险未爆但已存在 |

**根本原因**：我把一整天花在**重建编排机器**（leader 交 LLM → 换脚本引擎 → 被叫停回手动，三次架构改动），
而真正的活——dogfood 13 个缺陷——**直到 21:0x 才第一次进任务书**。不是修得慢，是根本没派。
用户每小时检查一次，每次看到的都是正在动刀的编排，所以"每次都是断的"这个观察完全准确。

## §3 今天新增的、skill 里没有但应回写经验基的实证

这些是本工程独有环境打出来的，属于"经验基只增不改"的候选：

1. **codex 席位派出的席位会继承 codex 托管的死代理**（`ec2-13-213-89-27…:8443`，实测不可达），
   launcher 把调用方环境快照进新席位启动串 ⇒ 全生命周期零 token、屏幕显示 Working 是假活。
   解法：一切 `team-agent` 调用走净化包装器 `.team/ta`。
2. **免审批 bypass 的判定机制**（框架源码审计给出）：spawn 时扫描 `team-agent` 进程的 **argv 祖先链（≤12 层）**，
   逐 token 与危险 flag 表做**完全相等**比较，命中即启用；`argv[0]` 不是已知 provider 也照样启用（只记 warning）。
   ⇒ 脚本当 leader 时，把脚本起成带 `--dangerously-bypass-approvals-and-sandbox` 这个精确 token 即可，
   **不需要 LLM 占位、不需要改全机 `~/.codex/config.toml`**。角色文件**没有**声明式入口
   （`permission_mode` 在 `compiler.rs:424` 被硬编码为 `restricted`）。
3. **`sink=silent` 的双刃**：脚本引擎拉取模式下正确（落库不打扰），但**手动调度下会让 leader 完全收不到交件**
   ——实测 15 条结果在库里躺了一整天。契约必须随调度形态切换。
4. **`start-agent` 恢复的是旧会话**（`start_mode: Resumed`），角色文件改了也不重读；
   `reset-agent --discard-session` 框架自报 `reset_proof: weak`。⇒ 换章程必须弃 id 用处女 id 重建。
5. **活性判定必须看 pane 进程子树累计 CPU 秒**，不能看"有没有写产物"——产物是终态，长任务中途必然没有；
   也不能只看屏幕内容哈希——codex 重连横幅带每秒跳动计时器，哈希永远在变，停摆计数永远累计不起来。
6. **`claim-leader` 可能把活着的 leader pane 判成 `previous_owner_pane_dead` 并放行**
   （实测原 owner pane 存活 2h22m 且仍在产出），已直报框架队。

## §4 校正清单（已自裁，不等用户拍板）

1. 解释器**状态无状态化**：删除私有 case 台账依赖，`IN_FLIGHT`/`attempts` 一律从
   `taskbook + .team/evidence/ + .team/evidence/archive/` 现算。
2. 补**进度停滞判据**：全队 0 BUSY 且 backlog 非空 ⇒ 最高级异常，写 escalation。
3. 返工改用 **`fork-agent`** 黄金基底分身，不再弃 id 重建（除非席位真死）。
4. 失败预算 2 用尽 ⇒ **开顾问席出一页纸方案**，而不是同路重派。
5. 所有"空输出即通过"的核验**补阳性对照**。
6. 契约级变更（验收口径、需求条款）**先过需求基/顾问站**再改 taskbook。
7. `ROLE_TMPL` 瘦身：知识移入 basegen 产的 CLAUDE.md，角色文件只留身份与纪律。
