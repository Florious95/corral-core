## 一、直通输入

> 「我现在在键盘里面输入的所有信息、所有内容,**直接发送到 Agent 的 CLI 的输入框里面**。」
>
> 「我在虚拟键盘,也就手机的虚拟键盘**按下删除键,也会直接的发送到 Agent 的 CLI 里面**。」

用户给的两条理由:

> 「1. **删除这个体验是天然的。**
> 2. 有些东西我必须,就比如说那些命令,我必须先按斜杠。假如说我在输入框里面输,我就必须完全的记住那些命令。
> **我完全可以说我一边输,然后按一下上面的 Tab 键,自动补全。**」

### 草稿问题——leader 判断错过一次,用户当场纠正

leader 曾说直通会失去「草稿编辑能力」。**用户否定:**

> 「你按下键,无论是打中文还是打英文,**到达 Agent 的 CLI 的输入框的时候,它本身就是草稿**,
> 你只有点发送它才发送,**不存在草稿编辑能力的消失**。」

⇒ 草稿没有消失,只是**从 App 本地移到了 CLI 输入框**。发送键仍是唯一提交动作。

## 三、会话状态

> 「我希望会话的状态是完全正确的,**去除完成这个状态,就是工作和空闲,并且要绝对准确**。」

判定原理（用户后续以截图实证）:

> 「所有 Provider 它在 Ctrl+B `w` 这一个界面,它都有一定的**动态效果**,在它工作的时候。
> **基于这个原理去确认它是否在工作**,但是**暂时只考虑 Claude Code 完全准确**,后面的话我们再加优化。」
>
> 「就是这个**黑白圆圈,它在动**,就代表我红框表达的那些 Agent 它是在工作。」
>
> 「它这个**不单单是动态效果,它还是有和没的区别**。它工作时候有,它不工作的时候前面没有任何字符。」

配套裁定:

> 「**权限全给**,没有说要按回车的。」
> 「暂时不考虑一个 window 里面有多个盘、多个通道的问题,因为**一行一个 title 和会话,
> 现在我就没看到过不是 1:1 对应的情况**。」

## 四、刷新模型

> 「现在所有界面它都是没有刷新的,所有的会话界面都是不会刷新的。
> 就外部的第一级就是 **Tmux Socket**。我希望**每次到一级的时候,它自动的刷一遍,拉最新的**。
> 此外,**我手指向下滑,它手动刷一遍,并且没有周期性自动刷新**。
> 你记住,**我第一次进入这个菜单,它刷新一次。然后我手动还可以再刷,它没有周期性自动刷新。**
>
> 同理,**我点开一个工作目录,到了第二级,它是会话的列表。第一次到的时候刷新,
> 往下拉、往下滑,手动刷新一次,没有周期性刷新。**」

### 三条不变量（从上面原文直接读出，不是推断）

1. **进入即刷一次**（一级 tmux socket 列表 / 二级会话列表,两级同规则）
2. **下拉手动刷**
3. **零周期性自动刷新**——这条是禁令,不是"频率低一点"

## 已澄清的歧义（leader 问、用户答）

| 歧义 | 结论 |
