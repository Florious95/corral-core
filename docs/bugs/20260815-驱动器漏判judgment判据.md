# 驱动器只跑 mechanical 就关任务，judgment 判据被静默跳过

- 日期：2026-08-15
- 报告方：远程Agent安卓 leader
- 归属：**ledger-orchestration**（`reference/ledger-driver.py` 的 `check_mech()` / `main()`）
- 严重度：**高**——**假绿**。任务被标 succeeded、日志显示「判据通过」，
  而 `required` 里声明的判据**有一条从来没被求过值**。

## 现象

本工程账本 `t.verify` 的 acceptance：

```json
"mechanical": [{"acceptance_id": "A-ctl-report", ...}],
"judgment":   [{"acceptance_id": "A-ctl-verdict", "judge_role": "r.advisor",
                "verdict_values": ["supports","refutes","inconclusive"], "veto": true, ...}],
"required":   ["A-ctl-report", "A-ctl-verdict"]
```

驱动器日志：

```
[03:19:07]   判据 A-ctl-report: exit=0 期望=0 通过
[03:19:07] t.verify: 判据通过 → succeeded（revision 4）
[03:19:07] 前沿为空。
```

**`A-ctl-verdict` 一个字都没提。** 它在 `required` 里，从未被求值，任务照样关闭。

## 根因

`check_mech()` 只遍历 `acceptance.mechanical`：

```python
for m in l["tasks"][tid]["acceptance"].get("mechanical", []):
```

`acceptance.judgment` **没有任何代码路径**；`required` 数组**从未被读取**。
⇒ 驱动器把 `required` 当成不存在，只要 mechanical 全过就置 succeeded。

## 更麻烦的第二层：引擎知道，但退出码不说

置完 succeeded 之后 `ledger-eval` 的输出：

```
task_states: succeeded: 5
workflow_state: state_error:terminalproofincomplete     ← 引擎明确报错
== 现在可以动的任务（0）==
```

**而退出码是 0。**

skill 的纪律写着「退出码是唯一的机器判据，不要 grep 输出文本」。
在这个场景下这条纪律**会把人带沟里**：一个自动化驱动器只看退出码，
拿到的是 exit 0 + 前沿为空，**完美的「跑完了」信号**，而引擎其实在说终局证明不完整。

已知条目里写过「别拿 exit 0 当跑完了，要看已完成是否覆盖必需任务」——
但本例更严：**已完成确实覆盖了全部 5 个任务，仍然是 state_error。**
覆盖率检查也发现不了它。

## 建议（两条独立，都需要）

1. **驱动器**：`check_mech` 改成按 `required` 求值。
   遇到 `judgment` 类判据**不要跳过也不要自己判**——
   停下来交给 leader（或按 `judge_role` 派单），日志显式打印
   「required 里有 N 条 judgment 判据未求值，停」。
   **静默跳过是这里唯一不可接受的行为。**
2. **`ledger-eval`**：`workflow_state` 是 `state_error:*` 时**不应返回 0**。
   否则「退出码是唯一机器判据」这条纪律在有 judgment 判据的账本上就是错的，
   而这恰恰是最需要机器判据的场景。
   （若出于兼容不便改 0→非 0，至少给一个 `--strict` 开关。）

## 本工程的处置

- 已把 `A-ctl-verdict` 单独派给账本指定的 `judge_role`（advisor，不在 `judge_must_not_be` 内、
  且未产出被验收的产物，判权成立），要求给出 supports/refutes/inconclusive 与依据。
- **在拿到裁定前，本工程不认为这张账本已经关闭**，尽管它 5/5 succeeded 且 exit 0。
