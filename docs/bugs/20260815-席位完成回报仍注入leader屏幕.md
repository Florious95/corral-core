## 一、现象

驱动器（`tools/ledger-driver.py`，owner pane 子进程）派单 → 席位干活 → 席位回报。
派单正文里**逐字要求**席位这样回报：

```
report_result 必须带结构化参数 presentation={"sink":"casefile","class":"stage_result"}
```

实际结果：席位 `dev-keybar` 的完成回报**出现在 leader 屏幕上**，形如

```
Team Agent message from dev-keybar for msg_69927e556ed8:
Task msg_69927e556ed8 reported completed from dev-keybar: 刷新模型实现完成……
Verification warnings: warning advisory tests: result_success_without_executed_tests
Changes: changed app/.../WorkspaceViewModel.kt……
Result id: res_e8f30b733c20
Team Agent stored this result. The coordinator/collect path will update team_state.md
```

这条对 leader 没有决策价值：驱动器**不采信席位自报**，完成与否由驱动器自己跑机械判据拿退出码决定。
（本例中席位自报"完成"，而驱动器实跑 `A-ri-test` 得到 exit=1。）

## 二、日志支撑

`team-agent inbox dev-keybar --json` 四条，方向与投递态：

| 方向 | status |
|---|---|
| leader → dev-keybar | `delivered` |
| dev-keybar → leader | `injected_awaiting_receipt` |
| leader → dev-keybar | `delivered` |
| dev-keybar → leader | `injected_awaiting_receipt` |

- 全量 JSON 中 `stored_not_presented` 出现 **0 次**，`injected_awaiting_receipt` 出现 **2 次**。
- 同一份 JSON 里 `casefile` 出现 4 次、`stage_result` 出现 1 次，**但这些字面量来自 leader 派单正文本身**
  （正文就在教席位怎么写），**不能**作为"席位声明了 casefile"的证据。这一点我一开始读错了，此处更正。

对照实验（证明 `--presentation-sink` 这条通路本身是好的）：

```
team-agent send advisor '<单行探针>' --presentation-sink casefile --message-class progress
→ ok: True status: stored_only verification: durable_without_live_inject channel: casefile
（附带 warning: message-class=progress is deprecated; use mailbox=true instead）
```

即：**`send` 侧的 casefile 生效**，落 `stored_only`。出问题的是 `report_result` 侧。
