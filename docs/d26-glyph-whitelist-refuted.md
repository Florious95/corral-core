【重要：先别让任何人重编生产 daemon —— D-26 的 Layer ① 会让状态误检变严重】

用户刚给出截图实证，推翻了 D-26 Layer ① 的做法：

  完成态：`※/✳ Brewed for 42m 3s`
  工作态：`✳ Churned for 3m 37s · 1 shell still running`

**两者前导是同一类星号字形，区别只在动词**（Brewed=完成 / Churned=进行中）。

而 D-26 Layer ① 恰恰把 `✳` 加进了 spinnerFrames「工作中」白名单。
**一旦重编 daemon，所有跑完的会话都会因为 `✳ Brewed for` 被判成「工作中」，误检更严重。**

用户当前实际报告的就是这个方向的误检：「它已经停止工作了，结果还显示它在工作中」
（注意：生产 daemon 仍是 13:40 旧二进制，D-26 改动尚未生效，
所以当前误检是旧规则造成的；但 Layer ① 上线后会让它更糟。）

**这是第三次证明按字形匹配走不通**：工作与完成用同一个符号，字形层面不可能分辨。
真正能分辨的只有「屏幕在不在变」——即已写好、已测绿、但**未接线**的 Layer ② 活性判据。

结论：
1. 生产 daemon **暂不重编**
2. D-26 需要修正：`✳` 不能单独作为 working 判据（至少要配合动词/上下文），
   且 Layer ② 必须接线才算真修
